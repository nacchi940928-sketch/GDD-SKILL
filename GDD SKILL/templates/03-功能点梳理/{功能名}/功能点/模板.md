## 案例（参考：排行榜系统 — 战力排行榜）

### 涉及模块

| 模块 | 表现 |
|------|------|
| 主界面-排行榜入口 | 按钮+红点 |
| 排行榜主界面 | 分页（战力榜/等级榜/公会榜）+ 排行列表 |
| 玩家详情弹窗 | 点击排行条目查看 |

### 功能点

- [ ] 战力榜按玩家战力降序排列，同战力按达成时间升序（先到者排前）
- [ ] 显示 Top100，自己的排名在不在Top100都在底部固定栏展示
- [ ] 每小时整点刷新榜单（非实时，降低服务器压力）
- [ ] 前三名显示特殊标识（冠/亚/季军icon）
- [ ] 点击任意条目弹出该玩家详情（头像/等级/战力/阵容）
- [ ] 自己的条目高亮底色

### 数据来源

| 读写 | 数据 | 字段 | 用途 |
|------|------|------|------|
| 读 | 玩家战力排行 | `rank_list[].player_id, power, rank, update_time` | 榜单渲染 |
| 读 | 玩家自己的排名 | `my_rank` | 底部固定栏 |
| 读 | 玩家详情 | `player_detail` | 点击查看弹窗 |

### 怎么实现

**通用规则**
- 榜单每小时整点由服务端定时任务计算（Redis Sorted Set 或 定时批处理）
- 客户端仅在打开排行榜时拉取快照，不实时推送
- 前三名特殊标识 + 自己高亮

**服务端**
- 定时任务：每小时 `ZRANK power_rank` → 写入Top100缓存
- 玩家详情接口：根据 player_id 返回头像/等级/战力/阵容
- 榜单快照缓存到 Redis，TTL=1h

**客户端**
- 打开排行榜 → 请求拉取快照 + 自己的排名
- 渲染列表（带虚拟滚动，100条）
- 点击条目 → 请求玩家详情 → 弹窗展示
- 底部固定栏显示「你的排名：第xx名」

### 程序分工

| 事项 | 客户端 | 服务端 | 备注 |
|------|--------|--------|------|
| 定时计算榜单 | — | ✓ 每小时整点 | Redis Sorted Set |
| 榜单快照下发 | ✓ 请求拉取 | ✓ 返回Top100+my_rank | — |
| 列表渲染 | ✓ 虚拟滚动 | — | — |
| 玩家详情 | ✓ 弹窗 | ✓ 接口 | — |
| 前三名标识 | ✓ 渲染逻辑 | — | 冠/亚/季军icon |
