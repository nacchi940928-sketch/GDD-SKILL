# 策划案转换规范

> 当拿到一份策划案（.docx 或 .md），按此规范转化为三阶段输出。

---

## 转换流程

```
策划案.docx
    │
    ├──→ 01-原始策划案/     ← 提取设计意图和规则叙述
    │
    ├──→ 02-需求拆解/       ← 按8个维度拆分、编号、标注来源
    │
    └──→ 03-功能点梳理/     ← 完整保留原始细节，每模块含所有表格
```

---

## 核心铁律

### 1. 03-功能点梳理 = 程序唯一主文档

- **绝对自包含**：程序无需对照任何其他文档即可开发
- **保留全部细节**：原始文档的每个段落、每个表格都要保留
- **禁止概括**：不要"总结为"、"归纳为"，要"原文照搬"
- **表格必须完整**：涉及模块表、数据来源表、程序分工表——一个不能少

### 2. 01-原始策划案 = 策划视角的设计叙述

- 从策划案中提取设计意图、玩法说明、规则叙述
- 用自然语言写，不需要表格化
- 覆盖：概述→流程→规则→UI→美术→配置

### 3. 02-需求拆解 = 维度文件夹体系

- 每个维度一个文件夹，按功能点拆文件
- 每条规则有唯一编号（R-xxx, EX-xxx 等）
- 每条标注来源（引用 01 的章节）

---

## Docx 提取规范

```
必须：使用 XML 方式提取，保持段落和表格的文档顺序
禁止：使用 python-docx 的 paragraphs→tables 分离方式（会丢失表格归属）

正确做法：
1. 解析 word/document.xml
2. 按文档 body 元素顺序遍历
3. w:p → 段落，w:tbl → 表格
4. 保持原始顺序输出
```

---

## 03 模块拆分规范

原始文档的章节结构：
```
[] 0. 阅读说明
  [] 0.1 子章节
  [] 0.2 子章节
  === 表格 === (表格1-7)
[] 1. 功能模块A
  [] 1.1 子章节
  === 表格 === (表格8-10)
[] 2. 功能模块B
  ...
```

拆分规则：
- **顶级章节**（[] N. 名称，N=0-13）→ 一个文件
- **子章节**（[] N.M 名称）→ 保留在父文件中
- **表格**（=== 表格 ===）→ 保留在它出现的位置
- **附录**（附录 A/B/C）→ 拆分到 验收场景.md / 待确认事项.md

## 检查清单

转换完成后逐项检查：

- [ ] 03 每个模块文件 > 500 字符（太短说明丢了表格）
- [ ] 03 每个模块含完整表格（涉及模块/数据来源/程序分工）
- [ ] 02 每条规则有唯一编号
- [ ] 01 覆盖概述/流程/规则/UI/美术/配置
- [ ] 字段映射 P-xx 全部登记
- [ ] 验收场景可直接测试
