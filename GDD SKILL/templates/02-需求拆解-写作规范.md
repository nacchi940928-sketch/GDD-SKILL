# 02-需求拆解 — 写作规范

> **读者**：策划、运营、产品、管理层。  
> **不是**：程序实现规格（那是 `03-功能点梳理.md`）。

---

## 02 vs 03

| | 02 需求拆解.md | 03 功能点梳理.md |
|--|----------------|------------------|
| 语言 | **自然语言**，像策划案扩写 | 技术规格，可交给程序/AI |
| 规则 | 何时、对谁、发生什么、为什么 | R-xx **伪代码**、检测位置、P-xx 读写 |
| 流程 | 玩家/界面视角的阶段描述 | Phase 枚举、状态机、协议时序 |
| 数据 | 需要哪些表/配置（**表名 + 代表字段**） | 附录 A 全字段、配置表、协议、审计 |
| 编号 | R-/EX-/T- 作**对照锚点**；配置项写 **P-xx + `表.字段`** | P-xx 全文、附录 A |
| 禁止 | 伪代码、协议表、Const 审计、数据契约 | 「见 02」「见策划案」 |

---

## 规则条目格式（02）

```markdown
## R-{缩写}-001 {规则标题}

**规则说明**：（2~5 句自然语言：触发情境 → 系统行为 → 玩家可见结果 → 例外）

【待确认】…（如有）

**来源**：01 §x.x
```

**不要写**：`检测位置`、`检测方式`、代码块、`| 读/写 | P-xx |` 表。

---

## 状态机（02）

用**玩家能感知的阶段名**：

```markdown
### 2.1 单局流程

选角 → 匹配中 → 对局内（每轮：抢道具 → 放道具 → 跑酷 → 小结算）→ 总结算 →（可选）加赛
```

**不要写**：`LOBBY`、`P-17`、`MatchStartReq`（放 03）。

---

## 数据章节（02）

```markdown
## 6. 数据概要

本玩法依赖以下配置（名称与 01 一致，**须带程序字段名**）：
- **AB2_XxxConst**：单局轮数 `total_rounds`、各阶段倒计时…（对应 P-01、P-03…）
- **AB2_XxxItem**：道具行为与权重…
- **AB2_XxxScore**：成就分…

程序可读 P-xx 与完整字段表见 **03-功能点梳理.md 附录 A**。
```

## 验收（02）

保留 **T-/B-/E-** 编号，步骤与预期用**用户操作语言**（「点击匹配」「全员到达终点」），字段编号可省略或括号注明。
