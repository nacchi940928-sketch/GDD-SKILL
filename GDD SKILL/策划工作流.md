# 策划工作流

> **策划提供原始策划案** → 程序/AI 拆解为 02/03 → **04 补充清单 ↔ 回填验收** 迭代至完整 → 入库交付程序

---

## 〇、三层基底（PromptMerge）

| 层级 | 位置 | 说明 |
|------|------|------|
| **L0 横切** | `skills/tech|ux/*` | resolution_standard、interaction_feedback 等全项目共用 |
| **L1 系统** | `skills/design/*` | tournament_bracket 等跨功能复用，`config_schema` 定义可调参数 |
| **L2 实例** | `案例/{功能}/02~04` | 只写相对 L1 的 delta；workflow 填项目配置 |

**编译**：`python tools/compile.py 案例/{功能} --workflow workflows/{项目}.workflow.json` → `outputs/{功能}/程序包|测试包|策划包.md`

**提示词**：`prompts/P1~P6/`（复制粘贴即用）。**规范 Skill**：`skills/gdd/p1-original-gdd` · `p2-decompose` · `p3-feature-spec` · `p4-planner-fill` · `p5-compile-verify` · `p6-pipeline`。

详见 [docs/PromptMerge规划.md](docs/PromptMerge规划.md)。

## 一、工作流总览

```
01-原始策划案 ──→ 02-需求拆解 ──→ 03-功能点梳理 ──→ 04-待策划补充 ⇄ 回填验收
  (策划提供)      (程序/AI)      (程序/AI)        (清单→策划填→验收，循环至完整)
                                                      ↓
                                               05-入库交付 → 程序
```

| 阶段 | 产出 | 执行者 |
|------|------|--------|
| 01-原始策划案 | 一份完整设计文档 | **策划提供** |
| 02-需求拆解 | 8 个维度文件夹 | 程序/AI |
| 03-功能点梳理 | 程序可执行模块规格 | 程序/AI |
| 04-待策划补充 | 补充清单 → 策划回填 → 验收 | 程序/AI 生成清单，**策划回填**，程序验收 |
| 05-入库交付 | git 提交，交付程序 | 程序 |

**迭代闭环**：P4-1 扫描 01~03 生成 04 清单 → 策划逐文件填写 → P4-2 验收；未通过则更新文档并再次循环，直至 02/03 无阻塞缺失项，再进入 P5 编译与 05 入库。

**输入**: 策划提供的原始策划案（如 `参考/` 中的 .docx 或策划自写的 01）。

## 二、阶段详解

### 阶段 1: 原始策划案

**定位**: 策划提供的一份完整设计文档。所有下游拆解从这里出发。

**模板**: `templates/01-原始策划案/{功能名}/原始策划案.md`

**内容覆盖**: 概述 → 功能流程 → 规则 → UI交互 → 美术需求 → 配置结构

**格式**: 自然语言叙述，不强制表格化。讲清楚：这是什么、怎么玩、规则是什么、界面长什么样。

---

### 阶段 2: 需求拆解

**定位**: 将一份原始策划案拆解为 8 个维度的文件夹体系。每个维度一个文件夹，文件夹内按功能点拆分为独立文件。

**模板**: `templates/02-需求拆解/{功能名}/`

**8 个维度文件夹**:

| 文件夹 | 拆解内容 | 每条编号 | 主要读者 |
|--------|----------|----------|----------|
| `规则/` | 所有游戏规则，含检测方式+伪代码+数据依赖 | R-xxx | 后端 |
| `边界条件/` | 异常流程、前置条件、限制条件，含检测层+处理逻辑 | EX-/PRE-/LIM-xxx | 前后端+测试 |
| `红点/` | 触发条件、消除条件、检测方式、层级聚合 | RD-xxx | 前端 |
| `数据源/` | 配置表、协议、运行时数据、枚举、字段映射索引 | P-xx | 前后端 |
| `UI交互/` | 界面跳转图、各界面布局交互、弹窗规格 | — | 前端 |
| `状态机/` | 所有状态流转，含服务端/客户端伪代码 | — | 后端 |
| `校验规则/` | 数据校验、失败处理、错误码、防篡改设计 | V-xxx | 后端 |
| `验收标准/` | 正常/边界/异常验收清单，每条含前置条件+验证点 | T-/B-/E-xxx | 测试 |

**核心原则**:
- 每条规则展开到可实现的级别：检测位置、检测方式、数据依赖、伪代码
- 每条标注来源（引用原始策划案章节）
- 每个文件可独立评审

---

### 阶段 3: 功能点梳理

**定位**: 程序/AI 管线开发的**唯一主读文档**。自包含，无需对照原始策划案即可开发与验收。

**模板**: `templates/03-功能点梳理/{功能名}/`

**文件结构**:

```
03-功能点梳理/{功能名}/
├── 0-阅读说明.md        ← 文档约定、功能点导航、名词定义、全局矩阵、日程表、跳转图
├── 功能点/               ← 每个功能模块一个文件
│   ├── 1-{模块A}.md
│   └── 2-{模块B}.md
├── 字段映射.md           ← P-xx 统一定义，禁止自创未确认字段名
├── 验收场景.md           ← 可直接测试
└── 待确认事项.md          ← 分三类：待程序确认 / 待策划确认 / 待美术确认
```

**每个功能点的标准块**:

```
涉及模块 → 功能点 → 数据来源 → 怎么实现（通用/服务端/客户端）→ 程序分工
```

**核心原则**:
1. **自包含**: 无需对照原始策划案即可开发验收
2. **字段引用**: P-xx 编号，字段映射统一登记
3. **规则写全**: 禁止「见原始文档」式引用
4. **验收自带**: 每条验收项自带关键规则，不依赖跳转

---

### 阶段 4: 待策划补充

**定位**: 转化过程中发现的不确定内容，整理为独立文件夹体系。策划逐文件填写后回传。

**模板**: `templates/04-待策划补充/{功能名}/`

**8 个补充文件**:

| 文件 | 内容 | 填写者 |
|------|------|--------|
| `01-字段命名.md` | P-xx 字段的程序命名 | 程序 |
| `02-配置数值.md` | 默认值→最终确认值 | 策划 |
| `03-UI文案.md` | 提示/按钮/空态文案 | 策划 |
| `04-GM需求.md` | GM操作场景与权限 | 策划+程序 |
| `05-打点需求.md` | 打点事件定义 | 策划 |
| `06-美术资源.md` | Icon/背景/动画资源确认 | 策划+美术 |
| `07-本地化.md` | 多语言文本 | 策划 |
| `08-新手引导.md` | 引导流程定义 | 策划 |

**使用方式**:
1. 程序完成 01-03 后，在 04 中标记所有不确定项
2. 策划打开 `README.md` 看进度总览
3. 逐文件填写「策划回复」区
4. 全部完成 → 通知程序 → 进入入库交付

---

### 阶段 5: 入库交付

确认目录完整后提交：

```
{功能名}/
├── 01-原始策划案/      ← 策划编写
├── 02-需求拆解/        ← 8 个维度文件夹
├── 03-功能点梳理/      ← 程序可执行规格
└── 04-待策划补充/      ← 策划回填完成
```

## 三、功能层级分类

| 层级 | 定义 | 示例 |
|------|------|------|
| **基础功能层** | 游戏运行最基本框架 | 登录、角色创建、网络通信 |
| **边缘系统层** | 支撑但不直接产生体验 | 背包、聊天、好友、邮件 |
| **核心玩法层** | 核心循环和差异化竞争力 | 战斗、养成、经济 |
| **活动玩法层** | 限时/运营活动 | 限时副本、节日活动、通行证 |

## 四、检查清单

### 01-原始策划案
- [ ] 概述：玩法说明 + 设计目的 + 文档范围
- [ ] 功能流程：界面流程 + 业务子流程 + 状态流转
- [ ] 规则：基本 + 子系统 + 特殊规则全覆盖
- [ ] UI：每界面布局→交互→状态→空态
- [ ] 美术：Icon/资源/动画编号管理
- [ ] 配置：Const + 各配置表完整

### 02-需求拆解
- [ ] 规则/：每条含检测方式+伪代码+数据依赖
- [ ] 边界条件/：异常/前置/限制，含检测层+处理逻辑
- [ ] 红点/：触发+消除+检测方式+层级聚合
- [ ] 数据源/：配置表+协议+运行时+枚举+P-xx索引
- [ ] UI交互/：跳转图+每界面布局+弹窗
- [ ] 状态机/：含服务端/客户端伪代码
- [ ] 校验规则/：每条含错误码+防篡改设计
- [ ] 验收标准/：正常+边界+异常，含前置条件+验证点

### 03-功能点梳理
- [ ] 每个功能点含标准块：模块→功能点→数据→实现→分工
- [ ] 字段映射 P-xx 全部登记
- [ ] 验收场景可直接测试
- [ ] 待确认事项按三类标注（程序/策划/美术）

### 04-待策划补充
- [ ] 01-字段命名：P-xx 全部程序确认
- [ ] 02-配置数值：默认值全部策划确认
- [ ] 03-UI文案：提示/按钮/空态文案确认
- [ ] 04-GM需求：GM操作场景与权限明确
- [ ] 05-打点需求：打点事件定义完成
- [ ] 06-美术资源：资源清单确认
- [ ] 07-本地化：中文原文提供
- [ ] 08-新手引导：引导流程定义
