# 实现数据契约 — 技术规范（L0 横切）

> **本文件是 Skill（知识与规范）**，不是提示词。  
> P2 收尾、P3 功能点、P5 编译前配合对应 Prompt。  
> 配置表格式见 [config_table/tech.md](../config_table/tech.md)；Const/表分轨见 [configurable_rules/tech.md](../configurable_rules/tech.md)。

---

## 目标

GDD 拆解的交付物不仅是「文档结构齐」，而是 **程序可加载的数据契约**：

- 每条 R-xx 伪代码中的**每个读写的量**，必须能追到 **P-xx（Const）**、**配置表.列** 或 **枚举**
- 缺数值时：**登记 Q-D** + `04/02-配置数值.md` 对应 §，并在审计中标 **阻塞 / 非阻塞**
- 禁止：规则写「摩擦衰减」「应用重力」但字段索引无 P-xx、表无列、数值只写在 `trigger_desc` 散文里

---

## 三层就绪度

| 层级 | 含义 | P2 门禁 |
|------|------|---------|
| **A 结构层** | 有 02 八维度、P-xx 编号、配置表主键 | 最低要求 |
| **B 契约层** | R-xx 变量 ↔ P-xx/表列/枚举 一一对应；01 可推断的已填入 | **P2 标 🟡 可评审** |
| **C 可开工层** | 某模块涉及字段均有值，或 Q-D 已填 | **P6 模块门禁** |

**P2 不得标「可开发」**：若核心路径 R-xx 存在 **契约层阻塞**（变量无落点，或整列待填且无 Q-D）。

---

## 变量追溯铁律

对每条 R-xx，导出 **读/写变量清单**，每个变量必须满足其一：

```text
变量 v
  → P-xx（Const）           有默认值，或 04/Q-D 待填且标阻塞模块
  → 表.{列}                 列存在；01/docx 可推断的已填；不可推断 待填 + Q-D
  → 枚举.{Name}             在 枚举定义.md 有 int 映射
  → 禁止                    不得出现在 R-xx 伪代码中
```

| 01 原文形态 | 必须落地为 |
|-------------|------------|
| 全局标量（重力、基础摩擦、冷却…） | Const P-xx + `04/02` §Const |
| 逐实体差异（冰面 50% 摩擦…） | 配置表列（如 `surface_friction_mult`） |
| 三态及以上（悬浮/掉落/跟随…） | **enum**，不得仅用 bool 丢信息 |
| 比例、速度、周期在 trigger 文案 | **独立数值列**；`trigger_desc` 仅保留策划可读摘要 |

## P2 Agent 职责

### 1. 与 configurable_rules 分工

| Skill | 侧重 |
|-------|------|
| `configurable_rules` | Const + 表驱动规则的 **分轨**（Q-D / Q-R）、域内审计结构 |
| `implementation_data` | **任意 R-xx** 的变量追溯、推断义务、就绪矩阵、P2/P3 门禁 |

二者同时适用；不重复造 Q-D 体系。

### 2. 01 推断义务（config_table 阶段 2 强化）

- 原文 **明确 bool/枚举/比例** → Agent **必须填入**，不得整表 `待填`
- 原文 **语义明确无数值**（如「存在掉落速度」）→ 新建 P-xx + Q-D，**不得**只在规则里写「应用重力」
- 默认值（如摩擦倍率 1.0）可填，**业务平衡数值**（如具体 g、摩擦系数）标 `待填` + Q-D

### 3. 必产出：数据契约审计

路径：`{feature_root}/03-功能点梳理.md` **附录 D**（`数据契约审计` / 专项审计）；02 仅保留策划语言规则说明。

| 章节 | 内容 |
|------|------|
| 总览 | 模块 × 契约层状态（✅ / 🟡 / ⬜阻塞） |
| 变量追溯表 | R-xx → 变量 → P-xx/表列/枚举 → 状态 → Q-D |
| 阻塞开发 | 清单 + 看板 ID |
| 域审计索引 | 链到 `02/规则/{域}全量审计.md`（按需） |

复杂域（计分、物理、匹配…）另建 **`{域}全量审计.md`**，结构同 configurable_rules，由本 Skill 规定 **必须存在变量追溯节**。

### 4. 必产出：模块就绪矩阵（P2 末或 P5 编译输入）

| 模块 | 依赖 R-xx | 阻塞项 | 可并行 |
|------|-----------|--------|--------|
| … | … | Q-Dxx / 缺 P-xx | 是/否 |

写入 `数据契约审计.md` 末章，或 `03/0-阅读说明.md` §就绪矩阵。

## P1 gap 清单：结构 vs 契约

gap 清单须 **拆分**，禁止「表骨架 ✅ = 域已解」：

| 级别 | 含义 | 示例 |
|------|------|------|
| G-xxa 结构已提取 | 表存在、主键行齐 | 47 行道具 |
| G-xxb 契约可开发 | R-xx 变量均有落点 | gravity_mode 列 + P-59 已登记 |

**可进 P2**：G-xxa 满足即可。  
**可进 P6（某模块）**：该模块 G-xxb 无阻塞项。

## P3 反向校验

功能点「数据来源」表必须与 R-xx 读表 **一致**：

- 功能点写「Const 驱动」→ 数据来源须列齐全部 P-xx
- 缺 P-xx → 功能点标 🟡，回写 P2 补字段映射

见 [gdd/p3-feature-spec/SKILL.md](../../gdd/p3-feature-spec/SKILL.md) 检查清单。
