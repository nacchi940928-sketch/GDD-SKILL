# 可配置规则 — 技术规范（L0 横切）

> **本文件是 Skill（知识与规范）**，不是提示词。  
> P2 规则/数据源、P4 待补充执行时配合对应 Prompt。  
> 配置表结构见 [config_table/tech.md](../config_table/tech.md)。

---

## 适用范围

凡满足以下条件的系统，**同一套拆解流程**适用（不限于「计分」）：

- 01 描述**可计算结果**（积分、奖励、排名、权重、冷却等）
- 程序实现需 **Const 标量** 和/或 **配置表行**
- R-xx 伪代码读 P-xx，但 01 **未给全数值或边界有歧义**

典型域：单局结算、段位/奖杯、匹配 MMR、轮次刷新权重、掉落概率等。

---

## 三层分工

```text
规则层   02/规则/           R-xx 伪代码 + 读/写 P-xx 表
配置层   02/数据源/         Const（P-xx）+ 配置表（见 config_table）
待办层   04/ + 看板         数值 Q-Dxx · 规则边界 Q-Rxx（分轨）
```

| 缺口类型 | 看板 ID | 填写位置 | 示例 |
|----------|---------|----------|------|
| **数值** | Q-Dxx | `04/02-配置数值.md` 各 § | 获胜分、基础分、表内 score |
| **规则边界** | Q-Rxx | `04/09-规则边界确认.md`（按需） | 触发次数、归因、判定条件 |
| **UI/文案** | UI-xx | `04/03-UI文案.md` | 结算提示 |

**禁止**：用「P-xx 待确认明细」笼统描述；须写明「行为/结构已定 / 数值待 Q-D / 边界待 Q-R」。

## P2 Agent 职责

### 1. 规则（R-xx）

- 伪代码引用 **P-xx 或配置表**，禁止魔法数（除非 01 明确且已登记 P-xx）
- 判定条件须**可程序执行**（如「全员到达终点」→ 明确字段条件，非「全员存活」散文）
- 边界歧义时：在 R-xx 写**默认实现**，并登记 Q-Rxx

### 2. 配置（P-xx + 表）

- **标量默认值** → Const，在 `字段映射索引.md` 登记 P-xx
- **多行行为/阶梯** → 配置表（一行一主键，遵循 config_table）
- 01 只写「到达得分」无数值 → 新建 P-xx + `04/02` §待填，**不得省略**

### 3. 专项审计（L2 按需）

复杂域可在 `02/规则/` 增 **`{域}全量审计.md`**（如 `{功能}计分全量审计`）：

- 已具备 / 待填配置 / 待确认规则 三列表
- 链到看板 ID 与 04 填表路径  
Skill **不规定**审计文件名中的业务域名，只规定结构与分轨。

## P4 待办结构

| 文件 | 何时需要 |
|------|----------|
| `02-配置数值.md` | 几乎总是；含 §Const、按需 §{域}数值（如 §基础计分、§成就分） |
| `09-规则边界确认.md` | 01/02 存在 **Q-Rxx** 时由 P4-1 **按需生成**（非固定第 9 个必填文件） |
| `补充与修改看板.md` | 建议设 **§{域}专项** 分配置/规则两轨 |

`05-打点需求.md` 等固定编号**不变**；`09` 专用于规则边界，避免与打点冲突。

## 反模式

| 反模式 | 正确 |
|--------|------|
| 规则写「+生存分」但无 P-xx | Const 登记 + 04 待填 |
| 行为表只有条件、score 列写【待确认】混在规则待办 | score → Q-D；条件实现 → R-xx + Q-R |
| 判定条件用模糊自然语言 | 写可执行条件或 Q-R 默认+待确认 |
| 把某玩法特例（如 SD、Too easy）写进 Skill | 留在 L2 规则与 09 填表 |

## Agent 自检（P2 / P4）

- [ ] 每条 R-xx 读写的数值是否都有 P-xx 或配置表列？
- [ ] Const 与配置表是否分轨，缺值是否标 `待填`？
- [ ] 是否存在 Q-D（数值）与 Q-R（边界）分轨，而非混在一个「待确认」？
- [ ] 03 功能点「数据来源」是否列 P-xx，程序分工是否区分 Q-D / Q-R？
- [ ] 配置表是否遵循 config_table（一行一主键）？
