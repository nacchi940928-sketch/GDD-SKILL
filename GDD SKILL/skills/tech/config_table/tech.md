# 配置表 — 技术规范（L0 横切）

> **本文件是 Skill（知识与规范）**，不是提示词。  
> P2 数据源执行时配合 `prompts/P2/P2-DS-数据源.md`；改表影响检索见 `_backlog/config_table_impact.md`（待晋升）。

---

## 目标

GDD 中的配置表必须是**程序可直接阅读、映射、加载**的结构，而不是策划 docx / Excel 的原始排版。

**一张配置表 = 一个逻辑表 = 一份主数据文件**：按主键分行（如 `id`、`behavior_id`），每行包含该实体的全部字段列。

---

## 三阶段协作流程

```text
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│ 1. 策划提供  │ ──► │ 2. Agent 补充 │ ──► │ 3. 程序完善  │
│ 基本结构     │     │ (P2-DS 等)    │     │ (开发期)     │
└─────────────┘     └──────────────┘     └─────────────┘
```

### 阶段 1 — 策划提供（01 / docx / Excel）

策划负责给出**可被程序理解的骨架**，通常包括：

| 交付物 | 内容 |
|--------|------|
| 表名 | 如 `AB2_ChickenHorseItem` |
| 主键 | 如道具 `id` |
| 字段清单 | 列名、类型意图（枚举 / bool / 数值 / 文案） |
| 枚举取值 | 如道具类型 1~6、触发方式 0~3 |
| 原始行数据 | 能提供的逐行数值；缺项允许留白 |

**允许**策划 docx 内嵌多 sheet（如「通用属性列说明」+「道具清单」），但那是**输入**，不是 GDD 最终形态。

### 阶段 2 — Agent 补充（P2-DS 数据源）

Agent 读取 01 与策划附件后，在 `{feature_root}/02-需求拆解/{功能名}/数据源/配置表/` 产出**程序态单表**：

1. **合并**：多 sheet / 多段说明 → 一张「字段说明 + 数据行」表
2. **类型化**：枚举进 `枚举/枚举定义.md`；开关用 `bool`；周期/权重用 `float` / `map`
3. **命名**：列名用程序字段（`snake_case`），与 P-xx 在 `字段映射索引.md` 登记
4. **推断**：仅从原文可确定的内容填入（如原文写明「受重力」→ `gravity_mode=Fall`；「摩擦力为基础 ×50%」→ `surface_friction_mult=0.5`）
5. **标注缺口**：无法从 01 确定的单元格写 **`待填`** 或 **`【待确认】`**，**禁止编造业务数值**；须登记 Q-D 并写入 [implementation_data](../implementation_data/tech.md) 数据契约审计
6. **登记待办**：缺口汇总到 `04-待策划补充/` 与 `补充与修改看板.md`（如 Q-D02b）

**提取备份**：docx 内嵌 xlsx / sheet 导出 md → `产出/{功能名}/01-…/源表提取/`；**程序态表** → `02-…/数据源/配置表/`（本 Skill）。

### 阶段 3 — 程序完善（开发期）

程序在实现与联调时：

| 动作 | 说明 |
|------|------|
| 补全 `待填` | 重力、权重、prefab、碰撞层等运行时字段 |
| 增删技术列 | 如 `prefab`、`collider_lethal_mask`（01 未写但加载器需要） |
| 导出真表 | xlsx / json / 现网配置仓库（项目自定） |
| 维护关联 | 更新 `config/表关联关系.json`（供改表影响检索） |
| 回流 GDD | 定稿数值写回 `02/…/配置表/*.md`，或注明「以 xx 导出为准」 |

**原则**：GDD 配置表是**规格真源**的 Markdown 视图；现网表与 GDD 不一致时，以双方约定为准并更新文档。

## 格式铁律

### 必须

| 规则 | 说明 |
|------|------|
| **一行一实体** | 主键唯一；多行实体 = 多行数据，不是「结构说明 + 摘要清单」两段 |
| **列即字段** | 每列有明确类型；枚举引用 `枚举定义.md` 中的命名枚举 |
| **bool 开关** | 重力、附着、可连接等用 `true`/`false`，不用散文「悬浮/掉落」占数据列 |
| **enum 整型** | 道具类型、触发方式等用 int 枚举 + 枚举表定义 |
| **索引一致** | 表字段必须在 `字段映射索引.md` 有对应 P-xx |
| **来源标注** | 文件头或表尾：`来源：01 §x.x` |

### 禁止

| 反模式 | 正确做法 |
|--------|----------|
| 照搬 docx 两个 sheet 拆成「§1 列说明 + §2 名称摘要」 | 合并为带全部列的数据表 |
| 用「类型推断」散文列代替 `item_type` 枚举 | `item_type` 填 1~6 |
| 无行级数据却声称「表已完整」 | 行齐、缺值标 `待填` |
| Agent 猜测权重/分值 | 标 `待填`，进 04 待策划补（Q-Dxx，见 configurable_rules） |
| 倍率/速度/周期只写在 `trigger_desc` | 拆独立数值列；desc 仅策划摘要（见 [implementation_data](../implementation_data/tech.md)） |
| 表骨架 ✅ 当作域可开发 | gap 分 G-xxa 结构 / G-xxb 契约 |

### 行为 / 积分类表

与道具表**同一规范**：一行一主键（如 `behavior_id`），条件列 + `score` 等数值列；分值缺失标 `待填`，边界歧义走 Q-Rxx（见 [configurable_rules](../configurable_rules/tech.md)），**不得**拆成「列说明 + 行为清单」两段。

## 目录约定

```text
{feature_root}/02-需求拆解/{功能名}/数据源/
├── 字段映射索引.md          ← P-xx 总表（先于配置表）
├── 配置表/
│   ├── 配置表说明.md        ← 全功能配置表索引 + 字段摘要
│   └── {TableName}.md       ← 每张表：枚举说明 + 数据行（单表）
└── 枚举/枚举定义.md         ← 跨表复用枚举
```

- **`配置表说明.md`**：表清单 + 字段类型摘要，**指向**各 `{TableName}.md`，不重复粘贴 47 行数据。
- **`{TableName}.md`**：该表的**完整**字段定义与数据行。

## 单表文件模板

```markdown
# {TableName} — {中文名}

> **表结构**：一行一{实体}（`{pk}` 主键）。
> **来源**：01 §x · {附件说明}

## 枚举与字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 主键 |
| item_type | enum | 见 PropItemType |
| gravity_fall | bool | 是否受重力掉落 |
| … | … | … |

## 数据（N 行）

| id | … | gravity_fall | weight_by_round | … |
|----|---|--------------|-----------------|-----|
| 1 | … | 待填 | 待填 | … |

**来源**：01 §x
```

枚举在表头写 `enum · PropItemType`，在 `枚举/枚举定义.md` 展开取值表。

## Agent 自检清单（P2-DS 配置表）

- [ ] 每张表是否**一行一主键**，而非「说明 + 清单」分离？
- [ ] 枚举是否已进 `枚举定义.md`，数据列是否填 int 而非中文分类？
- [ ] bool / float / map 是否与程序语义一致（开关 vs 散文）？
- [ ] 缺值是否标 `待填` 而非留空或臆造？
- [ ] `字段映射索引.md` 是否覆盖表中全部业务字段？
- [ ] 缺口是否链到 `04-待策划补充/` 或看板 ID？
