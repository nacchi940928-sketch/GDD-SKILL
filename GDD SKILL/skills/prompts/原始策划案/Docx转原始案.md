## 提示词正文（复制以下内容）

```
【规格交付 · Part 2 · 入口】
将策划提供的策划案源材料规范化为标准「01 原始策划案」，作为后续 需求拆解/功能点梳理 的统一输入。
保留全部业务信息；不得概括删减；不得写 R/P 编号（那是 需求拆解 的工作）。

工作包名称（策划案主题）：{功能名}    ← 与产出目录名一致
产出目录：产出/{功能名}              （feature_root）

【@ 必读输入】
- 源文档/{策划案}.docx（或 .md / 口述整理稿 / 原始策划案-草稿.md）
- 若经 docx_extract：`_docx_extract.txt` 或 tools 输出中间稿

【本步任务】
整理为规范的「01 原始策划案」定稿。

【输出路径】
{feature_root}/01-原始策划案/{功能名}/原始策划案.md
（配置/道具/技能等 **行级大表** 另存）{feature_root}/01-原始策划案/{功能名}/源表提取/{表名}.md

【本步格式要求 — 必须包含六章节】
1. 概述（玩法说明、设计目的、文档范围；含 **做/不做** 范围表或等价段落）
2. 功能流程（主流程 ASCII/文字、关键子流程）
3. 规则（基本规则、各子系统规则、特殊规则）
4. UI及交互（入口、各界面：布局→交互→身份/阶段差异→空态）
5. 美术与表现需求（Icon、背景、动效/特效/音效，带编号）
6. 配置结构（Const 常量、配置表清单与字段说明）

边界标注（必须）：**继承现网** / **本次新增** / **本次改动**

【源表摘录 — 铁律】
1. docx 内 **配置表、道具表、技能表、关卡表** 等行级数据：**禁止**用「若干道具如下」摘要替代
2. 处理方式（二选一或组合）：
   - **A**：01 正文 §6 或附录以 markdown 表格 **全量保留行**（列名与 docx 一致）
   - **B**：大表（>30 行或 >8 列）写入 `源表提取/{表名}.md`，01 §6 写表名 + 字段说明 + `见 源表提取/{表名}.md`
3. 表格须按 document.xml **原始顺序** 与段落交错保留（见 p1 SKILL Docx 提取规范）
4. 01 §6 至少列出：**表名 | 用途 | 关键字段 | 摘录位置（正文/源表提取）**

【Part 2 公共铁律】
1. 自然语言叙述，讲清楚设计意图
2. 不确定处标「【待确认】」，不留空壳章节
3. docx 提取稿须保留表格（转 markdown 表格）

【本步铁律】
- 不要输出 R-xxx / P-xx 编号
- 不要写伪代码和服务端实现细节
- 不要拆成 8 维度文件夹
- **禁止**删行、合并列、改写 docx 表内枚举值为「等」
- 自检：多执行方职责是否在 01 有描述或【待确认】；时序词（轮流/同时/并行/依次）是否矛盾并存

【完成后自检】
- [ ] 六个章节是否都有实质内容？
- [ ] 继承现网边界是否说清？
- [ ] 概述是否含 **做/不做** 范围？
- [ ] 流程描述是否存在 **时序歧义**？
- [ ] docx 每张配置/道具表是否已全量摘录（正文或 源表提取/）？
- [ ] §6 是否列出每张表的摘录位置？

请直接写入 原始策划案.md（及 源表提取/ 文件），不要只输出大纲。
```
