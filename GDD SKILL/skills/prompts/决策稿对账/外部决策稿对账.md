## 提示词正文（复制以下内容）

```
【规格交付 · Part 2 · P4.5 可选】
工作包名称：{功能名}
产出目录：{feature_root}

【@ 必读输入】
- 用户 @ 的外部决策稿（*业务逻辑表* / *已经确认* / 程序反馈目录下文件）
- {feature_root}/01-原始策划案/{功能名}/原始策划案.md
- {feature_root}/02-03需求拆解与功能点梳理/02-需求拆解.md
- {feature_root}/02-03需求拆解与功能点梳理/02.5-工程真源摘录.md
- {feature_root}/02-03需求拆解与功能点梳理/03-功能点梳理.md
- {feature_root}/04-待策划补充/{功能名}/（已有则读）
- {feature_root}/补充与修改看板.md
- templates/logs/模板.log.md

【禁止】
- 首次 P1～P4 未跑完时，不得用决策稿替代 01 真源
- 不得编造 sheet 数值、Spec 口头批准
- 不得把案例 diff 写入 prompts/ 或 pipeline/
- 不得修改 prompts/、pipeline/（维护者任务）

【本步任务】
1. 仅读取决策稿「策划结论 / 已确认」列，逐条 diff 01/02/03/04。
2. 分类登记：A 一致 / B 缺细节 / C 写反 / D 遗漏 / — 双方仍开放。
3. 回流：修正 02 R-、03 伪代码与附录 C、04 Q-R/Q-D（闭合项）、01 流程歧义句。
4. **03 必须与 02 已定 R- 同步**（重点：竞争终裁、阶段时序、放置/预测等易写反章节）。
5. 写 logs/{YYYYMMDD}-{HHmmss}-决策稿回流.log.md（变更类型：决策稿回流）；更新看板。
6. 汇报：覆盖占比变化（A/B/C/D 条数）、仍开放清单。

【覆盖等级定义】
- **A**：规则/终裁/时序与决策稿一致，02/03 可执行
- **B**：决策已闭合，但缺数值/schema/文案，或 03 待同步 02
- **C**：产线与决策稿冲突，按决策稿修正
- **D**：决策稿已闭合，产线无对应条目，须补写
- **—**：sheet 导出、数值终稿、Spec 批准等双方仍开放，只登记 04/看板

【完成后自检】
- [ ] 决策稿已闭合项无 C 类残留
- [ ] 03 与 02 已定 R- 无冲突
- [ ] sheet/数值/Spec 仍开放项只在 04/看板登记
- [ ] 未修改 prompts/、pipeline/
- [ ] log 含 diff 摘要（A/B/C/D 条数）与决策稿来源路径

请直接写入/修正产出文件，不要只输出 diff 大纲。
```
