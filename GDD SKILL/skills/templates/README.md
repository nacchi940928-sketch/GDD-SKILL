# templates — 空模板与写作规范

> **用途**：新建功能时复制骨架；Agent 跑 需求拆解/功能点梳理 时参考格式。**不是**管线产出（产出在 `产出/{功能名}/`）。

---

## 目录一览

```text
templates/
├── README.md                          ← 本文件
├── 02-需求拆解-写作规范.md             ← ★ 02 单文档写作铁律（需求拆解 必读）
├── 转换规范.md                        ← 01→03 转换铁律
├── 补充与修改看板.md                  ← 看板空模板
├── logs/
│   └── 模板.log.md                    ← 编译验收·管线执行日志 执行日志
├── 00-立项探索/{功能名}/              ← 立项探索 可选
├── 01-原始策划案/{功能名}/
│   └── 原始策划案.md
├── 02-需求拆解/{功能名}/              ← 需求拆解 九步章节骨架（见下）
└── 04-待策划补充/{功能名}/            ← 待策划补充 策划/程序/美术/音频填写区（06 含音效与动效）
```

---

## `02-需求拆解/{功能名}/` — 九步骨架（已扁平化）

需求拆解 各步 Prompt 按章节写入 **`{spec_root}/02-需求拆解.md` 单文件**，不再创建子文件夹。

本目录提供**各步的参考骨架**（含编号格式与案例），文件名即步骤名：

| 文件 | 对应 02 章节 | 需求拆解 Prompt |
|------|--------------|-----------|
| [数据源.md](02-需求拆解/{功能名}/数据源.md) | §6 数据概要（策划语言） | 需求拆解·数据源 |
| [系统内容分解.md](02-需求拆解/{功能名}/系统内容分解.md) | §1.5 系统与内容分解 | 需求拆解·系统内容分解 |
| [规则.md](02-需求拆解/{功能名}/规则.md) | §3 业务规则（含 **边界** 备注） | 需求拆解·规则 |
| [边界条件.md](02-需求拆解/{功能名}/边界条件.md) | §5 边界与异常 | 需求拆解·边界条件 |
| [状态机.md](02-需求拆解/{功能名}/状态机.md) | §2 流程与状态 | 需求拆解·状态机 |
| [UI交互.md](02-需求拆解/{功能名}/UI交互.md) | §4 UI 与交互 | 需求拆解·UI交互 |
| [红点.md](02-需求拆解/{功能名}/红点.md) | §6.1 红点 | 需求拆解·红点 |
| [校验规则.md](02-需求拆解/{功能名}/校验规则.md) | 引导至 03 附录 E.2 | 需求拆解·校验规则 |
| [验收标准.md](02-需求拆解/{功能名}/验收标准.md) | §7 验收要点 | 需求拆解·验收标准 |

**用法**：

1. 新建功能时，复制 `{功能名}` 占位目录或按需 @ 单个维度文件
2. 需求拆解 执行时：读骨架 + [02-需求拆解-写作规范.md](02-需求拆解-写作规范.md) → **合并写入** `{feature_root}/02-03需求拆解与功能点梳理/02-需求拆解.md`

## 功能点梳理 单文档

当前交付为 **单文件** `{spec_root}/03-功能点梳理.md`（§0 + 各章 + 附录 A~E）。格式见 [p3-feature-spec-功能点梳理/SKILL.md](../pipeline/p3-feature-spec-功能点梳理/SKILL.md)。

---

## 与 `skills/`、`prompts/` 的关系

| | templates/ | skills/ | prompts/ |
|--|------------|---------|----------|
| 内容 | 空表、示例行、章节骨架 | 格式铁律、抽象框架 | 可复制的执行指令 |
| 何时用 | 新建功能、查表格长什么样 | Agent 读规范 | 复制粘贴跑管线 |
| 是否含业务 | 仅**虚构案例**（背包、好友…） | 不含 L2 业务 | 不含 L2 业务 |

---

## 占位符

复制模板时将 `{功能名}` 替换为实际功能目录名（与 `产出/{功能名}` 一致）。
