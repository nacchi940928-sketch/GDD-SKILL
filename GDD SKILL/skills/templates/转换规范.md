# 策划案转换规范

> 当拿到一份策划案（.docx 或 .md），按此规范转化为三阶段输出。

---

## 转换流程

```
策划案.docx
    │
    ├──→ 01-原始策划案/     ← 提取设计意图和规则叙述
    │
    ├──→ 02-需求拆解.md     ← 策划视角单文档（八维度、自然语言）
    │
    └──→ 03-功能点梳理.md   ← 程序规格单文档（功能点 + 附录 A~E）
```

---

## 核心铁律

### 1. 03-功能点梳理.md = 程序唯一主文档

- **绝对自包含**：程序无需对照任何其他文档即可开发
- **保留全部细节**：原始文档的每个段落、每个表格都要保留
- **禁止概括**：不要"总结为"、"归纳为"，要完整展开
- **表格必须完整**：涉及模块表、数据来源表、程序分工表——一个不能少
- **附录**：A 字段 · B 验收 · C 待确认 · D 数据契约 · E 协议/校验/枚举/配置表

### 2. 01-原始策划案 = 策划视角的设计叙述

- 从策划案中提取设计意图、玩法说明、规则叙述
- 用自然语言写，不需要表格化
- 覆盖：概述→流程→规则→UI→美术→配置

### 3. 02-需求拆解.md = 策划可读单文档

- 八维度章节（§1~§8），**自然语言**
- 每条规则有唯一编号 R-/EX-/PRE-/LIM-
- **禁止**：P-xx、伪代码、V-xx、数据契约审计
- 每条标注来源（引用 01 的章节）

---

## Docx 提取规范

```
必须：使用 XML 方式提取，保持段落和表格的文档顺序
禁止：使用 python-docx 的 paragraphs→tables 分离方式（会丢失表格归属）

正确做法：
1. 解析 word/document.xml
2. 按文档 body 元素顺序遍历
3. w:p → 段落，w:tbl → 表格
4. 保持原始顺序输出
```

---

## 03 章节拆分规范

原始文档的章节结构：
```
[] 0. 阅读说明
  [] 0.1 子章节
[] 1. 功能模块A
  [] 1.1 子章节
  === 表格 ===
[] 2. 功能模块B
  ...
```

拆分规则（写入 **同一文件** `03-功能点梳理.md`）：
- **§0** → 阅读说明、导航、名词、全局矩阵
- **顶级章节** `## N.` → 功能点章
- **子章节** `### N.M` → 保留在父章内
- **附录 A~E** → 字段、验收、待确认、审计、协议/表/校验

---

## 检查清单

转换完成后逐项检查：

- [ ] 03 每个功能点章 > 500 字符（太短说明丢了表格）
- [ ] 03 每章含五块标准结构（涉及模块/功能点/数据来源/怎么实现/程序分工）
- [ ] 02 核心 R- 均为自然语言，无伪代码
- [ ] 01 覆盖概述/流程/规则/UI/美术/配置
- [ ] 附录 A P-xx 全部登记，与功能点引用一致
- [ ] 附录 B 验收场景可直接测试
- [ ] 每次改交付文档后新建 `logs/{YYYYMMDD}-{HHmmss}.log.md`
