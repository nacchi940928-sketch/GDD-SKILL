## 定位

`01-原始策划案/` 是策划视角的**完整设计叙述**，所有下游（需求拆解/功能点梳理）从这里提取。

**路径规范**（详见 [使用指导.md](../../../使用指导.md)）：

| 文件 | 路径 |
|------|------|
| 策划源 docx | `源文档/`（**仅原始 doc**，原始策划案·Docx转原始案 @ 转换） |
| 立项探索 草稿 | `产出/{功能名}/01-原始策划案/{功能名}/原始策划案-草稿.md` |
| **原始策划案 定稿（P2+ @ 此文件）** | `产出/{功能名}/01-原始策划案/{功能名}/原始策划案.md` |

## 与 02/03 的分工

| 01 原始策划案 | 02/03 |
|---------------|-------|
| 自然语言，讲清楚设计意图 | 结构化、编号化、可执行 |
| 允许不完整、待确认 | 必须可实现 |
| 策划主笔 | 程序/AI 拆解 |

## 必须覆盖的章节

1. 概述（玩法说明、设计目的、**范围：做/不做**）
2. 功能流程（主流程、子流程）
3. 规则（基本、子系统、特殊）
4. UI及交互（入口、各界面）
5. 美术与表现需求（Icon、背景、动效/特效、音效，带编号）
6. 配置结构（Const、配置表）

## 边界标注

必须在文中明确标注：
- **继承现网**：哪些模块/规则沿用已有系统
- **本次新增**：哪些是全新设计
- **本次改动**：哪些是改分组/入口/规则 delta

## Docx 提取规范

```
必须：按 document.xml body 元素顺序遍历（段落与表格交错保留）
禁止：python-docx 先 paragraphs 后 tables（会丢失表格归属）

流程：
1. 解析 word/document.xml
2. w:p → 段落，w:tbl → 表格
3. 表格输出为 markdown 表格或 === 表格 === 标记
4. 保持原始顺序
```

工具：`python tools/docx_extract.py`（提取中间稿，再经 原始策划案·Docx转原始案 整理为原始策划案）

## 源表摘录（01 输入质量）

docx 内 **行级配置表**（道具/技能/关卡/商店条目等）是 P2 拆解的硬输入，**禁止**在 01 仅留摘要。

| 表规模 | 处理方式 |
|--------|----------|
| 小表（≤30 行且 ≤8 列） | 01 正文 §6 或附录 **全量 markdown 表格** |
| 大表 | `{feature_root}/01-…/源表提取/{表名}.md` 全量保留；01 §6 写表名 + 字段说明 + 链接 |
| 枚举/Const | 01 §6 列名与取值 **与 docx 一致**，禁止「等」省略 |

完整性检查须对照 `源表提取/` 与 01 §6，缺失行级数据 → **P0 决策阻塞**（无法可靠拆 CNT-/R-）。

## Gap 阻塞分级（完整性检查 用）

| 级别 | 典型 gap | 进 P2 |
|------|----------|-------|
| **P0 · 决策阻塞** | 无做/不做、时序歧义、无终裁方、源表仅摘要、多执行方职责缺失 | ❌ |
| **P1 · 数值/Sheet** | Const 缺值、美术编号待填、表行在但数值【待确认】 | ⚠️ 可进，登记 04 |
| **P2 · 非阻塞** | 文案、可选章节、结构建议 | ✅ |

**铁律**：P0>0 → **禁止进 P2**；Agent 不得用推断默认闭合 P0。

## 检查清单（原始策划案·完整性检查 用）

- [ ] 概述：玩法 + 目的 + 范围（**做/不做** 或等价表述）
- [ ] 功能流程：主流程图 + 关键子流程；**无时序歧义**（轮流/同时/并行/依次 不得矛盾并存）
- [ ] 规则：子系统全覆盖
- [ ] UI：每界面布局→交互→状态→空态
- [ ] 美术：资源编号
- [ ] 配置：Const + 表结构
- [ ] 继承现网 / 新增 / 改动 边界清晰
- [ ] **决策级遗漏**：MVP 不做项、多执行方职责、阶段细则是否在 01 有提及或【待确认】
- [ ] **歧义未消歧**：时序词（轮流/同时）、终裁方（先到先得由谁）是否矛盾
- [ ] **源表摘录**：配置/道具/技能表是否全量进 01 或 `源表提取/`
- [ ] **Gap 分级**：P0 是否为零（否则不进 P2）
