# 编译验收 — 规范（Skill）

> **目录**：`p5-compile-verify-编译验收/`  
> **本文件是 Skill（知识与规范）**，不是提示词。  
> 执行请使用 `prompts/编译验收/` 中的提示词。

---

## 定位

编译验收 在 P3/待策划补充 完成后，检查文档质量、执行编译、策划验收。**禁止手改 `{feature_root}/开发文档/`**。

## 编译命令

```bash
cd "GDD SKILL"
python skills/tools/compile.py 产出/{功能名} --workflow skills/workflows/{项目}.workflow.json
```

产出 `{feature_root}/开发文档/`：

| 文件 | 内容 | 不嵌入 |
|------|------|--------|
| 程序包.md | 03 全文（+ 04 已填项） | 02 |
| 测试包.md | 03 附录 B + 02 §5/§7 + Skill QA 索引 | L1 qa 全文 |
| 策划包.md | skill_configs + 01 + 02 + Skill 索引 | L0/L1 design/ux/tech/qa 全文 |
| compiled.json | 编译元数据 | — |

**Skill 索引**：仅列 `skill_id`、仓库路径、可用文件名；实例参数只在 `skill_configs`。


## 执行日志

**铁律**：只要改动了 `{feature_root}` 下交付文档（01/02/03/04/看板/README 等），本次工作结束前须**新建**一条日志——不限于 编译验收 全量验收或管线会话结束。

| 场景 | 是否写 log |
|------|------------|
| 原始策划案～开发管线 任意组合 | ✅ 必写 |
| 仅改 02/03 局部 | ✅ 必写 |
| 04 回填 → 回流 02/03 | ✅ 必写 |
| 仅 `compile.py` | ✅ 必写（记录输入变更 + compile 结果） |
| 目录/链接/规范维护 | ✅ 必写 |
| 只读未改文件 | 不必 |

路径与命名：

```text
{feature_root}/logs/{YYYYMMDD}-{HHmmss}.log.md
```

模板：`templates/logs/模板.log.md`。同功能多次更新多条并存，**禁止覆盖**、禁止在旧文件追加。

**§0 本次变更**为必填：列出本次修改文件路径，与 git diff 对齐。

Prompt：`管线执行日志.md`（名称保留，适用全部文档更新）。

## 推荐顺序

```
待策划补充·策划回填验收 完成后 → 编译验收·职能分轨检查 → 修正错轨 → 编译验收·执行编译验收 compile → 编译验收·策划验收清单 → 编译验收·管线执行日志 写 logs → 开发管线
```
