# 工程真源对齐 — 规范（Skill）

> **目录**：`p2b-program-bind-工程真源对齐/` · **文档阶段**：02.5（**P2 与 P3 之间**）  
> **本文件是 Skill（知识与规范）**，不是提示词。  
> 执行请使用 `prompts/工程真源对齐/` 中的提示词。

---

## 定位

在 **需求拆解（02）完成** 之后、**功能点梳理（03）开始** 之前，根据 02 的 §1.5 / §6 / 流程与规则关键词，**检索 workflow 配置的 `program_repo`**，将仓库中**已存在**的协议、配置表、字段、枚举摘录为 L2 真源。

| 是 | 不是 |
|----|------|
| 填写仓库中**已证实存在**的字段/协议/表名 | Agent 臆造 `AB2_*`、自造 proto 名 |
| 未命中时 **留空** 并登记 `Q-P` 待程序补充 | 用建议默认值冒充程序字段 |
| 产出 `02.5-工程真源摘录.md` | 修改 02 策划正文 |
| P3 附录 A/E 的**绑定输入** | 替代 04 数值策划填写 |

---

## 三态绑定规则

| 状态 | 含义 | 附录 A「配置表·程序字段」列 |
|------|------|---------------------------|
| **已绑定** | 02.5 摘录有仓库路径来源 | 写 `表名.字段` + 备注来源文件 |
| **待补·程序** | 02 需要但仓库未找到 | 写 `—` · 状态 `Q-P-xx` · **禁止编造 snake_case** |
| **待补·策划** | 字段已绑定，数值未定 | 字段可写；默认值列 `待填 Q-D` |

**禁止第四态**：无仓库来源时，不得用 docx 内嵌表名（如 `AB2_*`）冒充程序真名，除非 02.5 标明 `来源: 01/docx 待程序映射`。

## 输入 / 输出

| 输入 | 输出 |
|------|------|
| `{feature_root}/02-03…/02-需求拆解.md` | `{spec_root}/02.5-工程真源摘录.md` |
| `skills/workflows/{项目}.workflow.json` → `program_repo` | 更新 `补充与修改看板.md` 中 Q-P 索引（可选） |
| 程序仓库（`program_repo.root`，可选） | |

**禁止输入**：`程序反馈/` 目录下任何文件（程序侧审计稿，非管线真源）。

---

## 跳过条件

| 条件 | 行为 |
|------|------|
| workflow 无 `program_repo` 或 `optional: true` 且 root 为空 | **仍执行** Prompt，产出 02.5 §4「全部待程序补充」，不检索 |
| `program_repo.root` 路径不存在 | 同上，标注「仓库路径无效」 |
| 用户明示跳过工程对齐 | 不写 02.5；P3 全部字段标 Q-P |

## 与 P3 的衔接

P3 **字段映射**、**功能点拆分** 必读 `02.5-工程真源摘录.md`：

- 已绑定 → 附录 A/E **必须**采用摘录名
- 待补·程序 → 正文用 **P-xx 或中文业务名**，不写未绑定 proto 名
- 伪代码中 `Req/Rsp` 名：仅当 02.5 §1 已列出
