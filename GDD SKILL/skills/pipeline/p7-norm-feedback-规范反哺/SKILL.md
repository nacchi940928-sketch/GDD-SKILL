# 规范反哺 — 演进萃取（Skill）

> **目录**：`p7-norm-feedback-规范反哺/` · **阶段**：P7（**可选 · 维护者 · 手动**）  
> **本文件是 Skill（知识与规范）**，不是提示词。  
> 执行请使用 `prompts/规范反哺/生成规范反哺报告.md`。

---

## 定位

从**已完成**的 L2（`产出/{功能名}/02、03、04、logs`）中萃取相对现有 Prompt/Skill 的**规范增量**，产出 `规范反哺报告.md`，供维护者按 [GDD-SKILL-更新规范.md](../../GDD-SKILL-更新规范.md) 人工改库。

| 是 | 不是 |
|----|------|
| 交付轨 A 之后的**演进轨 B** 入口 | gdd-decompose 的自动下一步 |
| 建议写 `_backlog`、改 Prompt 的**清单** | 自动修改 `prompts/`、`skills/` |
| 跨功能积累维度 Skill 的依据 | 单功能 04 回填 |

---

## 触发条件（须用户显式说明）

仅当用户说出类似意图时执行：

- 「跑规范反哺 / 生成规范反哺报告」
- 「按 gdd-norm-feedback …」
- 「从这次拆解总结规范，但不要改 skill」

**禁止**在 gdd-decompose 整包拆解、compile 完成后**自动**进入本阶段。

---

## 输入 / 输出

| 输入 | 输出 |
|------|------|
| `{feature_root}/02-需求拆解.md` | `{feature_root}/规范反哺报告.md` |
| `{feature_root}/03-功能点梳理.md` | （可选）维护者另写 `_backlog/{skill_id}.md` 草案内容在报告 §4 |
| `logs/`、`04/`、看板 | **不**写 `skills/`、`prompts/` |

---

## 抽象铁律（写入报告前必问）

与 [GDD-SKILL-更新规范.md](../../GDD-SKILL-更新规范.md) §3.3 一致：

1. 能否去掉功能名？不能 → 标「仅 L2」
2. 能否去掉具体数值？不能 → 标「仅 L2」或「待填流程」
3. 是否 2+ 项目复用？否 → 不建议晋升 Skill
4. 是格式问题还是业务规则？业务 → 留 L2；格式/协作 → 建议 Skill/Prompt
5. 程序是否已认可 L2 结构？未认可 → 只记问题，不建议晋升

---

## 与 P2/P3 步骤的对照

报告 §2 须按下列步骤填表（无缺口写「无」）：

**P2**：数据源 → 系统内容分解 → 规则 → 边界条件 → 状态机 → UI交互 → 红点 → 校验规则 → 验收标准  

**P3**：阅读说明 → 功能点拆分 → 字段映射 → 验收场景 → 待确认事项 → Feature对齐  

---

## 处置流程（报告写完后 · 人工）

```text
规范反哺报告.md
    → 维护者审阅 §3～§6
    → 确认项：S1 登记 _backlog / S6 改 Prompt @ / S5 晋升 skills/tech/
    → S7 用**新功能**回归；写 logs/
```

**频率建议**：同类玩法 **2+ 功能**出现同一规范缺口后再晋升 Skill，避免 Prompt/Skill 反复替换。
