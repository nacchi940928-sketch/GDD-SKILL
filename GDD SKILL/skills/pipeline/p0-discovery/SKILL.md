# P0 立项探索 — 规范（Skill）

> **本文件是 Skill（知识与规范）**，不是提示词。  
> 执行请使用 `prompts/P0/P0-*.md` 中的提示词。

---

## 定位

P0 是**可选的策划创作辅助线**，位于 P1 之前。  
帮助策划从模糊想法 → 结构化立项 → 玩法大纲 → 01 初稿，**不替代**策划定案。

| P0 立项探索 | P1 原始策划案 |
|-------------|---------------|
| 草稿、选项、问题清单 | 策划确认的正式输入 |
| 可脑暴、可多方案 | 单一真相来源 |
| 禁止 R/P 编号、伪代码 | 自然语言完整叙述 |
| 产出在 `00-立项探索/` | 产出在 `01-原始策划案/` |

**何时跳过 P0**：策划已有完整 docx/01，直接进入 P1-1 整理即可。

---

## 产出目录

路径相对于 `{feature_root}` = `产出/{功能名}/`。完整规范见 [使用指导.md](../../../使用指导.md)。

```text
{feature_root}/
├── 00-立项探索/{功能名}/
│   ├── README.md
│   ├── project.json
│   ├── game_dna.json / game_dna.md
│   ├── skill选型.md
│   └── 玩法大纲.md
└── 01-原始策划案/{功能名}/
    └── 原始策划案-草稿.md    ← P0-4；P1 定稿为 原始策划案.md
```

---

## 公共铁律

1. **创作 ≠ 交付**：P0 产出均为草稿，须策划确认后才能进 P2
2. **禁止编造**：数值、接口、现网规则不明则标「待研究 / 待确认」
3. **禁止程序规格**：不写 R-xxx、P-xx、伪代码、状态机表格
4. **参考游戏仅启发**：不得把参考游戏的规则当成本项目已定规则
5. **L1 优先**：有框架 Skill 的系统优先推荐继承，只列 delta
6. **一次一问**（P0-1 对话模式）：每组问题不超过 5 个，等策划回复再继续

## 功能层级（P0-3 用）

| 层级 | 说明 | 示例 |
|------|------|------|
| 基础功能层 | 账号、背包、通用 UI | 通常不单独走 P0 |
| 边缘系统层 | 商店、签到、邮件 | 待建 shop_system 等 |
| 核心玩法层 | 战斗、养成主循环 | 通常已有现网模块 |
| **活动玩法层** | 限时活动、赛季玩法 | **本工程主要场景** |

---

## L1 Skill 选型原则

1. 读取 `skills/README.md` 与 `skills/frameworks/*/meta.md`
2. 只推荐**已存在**的 skill_id，禁止虚构
3. 匹配度说明：完全匹配 / 部分匹配（列 delta）/ 无匹配（待建 Skill）
4. workflow 草案只填已知 config，未知留 `"待策划确认"`

---

## 与 workflow 的衔接

P0-3 产出 `skill选型.md` 中的 workflow 草案，策划确认后可复制为：

```text
workflows/{项目}.workflow.json
```

P0-4 玩法大纲中的「继承现网 / 新增 / 改动」须与 P1 边界标注一致。

## 检查清单（P0 → P1 交接）

- [ ] project.json 字段完整，open_questions 已处理或标注阻塞
- [ ] game_dna 五项有实质内容，excluded_systems 明确
- [ ] skill选型 推荐的 L1 已读 meta.config_schema
- [ ] 玩法大纲含主流程 + 子系统清单 + 界面清单
- [ ] 01 草稿六章节有内容，【待确认】项策划已知悉
- [ ] 策划口头/书面确认「可进入 P1 定稿」

## 推荐顺序

```text
（策划有模糊想法或仅有口述）
  → P0-1 → 策划确认 project
  → P0-2 → 策划确认 DNA
  → P0-3 → 策划确认 Skill 选型
  → P0-4 → 策划审阅大纲与 01 草稿
  → P1-1 定稿（或 P1-2 完整性检查）→ P2
```
