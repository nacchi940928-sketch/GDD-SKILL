## 必须覆盖的章节

1. 概述（玩法说明、设计目的）
2. 功能流程（主流程、子流程）
3. 规则（基本、子系统、特殊）
4. UI及交互（入口、各界面）
5. 美术需求（Icon、背景、动画）
6. 配置结构（Const、配置表）

## 边界标注

必须在文中明确标注：
- **继承现网**：哪些模块/规则沿用已有系统
- **本次新增**：哪些是全新设计
- **本次改动**：哪些是改分组/入口/规则 delta

## Docx 提取规范

```
必须：按 document.xml body 元素顺序遍历（段落与表格交错保留）
禁止：python-docx 先 paragraphs 后 tables（会丢失表格归属）

流程：
1. 解析 word/document.xml
2. w:p → 段落，w:tbl → 表格
3. 表格输出为 markdown 表格或 === 表格 === 标记
4. 保持原始顺序
```

工具：`python tools/docx_extract.py`（提取中间稿，再经 P1-1 整理为原始策划案）
