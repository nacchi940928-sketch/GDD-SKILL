# P5 编译验收 — 规范（Skill）

> **本文件是 Skill（知识与规范）**，不是提示词。  
> 执行请使用 `prompts/P5/P5-*.md` 中的提示词。

---

## 定位

P5 在 P3/P4 完成后，检查文档质量、执行编译、策划验收。**禁止手改 outputs/**。

## 编译命令

```bash
cd "GDD SKILL"
python tools/compile.py 产出/{功能名} --workflow workflows/{项目}.workflow.json
```

产出 `outputs/{功能名}/`：
- 程序包.md
- 测试包.md
- 策划包.md
- compiled.json

| 错轨内容 | 应在 |

## 策划验收清单

## 变更回流

```text
需求变更 → 改 02/03/04 或 L1 Skill → 重新 compile → 评审 outputs diff
```

## 执行日志

**铁律**：只要改动了 `{feature_root}` 下交付文档（01/02/03/04/看板/README 等），本次工作结束前须**新建**一条日志——不限于 P5 全量验收或管线会话结束。

| 场景 | 是否写 log |
|------|------------|
| P1~P6 任意组合 | ✅ 必写 |
| 仅改 02/03 局部 | ✅ 必写 |
| 04 回填 → 回流 02/03 | ✅ 必写 |
| 仅 `compile.py` | ✅ 必写（记录输入变更 + compile 结果） |
| 目录/链接/规范维护 | ✅ 必写 |
| 只读未改文件 | 不必 |

路径与命名：

```text
{feature_root}/logs/{YYYYMMDD}-{HHmmss}.log.md
```

模板：`templates/logs/模板.log.md`。同功能多次更新多条并存，**禁止覆盖**、禁止在旧文件追加。

**§0 本次变更**为必填：列出本次修改文件路径，与 git diff 对齐。

Prompt：`P5-4-管线执行日志.md`（名称保留，适用全部文档更新）。

## 推荐顺序

```
P4-2 完成后 → P5-1 → 修正错轨 → P5-2 compile → P5-3 → P5-4 写 logs → P6
```
