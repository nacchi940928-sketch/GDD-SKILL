# P3 功能点梳理 — 规范（Skill）

> **本文件是 Skill（知识与规范）**，不是提示词。  
> 执行请使用 `prompts/P3/P3-*.md` 中的提示词。  
> **格式真源**：`源文档/竞技场高级赛（纷乱的群殴锦标赛）—— 功能点梳理.docx`

---

## 定位

`03-功能点梳理.md` 是**程序 / 服务端 / AI 开发管线的唯一主读文档**，必须自包含、单文件可读。

| 读者 | 文档 |
|------|------|
| 程序、服务端、AI | **`{feature_root}/03-功能点梳理.md`** |
| 策划、运营、产品、老板 | `{feature_root}/02-需求拆解.md`（自然语言，**非**程序输入） |

02 定「做什么」；03 定「怎么做」——含伪代码、P-xx、协议、表结构、审计。

---

## 交付形态（单文档）

```text
{feature_root}/
├── 02-需求拆解.md          ← 策划汇报（P2）
├── 03-功能点梳理.md        ← 程序主读（P3）
├── 01-原始策划案/…
├── 04-待策划补充/…
└── 补充与修改看板.md
```

合并工具（legacy 一次性）：`python tools/merge_delivery.py {feature_root}`

## 文档结构

```markdown
# {功能名} — 功能点梳理

## 0. 阅读说明（导航、名词、跳转、分工）
## 1. {顶级功能点}
### 涉及界面 / 系统模块
### 功能点
### 数据来源（P-xx）
### 怎么实现（伪代码、服务端/客户端）
### 程序实现分工

## 附录 A 字段映射（P-xx 全表）
## 附录 B 验收场景
## 附录 C 待确认事项
## 附录 D 实现数据契约与专项审计（implementation_data）
## 附录 E 协议与配置表（程序态，可选独立节）
```

| 原则 | 说明 |
|------|------|
| 一级目录 = 功能点 | `## N.`；从 **02 的 R-/流程** 展开，写全实现 |
| 正文 | 可写 P-xx、协议名、Phase；禁止「见 02 §x」 |
| 每章五块 | 模块 → 功能点 → 数据 → 怎么实现 → 分工 |
| 附录 A | **唯一** P-xx 登记处 |
| 附录 D | R-xx 变量追溯、Const/表审计、模块就绪矩阵 |
| 附录 E | MatchStartReq 等协议表、AB2_* 配置表（一行一主键） |

---

## 公共铁律

1. **绝对自包含**：禁止跳转 01/02 才能开发
2. **02 → 03 映射**：每条 R-CHH-xxx 在 03 有对应「怎么实现」或附录追溯
3. **字段**：只用附录 A 已登记 P-xx
4. **implementation_data**：审计产出在 **附录 D**，不在 02
5. **config_table**：程序态表在附录 E 或各章「数据来源」

---

## 03 vs 02 分工

| 02 需求拆解.md | 03 功能点梳理.md |
|----------------|------------------|
| 策划可读自然语言 | 伪代码 + P-xx + 协议 |
| R- 规则说明 | R- 检测位置/方式/读写 |
| 玩家流程 | Phase 枚举、状态机 |
| 数据概要（表名） | 字段映射、配置表、审计 |
| UI 跳转（用户视角） | 模块、接口、分工 |
| T- 用户语言验收 | 附录 B 细场景 + 字段断言 |
