# P3 功能点梳理 — 规范（Skill）

> **本文件是 Skill（知识与规范）**，不是提示词。  
> 执行请使用 `prompts/P3/P3-*.md` 中的提示词。  
> **格式真源**：`源文档/竞技场高级赛（纷乱的群殴锦标赛）—— 功能点梳理.docx`

---

## 定位

`03-功能点梳理.md` 是**程序 / 服务端 / AI 开发管线的唯一主读文档**，必须自包含、单文件可读。

| 读者 | 文档 |
|------|------|
| 程序、服务端、AI | **`{feature_root}/03-功能点梳理.md`** |
| 策划、运营、产品、老板 | `{feature_root}/02-需求拆解.md` |

---

## 交付形态（单文档）

```text
{feature_root}/
├── 02-需求拆解.md          ← 汇报用（P2 产出合并）
├── 03-功能点梳理.md        ← 程序主读（P3 产出合并）
├── 01-原始策划案/…         ← 保留
├── 04-待策划补充/…         ← 保留
└── 补充与修改看板.md
```

**禁止**再按 `03-功能点梳理/{功能名}/功能点/*.md` 多文件作为最终交付（Agent 可分批写临时片段，**必须**合并进单文档）。

合并工具：`python tools/merge_delivery.py {feature_root}`

---

## 文档结构（对齐竞技场 docx）

```markdown
# {功能名} — 功能点梳理

> 程序主文档：自包含…

## 0. 阅读说明
### 0.1 文档结构与引用约定
### 0.2 功能点一览（导航）
### 0.3 名词定义
### 0.4 UI 原型图索引（如有）
### 0.5 全局行为矩阵（如有）
### 0.6 活动日程（如有）
### 0.7 界面跳转

## 1. {顶级功能点}
### 涉及界面 / 系统模块
### 功能点（规则表写全）
### 数据来源
### 怎么实现
### 程序实现分工

## 2. …

## 附录 A 字段映射
## 附录 B 验收场景
## 附录 C 待确认事项
```

| 原则 | 说明 |
|------|------|
| 一级目录 = 功能点 | `## N. 名称`；子节 `N.M` 用 `###` |
| 正文引用 | 写功能点/界面名称，禁止「见原始文档」「见 02/xx」 |
| 每章标准块 | 涉及模块 → 功能点 → 数据来源 → 怎么实现 → 程序分工 |
| 字段 | 只用 P-xx；完整定义在附录 A |

## 公共铁律

1. **绝对自包含**：禁止跳转 01/02 才能理解实现
2. **保留全部细节**：表格完整，禁止「总结为」「归纳为」
3. **字段引用**：P-xx 在附录 A 统一定义
4. **继承现网**：只写 delta + 对接点
5. **数据契约**：与 02 中 R-xx 读表一致（见 [implementation_data](../tech/implementation_data/tech.md)）
