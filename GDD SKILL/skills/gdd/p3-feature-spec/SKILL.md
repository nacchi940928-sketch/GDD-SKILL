# P3 功能点梳理 — 规范（Skill）

> **本文件是 Skill（知识与规范）**，不是提示词。  
> 执行请使用 `prompts/P3/P3-*.md` 中的提示词。

---

## 定位

`03-功能点梳理/` 是**程序 AI 管线的唯一主读文档**，必须自包含。

## 公共铁律

1. **绝对自包含**：禁止「见原始文档」「见 02/xx」
2. **保留全部细节**：禁止「总结为」「归纳为」，表格完整
3. **标准块**：每个功能点含「涉及模块 → 功能点 → 数据来源 → 怎么实现 → 程序分工」
4. **字段引用**：只用 P-xx，在 `字段映射.md` 统一定义
5. **继承现网**：只写 delta + 对接点，标注复用/改动/新增模块

## 目录结构

```text
03-功能点梳理/{功能名}/
├── 0-阅读说明.md
├── 功能点/
│   └── {编号}-{名称}.md
├── 字段映射.md
├── 验收场景.md

```

## 功能点拆分规则

| 原始结构 | 输出 |
|----------|------|
| 顶级章节 `N. 名称` | `功能点/{N}-{名称}.md` |
| 子章节 `N.M` | 保留在父文件内 |
| 表格 | 保留在出现位置，禁止拆散 |
| 附录 A/B/C | → 验收场景.md / 待确认事项.md |

```markdown

## 怎么实现
```

## 03 vs 02 分工

| 02 需求拆解 | 03 功能点梳理 |
|-------------|---------------|
| 维度化、编号化、可评审 | 按模块、程序可读、可开发 |
| 允许跨文件引用 P-xx | 规则写全，禁止跳转 |
| 伪代码偏规范 | 伪代码偏实现 + 分工 |

## 检查清单

- [ ] 每个功能点文件 > 500 字符（过短说明丢了表格）
- [ ] 每个功能点含完整三表（模块/数据/分工）
- [ ] 字段映射与 02/数据源/字段映射索引 一致
- [ ] 验收场景可直接测试，自带关键规则
