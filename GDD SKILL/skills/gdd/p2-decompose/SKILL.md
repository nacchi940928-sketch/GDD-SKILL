> 执行拆解请使用 `prompts/P2/P2-*.md` 中的提示词。

---

## 公共铁律

0. **路径**：所有产出写在 `产出/{功能名}/` 下，结构见 [使用指导.md](../../../使用指导.md)；Prompt 中 `{feature_root}` = `产出/{功能名}`
0b. **单文档交付**：P2 完成后合并为 **`{feature_root}/02-需求拆解.md`**（策划/运营/产品/老板汇报）；八维度可分批写入临时目录后由 `tools/merge_delivery.py` 合并，或 Agent 直接维护单文件
1. 每条有唯一编号，标注来源章节（引用 01）
2. 展开到可实现：检测位置 / 检测方式 / 数据依赖 / 伪代码
3. 与 L1 基底相同写「继承 {skill_id}」，只写 delta
4. 禁止「见原始文档」等模糊引用
5. 字段用 P-xx，在数据源维度统一登记
6. 状态机用 V6 写法：触发条件 / 表现 / 禁止 / 验收

## 配置表（L0）

P2-DS 产出 `数据源/配置表/` 时**必须**遵循 [tech/config_table/tech.md](../tech/config_table/tech.md)：

- 一行一主键，禁止 docx 式「列说明 + 摘要清单」拆分
- 枚举 / bool / 数值列程序可读；缺值标 `待填`，禁止臆造
- 策划提供骨架 → Agent 合并补充 → 程序开发期完善并回流
- docx 内嵌表**备份** → `01-…/源表提取/`；**程序态** → `02-…/配置表/`（见 config_table）

## 可配置规则（L0）

P2-R / P2-DS 涉及 **Const + 配置表驱动** 的 R-xx 时，遵循 [tech/configurable_rules/tech.md](../tech/configurable_rules/tech.md)：

- R-xx 伪代码只读 P-xx / 表，禁止未登记魔法数
- 数值缺口 → Q-Dxx + `04/02-配置数值.md`；边界缺口 → Q-Rxx + 按需 `04/09-规则边界确认.md`
- 复杂域可产出 `02/规则/{域}全量审计.md`（L2 结构见 configurable_rules Skill）

## 实现数据契约（L0）

P2 **收尾前**必须遵循 [tech/implementation_data/tech.md](../tech/implementation_data/tech.md)：

- 产出 `02/…/数据源/数据契约审计.md`：R-xx 变量 → P-xx/表列/枚举 追溯
- 01 可推断的表单元格**必须填入**；`trigger_desc` 不得承载可程序化数值
- gap 清单区分 **结构已提取（G-xxa）** 与 **契约可开发（G-xxb）**
- P2 完成门禁见下节；**存在核心路径契约阻塞时标 🟡，不得标「可开发」**
