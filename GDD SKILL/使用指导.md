# 使用指导

> 本文件规定**文件放哪里、Prompt 里 @ 什么、产出写哪里**。  
> 所有路径相对于 `GDD SKILL/` 子项目根目录（即与 `prompts/`、`案例/` 同级）。

---

## 1. 三类目录，不要混用

| 目录 | 角色 | 谁写 | 是否进 Git |
|------|------|------|------------|
| **`参考/`** | 策划**原始输入**（docx、会议纪要、截图说明） | 策划 | 可选（建议入库便于追溯） |
| **`templates/`** | **空模板**，新建功能时复制 | 维护者 | 是 |
| **`案例/{功能名}/`** | **功能实例**（00~04 全部产出） | 策划 + AI/程序 | 是 |
| **`outputs/{功能名}/`** | `compile.py` **编译产出** | 工具 | 是（禁止手改） |
| **`workflows/*.json`** | 项目配置（`feature_root` 指向案例） | 程序/策划 | 是 |

**铁律**

- `参考/` **不是** 01 定稿位置，只存放尚未结构化的源材料。
- 01 定稿必须在 `案例/{功能名}/01-原始策划案/{功能名}/原始策划案.md`。
- 02/03/04 必须在 `案例/{功能名}/` 下，**禁止**写到 `templates/` 或 `参考/`。

---

## 2. 路径变量（Prompt 占位符）

执行 Prompt 前统一替换：

| 占位符 | 含义 | 示例 |
|--------|------|------|
| `{功能名}` | 功能中文名，与案例子目录名一致 | `竞技场高级赛` |
| `{feature_root}` | 功能实例根目录 | `案例/竞技场高级赛` |
| `{功能缩写}` | 编号用英文缩写 | `ARENA` |
| `{skill_id}` | L1 框架 Skill id | `tournament_bracket` |

**标准阶段路径**（以下 `{功能名}` 两处必须相同）：

```text
{feature_root}/
├── 00-立项探索/{功能名}/          ← P0 可选
├── 01-原始策划案/{功能名}/
│   ├── 原始策划案.md              ← P1 定稿（P2+ 主读）
│   └── 原始策划案-草稿.md          ← P0-4 草稿
├── 02-需求拆解/{功能名}/
│   ├── 规则/
│   ├── 边界条件/
│   ├── 红点/
│   ├── 数据源/
│   ├── UI交互/
│   ├── 状态机/
│   ├── 校验规则/
│   └── 验收标准/
├── 03-功能点梳理/{功能名}/
│   ├── 0-阅读说明.md
│   ├── 字段映射.md
│   ├── 验收场景.md
│   ├── 待确认事项.md
│   └── 功能点/*.md
└── 04-待策划补充/{功能名}/
    ├── README.md
    └── 01~08-*.md
```

> **为何有两层 `{功能名}`？**  
> 外层 `案例/竞技场高级赛` 是功能包；内层 `…/01-原始策划案/竞技场高级赛/` 与 `compile.py`、`workflow.feature_root` 约定一致，便于同仓库多案例管理。

## 3. 原始策划案放哪里

```text
策划 docx / 口述
      ↓
参考/{任意文件名}.docx          ← 源文件归档（可选）
      ↓ P1-1 或 P0-4
案例/{功能名}/01-原始策划案/{功能名}/
      ├── 原始策划案-草稿.md    ← P0-4 产出，策划审阅
      └── 原始策划案.md         ← P1 定稿，P2 拆解 @ 此文件
```

| 文件 | 阶段 | 能否进 P2 |
|------|------|-----------|
| `参考/*.docx` | 输入 | 否（须先转 01） |
| `原始策划案-草稿.md` | P0-4 | 否（须 P1 定稿） |
| `原始策划案.md` | P1 定稿 | **是** |

**P2 及以后 @ 引用**：一律指向

```text
案例/{功能名}/01-原始策划案/{功能名}/原始策划案.md
```

不要 @ `参考/` 下的 docx（除非 P1-1 转换步骤中临时使用）。

## 4. 各阶段：读什么、写什么

### P0 立项探索（可选）

| 步骤 | @ 引用 | 写出路径 |
|------|--------|----------|
| P0-1 | 策划口述 / `参考/*` | `{feature_root}/00-立项探索/{功能名}/project.json` |
| P0-2 | `…/project.json` | `…/game_dna.json`、`game_dna.md` |
| P0-3 | game_dna + `skills/README.md` | `…/skill选型.md` |
| P0-4 | 上述 + L1 `design.md` | `…/玩法大纲.md`、`01-…/原始策划案-草稿.md` |

### P1 原始策划案

| 步骤 | @ 引用 | 写出路径 |
|------|--------|----------|
| P1-1 | `参考/*.docx` 或 `原始策划案-草稿.md` | `{feature_root}/01-原始策划案/{功能名}/原始策划案.md` |
| P1-2 | `原始策划案.md` | `{feature_root}/01-原始策划案/{功能名}/完整性检查-gap清单.md` |

### P2 需求拆解（8 维度）

**前置 @**：`原始策划案.md` + `workflows/*.json` + L1 Skill（如有）

| 维度 | Prompt | 输出目录 |
|------|--------|----------|
| 数据源 | P2-DS | `{feature_root}/02-需求拆解/{功能名}/数据源/` |
| 规则 | P2-R | `…/规则/` |
| 边界条件 | P2-EX | `…/边界条件/` |
| 状态机 | P2-SM | `…/状态机/` |
| UI交互 | P2-UI | `…/UI交互/` |
| 红点 | P2-RD | `…/红点/` |
| 校验规则 | P2-V | `…/校验规则/` |
| 验收标准 | P2-T | `…/验收标准/` |

**推荐顺序**：P2-DS → P2-R → P2-EX → P2-SM → P2-UI → P2-RD → P2-V → P2-T

### P3 功能点梳理

| 步骤 | @ 引用 | 写出路径 |
|------|--------|----------|
| P3-1 | 01 + 02 全目录 | `{feature_root}/03-功能点梳理/{功能名}/0-阅读说明.md` |
| P3-2 | 同上 | `…/功能点/*.md` |
| P3-3~6 | 03 已有文件 | `字段映射.md`、`验收场景.md` 等 |

**程序主读入口**：

```text
案例/{功能名}/03-功能点梳理/{功能名}/0-阅读说明.md
```

### P4~P6

| 阶段 | 主读 | 产出 |
|------|------|------|
| P4 | 01 + 02 + 03 | `{feature_root}/04-待策划补充/{功能名}/` |
| P5 | 02 + 03 + workflow | `outputs/{功能名}/程序包.md` 等 |
| P6 | 03 + `outputs/程序包.md` | server/client design 四件套（仓库外） |

## 5. 新建功能（操作步骤）

### 5.1 初始化目录

```bash
# 在 GDD SKILL/ 下执行
功能名="你的功能名"
mkdir -p "案例/${功能名}/01-原始策划案/${功能名}"
mkdir -p "案例/${功能名}/02-需求拆解/${功能名}"
mkdir -p "案例/${功能名}/03-功能点梳理/${功能名}/功能点"
mkdir -p "案例/${功能名}/04-待策划补充/${功能名}"
# 若走 P0：
mkdir -p "案例/${功能名}/00-立项探索/${功能名}"
```

或复制模板：

```bash
cp -r templates/01-原始策划案/{功能名} "案例/${功能名}/01-原始策划案/${功能名}"
# 其余阶段同理
```

### 5.2 归档策划源文件

```text
参考/你的策划案.docx   → 仅作输入，P1-1 @ 引用
```

### 5.3 创建 workflow

复制 `workflows/arena.workflow.json` → `workflows/{项目}.workflow.json`：

```json
{
  "feature_root": "案例/{功能名}",
  "selected_skills": ["resolution_standard", "interaction_feedback"],
  "skill_configs": { }
}
```

`feature_root` **必须**与 `案例/` 下文件夹名一致（不含末尾 `{功能名}` 子层）。

### 5.4 选路径

| 情况 | 路径 |
|------|------|
| 有 docx / 完整 01 | 跳过 P0 → P1-1 → P2 |
| 只有想法 | P0-1~4 → P1 定稿 → P2 |

### 5.5 编译

```bash
cd "GDD SKILL"
python tools/compile.py 案例/{功能名} --workflow workflows/{项目}.workflow.json
```

产出：`outputs/{功能名}/程序包.md | 测试包.md | 策划包.md`

## 6. Agent 使用 Prompt 的标准动作

1. 打开 `prompts/Px/` 对应 `.md`
2. 复制「提示词正文」
3. 替换 `{功能名}`、`{feature_root}`、`{功能缩写}`、`{skill_id}`
4. **@ 引用本表第 4 节所列路径**（用仓库内真实路径，不用省略号）
5. 发送 Agent；检查产出是否落在 `{feature_root}/` 下正确子目录
6. 策划确认后再进下一阶段

**示例（竞技场 · P2-R 规则）**

```text
功能名：竞技场高级赛
feature_root：案例/竞技场高级赛
功能缩写：ARENA

@ 案例/竞技场高级赛/01-原始策划案/竞技场高级赛/原始策划案.md
@ workflows/arena.workflow.json
@ skills/design/tournament_bracket/design.md
```

## 7. 常见错误

| 错误 | 正确做法 |
|------|----------|
| 把 01 写在 `参考/` | 01 定稿必须在 `案例/…/01-原始策划案/{功能名}/` |
| 02 写到 `templates/` | 只复制模板一次，产出写 `案例/` |
| 省略内层 `{功能名}` | 路径必须是 `02-需求拆解/{功能名}/规则/` |
| P2 @ docx 不转 01 | 先 P1-1 生成 `原始策划案.md` |
| 手改 `outputs/` | 改 02/03 后重新 `compile.py` |
| `feature_root` 与目录名不一致 | workflow 与 `案例/` 文件夹名对齐 |
