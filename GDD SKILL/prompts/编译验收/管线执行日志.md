# 编译验收·管线执行日志 管线执行日志

规范：`skills/pipeline/p5-compile-verify-编译验收/SKILL.md` · 库索引：[规格交付库.md](../规格交付库.md)

> **每次更新交付文档必做**（不限于跑完 编译验收/开发管线）：写入 `{feature_root}/logs/` 下**按时间命名**的新日志文件。  
> 同功能多次更新 → 多条日志，**禁止覆盖**已有 `.log.md`。

## 提示词正文（复制以下内容）

```
【规格交付 · Part 2】
将策划已定稿的 01 原始策划案转化为程序与 AI 可执行的 GDD 规格（02/03）。
不得改变策划业务意图；不得遗漏 01 内容；禁止「见原始文档」「见上文」。

工作包名称（策划案主题）：{功能名}    ← 系统/玩法/活动/流程或界面改版等；与产出目录名一致
产出目录：产出/{功能名}              （feature_root）
编号缩写：{功能缩写}                ← R-/P- 编号用；Agent 或程序填，策划可不填
玩法框架模板：{skill_id}            ← 无则留空；Agent 或程序填，策划可不填

【@ 必读输入】
- 本次实际修改过的 {feature_root} 下文件（01/02/03/04/看板/README/logs 等）
- workflows/{项目}.workflow.json（若涉及 compile）
- templates/logs/模板.log.md

【本步任务】
汇总**本次**文档变更与执行记录，**新建**时间命名的执行日志。

适用场景（均需写 log）：
- 全量或部分管线（原始策划案～开发管线）
- 仅改 02/03 某一节、04 回填回流、看板更新
- 目录清理、链接修正、规范维护
- 仅重跑 compile（仍须记录输入变更与 compile 结果）

【输出路径】
{feature_root}/logs/{YYYYMMDD}-{HHmmss}.log.md

文件名规则：
- `{YYYYMMDD}` = 执行结束日，如 20260706
- `{HHmmss}` = 执行结束时刻 24h，如 151530
- 扩展名固定 `.log.md`
- 若同秒冲突，秒数 +1 重试，仍禁止覆盖

【本步格式要求】
按 templates/logs/模板.log.md 填写：
0. **§0 本次变更（必填）**：变更文件清单 + 是否 compile
1. 执行摘要：立项探索～开发管线 每阶段 ✅ / 🟡 / ❌ / ⏸ / —（未触达标 —）
2. 阶段明细：本次实际跑过的步骤与产出路径
3. 关键产出索引（01、02/03 单文档、{feature_root}/开发文档/ 三包）
4. workflow / selected_skills / 功能缩写
5. 阻塞项与待办
6. 备注：未执行步骤、下次建议起点

【Part 2 公共铁律】
1. 日志只记录事实与路径，不写业务规则正文
2. 禁止修改 `skills/`（Skill 维护会话除外，且须在 log 标明）

【本步铁律】
- **每次**改动 feature_root 交付文档后必须**新建**一条日志
- 禁止覆盖 `logs/` 下已有 `.log.md`
- 禁止在旧 log 末尾追加
- 禁止用固定文件名（如 管线执行报告.md）替代 logs/
- 改完文档忘记写 log = 交付未完成

【完成后自检】
- [ ] 文件名是否符合 `{YYYYMMDD}-{HHmmss}.log.md`？
- [ ] §0 是否列出本次所有变更文件？
- [ ] 本次到达节点与阻塞项是否写清？
- [ ] 关键产出路径是否可点击定位？
- [ ] README「上次执行记录」是否指向本条 log（若维护 README）？

请直接写入 logs/ 下新文件，不要只输出大纲。
```

## 输入内容示例

> 说明如何填写占位符与 @ 引用。**勿与上方「提示词正文」一并复制**。路径均相对于 `GDD SKILL/` 根。

### 占位符

| 占位符 | 本例取值 |
|--------|----------|
| `{功能名}` | {你的工作包名称} |
| `{feature_root}` | `产出/{功能名}` |
| `{功能缩写}` | XXX（Agent/程序填） |
| `{skill_id}` | 有 L1 时填 id，无则留空 |
| `{项目}` | workflow 文件名不含 .json（Agent/程序填） |

