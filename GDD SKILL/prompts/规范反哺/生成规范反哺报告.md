# 规范反哺·生成规范反哺报告 生成规范反哺报告

规范：`skills/pipeline/p7-norm-feedback-规范反哺/SKILL.md` · 演进流程：[GDD-SKILL-更新规范.md](../../skills/GDD-SKILL-更新规范.md) · 库索引：[规格交付库.md](../规格交付库.md)

> **维护者专用 · 手动触发** — 不纳入 gdd-decompose。本步**只写报告**，禁止直接修改 `prompts/`、`skills/`。

## 提示词正文（复制以下内容）

```
【规范反哺 · 维护者手动】
工作包名称：{功能名}
产出目录：产出/{功能名}              （feature_root）

【@ 必读输入】
- {feature_root}/02-03需求拆解与功能点梳理/02-需求拆解.md
- {feature_root}/02-03需求拆解与功能点梳理/03-功能点梳理.md
- {feature_root}/04-待策划补充/{功能名}/（如有）
- {feature_root}/补充与修改看板.md
- {feature_root}/logs/（本次拆解相关 .log.md）
- skills/_backlog/维度Skill路线图.md
- P2-P3-待完善清单.md（对照基线）
- skills/GDD-SKILL-更新规范.md

【本步任务】
对照现有 Prompt/Skill 基线，从本功能 L2 与 logs 中**萃取可复用的规范增量**，写入规范反哺报告。
只输出**建议**与 backlog 登记草案，**不**直接改 prompts/、skills/。

【输出路径】
{feature_root}/规范反哺报告.md

【报告必须包含的章节】
1. 元信息（功能名、L2 路径、程序/策划是否认可、对照基线日期）
2. 按 P2 九维 / P3 六步 的缺口表（现象 | 根因 | L2 特例 / 可抽象）
3. 候选 Prompt 增量（改哪个 .md、加哪条铁律/自检 — 建议文案）
4. 候选 _backlog 登记（skill_id、WHEN、反模式 — 不含业务数值）
5. 候选 Skill 晋升（须双签、2+ 项目 — 勾选 S1～S7 处置表）
6. 明确「仅 L2、不进库」项
7. 与现有模板/Skill 冲突项

【铁律】
- 禁止复制 L2 业务正文、P-xx 数值、功能名进「可抽象」建议
- 同一现象未在 2+ 功能出现 → 标「仅 L2」，不建议晋升 Skill
- 报告不得自动创建或修改 skills/tech/、prompts/ 下任何文件
- 维护者确认后，另开会话按 GDD-SKILL-更新规范 S1～S7 改库

【完成后】
在报告 §7 处置表勾选；如需登记 backlog，列出拟新增 `skills/_backlog/{skill_id}.md` 文件名。

请直接写入 规范反哺报告.md，不要只输出大纲。
```
