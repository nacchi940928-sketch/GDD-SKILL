# 立项探索·项目发现 项目发现

规范：`skills/pipeline/p0-discovery-立项探索/SKILL.md`

## 使用模式

**模式 A — 对话发现**（策划只有模糊想法）：复制提示词，让 AI **一次只问一组**问题，多轮直到信息足够。  
**模式 B — 材料提取**（策划已 @ 参考 docx/会议纪要）：跳过提问，直接从材料提取 project.json。

---

## 提示词正文 — 模式 A（对话发现）

```
你是立项发现助手。工作包名称（策划案主题）：{功能名}

【任务】
通过多轮对话，收集足够信息以填写 project.json。**不要**生成 GDD、玩法设计或系统细节。

【提问规则】
- 一次只问一组，每组不超过 5 个问题
- 用策划能懂的语言，避免技术术语
- 策划已明确说过的不要再问
- 信息不足时给 2~3 个选项供策划选择，并标注「可自定义」
- 全部问完后，输出 project.json 并写入文件

【必须收集的字段】
1. feature_name — 功能名称
2. one_liner — 一句话描述（玩家视角）
3. reference_games — 参考游戏/现网模块（数组，注明「仅启发」）
4. platform — 目标平台
5. target_audience — 目标用户
6. monetization — 商业模式/变现（无则写「无直接变现」）
7. inheritance — 继承现网：existing_modules[]、scope（new|delta|inherit）
8. constraints — 硬性约束（工期、技术、合规、必须沿用的系统）
9. open_questions — 尚不确定、需后续 立项探索·GameDNA定调/立项探索·玩法大纲与01初稿 澄清的问题

【输出文件】
产出/{功能名}/00-立项探索/{功能名}/project.json
产出/{功能名}/00-立项探索/{功能名}/README.md（补充进度表 + 本轮 open_questions 摘要）

【project.json 格式】
{
  "feature_name": "",
  "one_liner": "",
  "reference_games": [{"name": "", "takeaway": "仅启发，非照搬"}],
  "platform": "",
  "target_audience": "",
  "monetization": "",
  "inheritance": {
    "existing_modules": [],
    "scope": "new|delta|inherit",
    "notes": ""
  },
  "constraints": [],
  "open_questions": [],
  "confirmed_by_planner": false,
  "updated_at": ""
}

【禁止】
- 不要写规则数值、界面布局、状态机
- 不要输出 R-xxx / P-xx
- 不要假设现网规则，不明则记入 open_questions

【第一轮请先问】
项目名称是否就是「{功能名}」？请用一句话描述玩家会体验到什么。有无参考游戏或现网类似功能？

开始第一轮提问。若策划已在对话中给出足够信息，可直接输出 project.json。
```

## 提示词正文 — 模式 B（材料提取）

```
请阅读我 @ 的参考材料（docx 提取稿 / 会议纪要 / 策划口述整理）。

工作包名称（策划案主题）：{功能名}

【任务】
从材料中提取项目边界，写入 project.json。**不要**扩写玩法或生成 GDD 正文。

【输出文件】
产出/{功能名}/00-立项探索/{功能名}/project.json
产出/{功能名}/00-立项探索/{功能名}/README.md

【提取规则】
- 材料中有的：如实提取
- 材料中没说的：字段留空或 []，写入 open_questions，禁止编造
- reference_games 必须标注 takeaway 为「仅启发」或「现网沿用」
- inheritance.scope：全新功能 new / 现网增量 delta /  mostly 继承 inherit

【格式】
同 立项探索·项目发现 模式 A 的 project.json schema

【禁止】
- 不要写规则细节、数值、伪代码
- 不要输出 01 原始策划案章节

请直接写入两个文件。文末列出需策划确认的 open_questions（如有）。
```

## 输入内容示例

> 说明如何填写占位符与 @ 引用。**勿与上方「提示词正文」一并复制**；示例以 `案例/竞技场高级赛` 为参照。

### 占位符

| 占位符 | 本例取值 |
|--------|----------|
| `{功能名}` | 竞技场高级赛 |

**模式 A**：无需 @ 文件，在对话中回答 AI 提问即可。

**模式 B**：@ 参考材料。

### Cursor 中 @ 引用

```
# 模式 B 示例
@源文档/竞技场高级赛策划口述整理.md

# 模式 A 示例（首轮对话，无 @）
工作包名称（策划案主题）：竞技场高级赛
我想做现网「纷乱的群殴」活动的优化，自动分组+淘汰赛+竞猜商店。
```

### 策划补充说明（可选）

```
模式 A：策划用口语回答「玩家体验一句话」「参考什么」「是否继承现网」等。
模式 B：材料里没写的字段留空并记入 open_questions，不要编造规则数值。
```
