```

对照检查清单，输出 gap 报告。**不要补写 01 正文。**

【输出路径】
{feature_root}/01-原始策划案/{功能名}/完整性检查-gap清单.md

【检查项】
1. 概述：玩法说明 + 设计目的 + 文档范围
2. 功能流程：主流程 + 关键子流程
3. 规则：基本 + 各子系统 + 特殊规则是否全覆盖
4. UI：每界面是否含布局、交互、状态差异、空态
5. 美术：Icon/背景/动画是否有编号或清单
6. 配置：Const + 配置表是否列出
7. 边界：继承现网 / 新增 / 改动 是否明确
8. 【待确认】项：列出所有待确认及是否阻塞 P2

【输出格式】
| 检查项 | 状态（✅/🟡/❌）| gap 描述 | 建议动作 | 阻塞级别 |
文末汇总：P0 阻塞项 / P1 建议补完项 / 可带进 P2 的待确认项

【Part 2 公共铁律】
1. 只报告 gap，不擅自扩写原始策划案
2. gap 描述要具体（缺哪一节、哪张表、哪个界面）

【完成后自检】
- [ ] 阻塞 P2 的项是否已标注 P0？
- [ ] 策划是否可据此补完 01？

请直接写入 gap清单.md，不要只输出大纲。
```
