# P1-1 Docx转原始案

规范：`skills/gdd/p1-original-gdd/SKILL.md`

## 提示词正文（复制以下内容）

```
请阅读我 @ 的策划案源文件（.docx 提取文本 / .md / 口述整理稿）。

功能名：{功能名}

你的任务：整理为规范的「原始策划案」。

【输出文件】
01-原始策划案/{功能名}/原始策划案.md

【必须包含的章节】
1. 概述（玩法说明、设计目的、文档范围）
2. 功能流程（主流程 ASCII/文字、关键子流程）
3. 规则（基本规则、各子系统规则、特殊规则）
4. UI及交互（入口、各界面：布局→交互→身份/阶段差异→空态）
5. 美术需求（Icon、背景、动画，带编号）
6. 配置结构（Const 常量、配置表清单与字段说明）

【边界标注（必须）】
在概述或独立小节标明：
- **继承现网**：{模块名} — 沿用什么、本次不改什么
- **本次新增**：…
- **本次改动**：…

【写作要求】
- 自然语言叙述，讲清楚设计意图，不强行表格化
- 保留源文件全部业务信息，禁止概括删减
- 若源文件是 docx 提取稿：保留表格内容（转为 markdown 表格）
- 不确定处标「【待确认】」，但不留空壳章节

【禁止】
- 不要输出 R-xxx / P-xx 编号（那是 P2 的工作）
- 不要写伪代码和服务端实现细节
- 不要拆成 8 维度文件夹

【完成后自检】
- 六个章节是否都有实质内容？
- 继承现网边界是否说清？

请直接写入 原始策划案.md，不要只输出大纲。
```
