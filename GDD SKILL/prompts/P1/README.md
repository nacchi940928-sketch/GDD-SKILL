# P1 提示词索引

规范：`skills/gdd/p1-original-gdd/SKILL.md`

## 定位

01 原始策划案由**策划提供**，是本工程唯一业务输入。  
P1 负责 docx 转换与完整性检查，**不从零生成玩法设计**。

## 推荐顺序

```
（可选）P0-1~P0-4 → 策划确认 01 草稿
  ↓
（可选）docx 提取 → P1-1 转原始案 → P1-2 完整性检查 → 策划确认 → P2
```

## 与 P0 的衔接

| 来源 | P1 动作 |
|------|---------|
| P0-4 产出 `案例/…/原始策划案-草稿.md` | P1-1 修订定稿为 `原始策划案.md` |
| `参考/*.docx` | P1-1 @ docx → 产出 `案例/…/原始策划案.md` |
| 仅有 P0 无 docx | P1-2 对定稿 01 做 gap 检查 |

路径详见 [使用指导.md](../../使用指导.md)。

## 与 L1 框架的关系

P1 阶段**不选 Skill**。L1 框架（如 `tournament_bracket`）在 P2 拆解时根据 workflow 引入，用于继承通用规则、减少重复劳动。
