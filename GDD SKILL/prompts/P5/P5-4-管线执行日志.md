# P5-4 管线执行日志

规范：`skills/gdd/p5-compile-verify/SKILL.md` · 库索引：[规格交付库.md](../规格交付库.md)

> **每次工作流执行结束必做**（无论是否跑完 P6）：写入 `{feature_root}/logs/` 下**按时间命名**的日志文件。  
> 同功能多次执行 → 多条日志，**禁止覆盖**已有 `.log.md`。

## 提示词正文（复制以下内容）

```
【规格交付 · Part 2】
将策划已定稿的 01 原始策划案转化为程序与 AI 可执行的 GDD 规格（02/03）。
不得改变策划业务意图；不得遗漏 01 内容；禁止「见原始文档」「见上文」。

功能名：{功能名}
feature_root：产出/{功能名}
功能缩写：{功能缩写}
L1 skill_id：{skill_id，无则留空}

【@ 必读输入】
- {feature_root}/01~04 各阶段已有产出（按本次实际执行到的阶段）
- {feature_root}/职能分轨检查报告.md（如有）
- outputs/{功能名}/编译验收报告.md、策划验收清单.md（如有）
- workflows/{项目}.workflow.json
- templates/logs/模板.log.md

【本步任务】
汇总**本次**工作流执行记录，写入时间命名的执行日志。

【输出路径】
{feature_root}/logs/{YYYYMMDD}-{HHmmss}.log.md

文件名规则：
- `{YYYYMMDD}` = 执行结束日，如 20260706
- `{HHmmss}` = 执行结束时刻 24h，如 151530
- 扩展名固定 `.log.md`
- 若同秒冲突，秒数 +1 重试，仍禁止覆盖

【本步格式要求】
按 templates/logs/模板.log.md 填写：
1. 执行摘要：P0~P6 每阶段 ✅ / 🟡 / ❌ / ⏸ / —
2. 阶段明细：本次实际跑过的 Prompt 步骤与产出路径
3. 关键产出索引（01 定稿、03 入口、outputs 三包）
4. workflow / selected_skills / 功能缩写
5. 阻塞项与待办（含 04 未填、P5 未通过项）
6. 备注：主要改动文件、未执行步骤、下次建议起点

【Part 2 公共铁律】
1. 日志只记录事实与路径，不写业务规则正文
2. 禁止修改 `skills/`

【本步铁律】
- **每次**工作流会话结束必须新建一条日志（含部分执行、重跑、增量）
- 禁止覆盖 `logs/` 下已有 `.log.md`
- 禁止用固定文件名（如 管线执行报告.md）替代 logs/

【完成后自检】
- [ ] 文件名是否符合 `{YYYYMMDD}-{HHmmss}.log.md`？
- [ ] 本次到达节点与阻塞项是否写清？
- [ ] 关键产出路径是否可点击定位？

请直接写入 logs/ 下新文件，不要只输出大纲。
```
