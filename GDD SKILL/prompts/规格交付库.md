# 规格交付 Prompt 库（Part 2）

> **工作重点**：无论哪位策划、何种风格的 01 原始策划案，经本库执行后，产出**统一规范、程序与 AI 可执行**的 02 + 03。  
> Part 1（策划辅助）见 [P0/README.md](P0/README.md)。

---

## 1. 两部分 Prompt 分工

| 部分 | 目录 | 输入 | 输出 | 角色 |
|------|------|------|------|------|
| **Part 1 策划辅助** | `P0/` | 模糊想法、口述、竞品 | 00 立项探索、01 草稿 | 帮策划**写**案 |
| **Part 2 规格交付** | `P1/` ~ `P6/` | **策划定稿 01** | 02/03/04 + 编译 + 开发管线 | 帮程序/AI**读**案 |

```text
Part 1（可选）          Part 2（核心）
P0 → 01 草稿    →    P1 定稿 → P2 拆解 → P3 功能点 → P4 补全 → P5 编译 → P6 管线
                         ↑
              策划 docx 也可直接 P1，跳过 P0
```

**Part 2 交付物**：`02-需求拆解` + `03-功能点梳理`（及填完的 `04`）→ `{feature_root}/开发文档/程序包.md`

**Prompt 与 Skill 边界**

| | Prompt（本库） | Skill（`skills/`） |
|--|----------------|-------------------|
| 内容 | 文档格式、路径、编号、铁律 | 抽象框架与横切规范 |
| 业务 | **禁止**写具体功能名词 | **禁止**写 L2 案例正文 |
| 变更 | 维护者迭代 | **须维护者确认**；AI 跑管线时不得改 Skill |

## 2. 统一输入契约（所有 Part 2 Prompt 共用）

### 2.1 占位符

| 占位符 | 含义 | 填写说明 |
|--------|------|----------|
| `{功能名}` | 功能中文名 | 与 `产出/{功能名}` 目录名一致 |
| `{feature_root}` | 案例根路径 | `产出/{功能名}` |
| `{功能缩写}` | 编号前缀 | 大写英文缩写，如 `R-{缩写}-001` |
| `{skill_id}` | L1 框架 id，无则留空 | 来自 workflow `selected_skills` |
| `{项目}` | workflow 文件名（不含 .json） | 如 `workflows/{项目}.workflow.json` |

> Prompt 正文只写**文档规范**与占位符，不写具体功能业务。具体案例见 `产出/{功能名}/`。

### 2.2 必读输入（按阶段递增）

| 阶段 | 必须 @ |
|------|--------|
| **P1** | `源文档/*.docx` 或已有 01 草稿 |
| **P2-DS**（首个） | `{feature_root}/01-…/原始策划案.md` + `workflows/{项目}.workflow.json` + L1 `meta/design/tech.md` |
| **P2 其余** | 01 + `02-需求拆解.md`（按维度依赖递增） |
| **P3** | 01 + `02-需求拆解.md` + L1 skill |
| **P4** | 01 + `02-需求拆解.md` + `03-功能点梳理.md` |
| **P5/P6** | 02 + 03 + `{feature_root}/开发文档/程序包.md` + workflow |

**01 定稿路径（唯一）**：

```text
{feature_root}/01-原始策划案/{功能名}/原始策划案.md
```

### 2.3 Part 2 公共铁律

1. **不改意图**：规格化表达，不擅自改策划业务决策
2. **不遗漏**：01 每个章节、表格、规则须在 02 或 03 有对应条目
3. **不跳转**：禁止「见原始文档」「见 02/xx」——03 必须自包含
4. **先概要后规格**：P2 写策划语言；P-xx / 伪代码 / 审计在 **P3 → 03 附录**
5. **编号唯一**：R / EX / PRE / LIM / RD / V / T / B / E / P 全局唯一
6. **标注来源**：每条标注 `来源：01 §x.x`
7. **L1 继承**：框架已有写 `继承 {skill_id} R-xxx`，只写 delta
8. **可实现**：02 写清业务；**03** 写检测位置、数据依赖、伪代码（见 [02-需求拆解-写作规范](../templates/02-需求拆解-写作规范.md)）
9. **路径固定**：产出只在 `{feature_root}/` 下，见 [使用指导.md](../使用指导.md)

## 4. Part 2 全流程（推荐顺序）

```text
P1-1  docx/草稿 → 01 定稿
P1-2  01 完整性 gap 清单（不扩写）
  ↓
P2-DS → P2-R → P2-EX → P2-SM → P2-UI → P2-RD → P2-V → P2-T
  ↓
P3-1 → P3-2（可分批）→ P3-3 → P3-4 → P3-5 → P3-6
  ↓
P4-1 → 策划回填 04 → P4-2 验收 ──┐
  ↑                              │ 未通过
  └──────────────────────────────┘
  ↓
P5-1 分轨检查 → P5-2 compile → P5-3 策划验收 → P5-4 执行日志
  ↓
P6-1 后端管线 → P6-2 前端管线 → P6-3 增量核对（可选）→ 更新 logs（新建条目）
```

### 阶段门禁（进入下一步前须满足）

| 门禁 | 条件 |
|------|------|
| P1 → P2 | `原始策划案.md` 六章节齐全；P1-2 无 P0 阻塞项 |
| P2-DS → P2-R | 02 §6 数据概要已列全表名（P-xx 在 P3 登记） |
| P2 → P3 | 02 八维度为策划可读；核心 R- 均有「规则说明」 |
| P3 → P4 | 03 单文档 + 附录 A/D；各功能点含「怎么实现」伪代码 |
| P4 → P5 | P4-2 验收通过；04 策划必填项已填 |
| P5 → P6 | compile 成功；`{feature_root}/开发文档/` 三包生成；**P5-4 已写 logs/**（**每次文档更新**均须新建，非仅 P5 全量） |

## 6. 统一 Prompt 结构（每个 Part 2 文件必含）

每个 `prompts/P1~P6/*.md` 的「提示词正文」按以下顺序组织：

```text
【规格交付 · Part 2】          ← 身份与目标（1 段）
功能名 / feature_root / 缩写 / skill_id   ← 占位符块
【@ 必读输入】                  ← 本步须 @ 的文件列表
【输出路径】                    ← 完整 {feature_root}/… 路径
【本步任务】                    ← 具体做什么
【本步格式要求】                ← 编号、表格、标准块
【Part 2 公共铁律】              ← 引用第 2.3 节（可精简复述）
【本步铁律】                    ← 本维度特有禁止项
【完成后自检】                  ← 勾选清单
请直接写入文件，不要只输出大纲。
```

公共头模板见 [_shared/Part2-公共头.md](_shared/Part2-公共头.md)。

## 7. 02 vs 03 分工（避免重复与遗漏）

| 维度 | 02 需求拆解.md | 03 功能点梳理.md |
|------|----------------|------------------|
| 读者 | **策划、运营、产品、老板** | **程序、AI 开发管线** |
| 语言 | 自然语言 | 伪代码 + P-xx + 协议 |
| 组织 | 八维度单文档 | 功能点 + 附录 A~E |
| 规则 | R-「规则说明」段落 | 「怎么实现」+ 读写表 |
| 数据 | §6 表名概要 | 附录 A/D/E |
| 引用 | 可指向 03 | **禁止**「见 02」 |

**原则**：02 **可读可评审**；03 **可独立开发**。同一规则：02 写「做什么」，03 写「怎么做」。

## 8. 不同策划案的统一化策略

| 策划案差异 | Part 2 如何处理 |
|------------|-----------------|
| 章节顺序不同 | P1-1 归并为标准六章；P3 按功能模块重排 |
| 表格 vs 叙述混用 | P2 提取为编号条目；P3 保留原表格 |
| 缺 UI / 缺配置 | P1-2 报 gap；P4 生成待补充 |
| 数值未定 | 02/03 标【待确认】+ 建议值；P4 汇总给策划 |
| 继承现网描述模糊 | P2 规则写对接点；03 写 delta；04 列 Q-xx |
| 已有 L1 框架 | workflow 选 skill；P2 只写 delta |
