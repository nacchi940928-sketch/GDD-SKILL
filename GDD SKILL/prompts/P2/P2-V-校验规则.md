# P2-V 校验规则

规范：`skills/gdd/p2-decompose/SKILL.md`

## 提示词正文（复制以下内容）

```
请阅读我 @ 的原始策划案、规则/、数据源/。

功能名：{功能名}
功能缩写：{功能缩写}

你的任务：为「{功能名}」生成 02-需求拆解 的「校验规则」维度。

【输出目录】
02-需求拆解/{功能名}/校验规则/数据校验.md
（模块多时可拆分）

【编号】
V-{功能缩写}-{序号}

【每条校验必须写全】
- 校验时机（请求入口 / 定时 / 结算）
- 校验逻辑（条件表达式或伪代码）
- 失败处理（拒绝 / 降级 / 回滚）
- 错误码（客户端映射）
- 防篡改（服务端重算 / 签名校验，如适用）
- 数据依赖 P-xx
- 来源章节

【区分】
- 校验 = 请求能不能过
- 规则 = 过了之后做什么
- 不与 规则/ 重复描述业务行为

【铁律】
- 每个写操作必须有对应校验
- 禁止「见原始文档」

【完成后自检】
- 竞猜/报名/战斗等关键写操作是否都有 V- 条目？
- 错误码是否唯一？

请直接创建/写入 markdown 文件，不要只输出大纲。
```
