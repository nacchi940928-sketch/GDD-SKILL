# P2-UI UI交互

规范：`skills/gdd/p2-decompose/SKILL.md`

## 提示词正文（复制以下内容）

```
请阅读我 @ 的原始策划案，以及 L0 skill：resolution_standard、interaction_feedback（如有）。

功能名：{功能名}

你的任务：为「{功能名}」生成 02-需求拆解 的「UI交互」维度。

【输出目录】
02-需求拆解/{功能名}/UI交互/
  ├── 界面跳转图.md          ← 必须第一个产出
  └── {界面名}.md            ← 每个主要界面一个文件

【必须先回答界面架构预设】
- 入口在哪（HUD / Tab / 弹窗）
- 主界面形态（全屏 / 抽屉 / 居中弹窗）
- 反馈层级（行内 / Toast / 叠加弹窗 / 全屏）
- 身份差异（如选手 vs 观众）如何分流

【每个界面文件必须包含】
- 入口
- 布局区域（区域名 + 职责，不写具体 px）
- 交互表：控件 | 操作 | 条件 | 结果
- 状态差异（不同身份/阶段的 UI 差异）
- 空态
- 引用：分辨率继承 resolution_standard；按钮反馈继承 interaction_feedback

【铁律】
- 禁止写业务规则伪代码（归 规则/）
- 禁止写协议字段定义（归 数据源/）
- 禁止重复定义分辨率与按钮三态
- 禁止「见原始文档」

【完成后自检】
- 界面跳转图是否覆盖所有入口与返回路径？
- 选手/观众（或同类身份）差异是否写清？

请直接创建/写入 markdown 文件，不要只输出大纲。
```
