# P2-R 规则

规范：`skills/gdd/p2-decompose/SKILL.md`

## 提示词正文（复制以下内容）

```
请阅读我 @ 的原始策划案、字段映射索引（如有），以及（如有）L1 skill 文件。

功能名：{功能名}
功能缩写：{功能缩写}（用于编号，如 ARENA）

你的任务：为「{功能名}」生成 02-需求拆解 的「规则」维度。

【输出目录】
02-需求拆解/{功能名}/规则/
（按子系统拆文件，如 报名与身份规则.md、签位规则.md）

【编号】
R-{功能缩写}-{序号}，如 R-ARENA-011
L1 已有编号（如 R-TB-001）继承时不重新编号，写「继承 tournament_bracket R-TB-001」

【每条规则必须写全】
- 编号 + 标题
- 触发条件
- 行为（执行什么）
- 检测位置（服务端/客户端/双端）
- 检测方式（定时/请求/事件）
- 数据依赖（P-xx 读写，必须引用已登记编号）
- 伪代码（可执行级别）
- 来源（01 章节）

【铁律】
- L1 基底已覆盖的规则只写 delta，其余写「继承 {skill_id}，无 delta」
- 继承现网模块：只写对接点，标注「继承现网 {模块名}」
- 禁止 UI 布局、跳转、像素（归 UI交互/）
- 禁止「见原始文档」

【完成后自检】
- 每条 R- 是否都有触发、行为、伪代码、P-xx？
- 是否重复展开了 L1 已有规则？
- 子系统是否已拆成独立文件？

请直接创建/写入 markdown 文件，不要只输出大纲。
```
