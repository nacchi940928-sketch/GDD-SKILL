# P2-SM 状态机

规范：`skills/gdd/p2-decompose/SKILL.md`

## 提示词正文（复制以下内容）

```
请阅读我 @ 的原始策划案、规则/、数据源/（如有），以及 L1 skill 文件。

功能名：{功能名}

你的任务：为「{功能名}」生成 02-需求拆解 的「状态机」维度。

【输出目录】
02-需求拆解/{功能名}/状态机/
（按实体拆分，如 活动阶段.md、对阵树节点.md）

【每个状态机文件必须包含】
1. 状态转移表：
   | 当前状态 | 触发事件 | 目标状态 | 条件 | 副作用 |
2. 服务端伪代码块（func onEvent(): ...）
3. 客户端伪代码块（若涉及 UI 门控：func isActionAllowed(): ...）

【每个状态用 V6 写法补充】（关键状态必填）
- 触发条件
- 表现
- 禁止
- 验收（自动化可检查项）

【铁律】
- 服务端权威；客户端门控必须与 phase/状态一致
- 副作用列明 Push 名称、写入 P-xx
- L1 已有状态（如 tournament_bracket 节点三态）只写 delta
- 禁止孤立状态（除初始态/终态）
- 禁止「见原始文档」

【完成后自检】
- 宏观阶段与微观节点是否分文件？
- 每条转移的副作用是否列明？

请直接创建/写入 markdown 文件，不要只输出大纲。
```
