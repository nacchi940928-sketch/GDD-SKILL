# P2-EX 边界条件

规范：`skills/gdd/p2-decompose/SKILL.md`

## 提示词正文（复制以下内容）

```
请阅读我 @ 的原始策划案、规则/（如有），以及 L1 skill 文件。

功能名：{功能名}
功能缩写：{功能缩写}

你的任务：为「{功能名}」生成 02-需求拆解 的「边界条件」维度。

【输出目录】
02-需求拆解/{功能名}/边界条件/
  ├── 异常流程.md      ← EX-{功能缩写}-{序号}
  ├── 前置条件.md      ← PRE-{功能缩写}-{序号}
  └── 限制条件.md      ← LIM-{功能缩写}-{序号}

【每条必须写全】
- 编号 + 场景描述
- 检测层（客户端预检 / 服务端权威 / 双端）
- 触发条件
- 处理逻辑（含错误码或 Tips 文案占位）
- 数据依赖 P-xx
- 来源章节

【区分】
- 前置 = 能不能参与（资格、开放时间）
- 限制 = 频率、次数、锁定（如身份整期不变）
- 异常 = 失败、超时、回滚
- 与 规则/ 不重复：规则写「怎么做」，边界写「不能做/失败了怎么办」

【铁律】
- L1 已有 EX-TB-xxx 等条目只写 delta
- 禁止「见原始文档」
- 异常场景必须有明确处理，禁止留「待定」

【完成后自检】
- 三类文件是否齐全？
- 每条是否有检测层和处理逻辑？

请直接创建/写入 markdown 文件，不要只输出大纲。
```
