## 执行顺序（固定）

```text
P2-DS（§6 数据概要）
  → P2-R（§3 业务规则）
  → P2-EX（§5 边界与异常）
  → P2-SM（§2 流程与状态）
  → P2-UI（§4 UI 与交互）
  → P2-RD（§6.1 红点，或并入 §4）
  → P2-V（可选；详细 V-xx 建议直接 P3 附录 E）
  → P2-T（§7 验收要点）
```

| 顺序 | 原因 |
|------|------|
| DS 第一 | 02 先列配置类型概要；P-xx 在 P3-3 登记 |
| R 第二 | 业务规则是其他维度基础 |
| EX / SM / UI | 流程、界面、边界 |
| T 最后 | 验收覆盖核心 R- |

每步产出**追加/改写** `02-需求拆解.md` 对应章节，**不**再创建 `02-需求拆解/{功能名}/` 子目录。
