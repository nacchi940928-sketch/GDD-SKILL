﻿# 超级鸡马

> **边界标注**：**本次新增** — 联机派对平台跳跃玩法，含匹配、布置、跑酷、结算、段位全链路。  
> 源文档：`源文档/《超级鸡马》.docx`

---

## 1. 概述

**玩法说明**：

联机多人派对平台跳跃游戏。玩家既是「关卡设计师」也是「挑战者」：每轮轮流从中央木箱抢夺道具并放置于地图网格，在确保自己能通过的前提下尽可能阻碍对手到达终点；随后进入跑酷阶段竞速通关，按生存、速度、成就等维度计分，累计至获胜分值后按总积分排名结算段位奖杯。

**设计目的**：

1. 提供轻量、高互动的派对竞技体验，强调「造关 + 闯关」双重身份。
2. 通过道具抢夺、放置策略与跑酷操作形成每轮差异化博弈。
3. 段位与奖杯体系驱动长期留存与匹配公平性。

**文档范围**：

- 单局流程：匹配 → 多轮（默认 12 轮）布置 + 跑酷 → 积分结算 → 可选 Sudden Death 加赛 → 对局结束。
- 外围：角色选择、段位奖杯、段位奖励、红点。
- 配置：常量表、道具表、积分表、段位表。
- 埋点：匹配、对局进程、道具、死亡、得分等（见 §6 埋点章节）。

**继承现网**：无（全新玩法模块）。  
**本次新增**：本玩法全部系统。  
**本次改动**：无。

## 2. 功能流程

**主流程**：

```
[主界面-开始游戏]
    → [选择角色]（仅已解锁小鸟可选）
    → [匹配]（段位优先匹配）
    → 循环 × N 轮（默认 12）：
        [布置阶段：木箱抢夺 → 道具放置]
        → [跑酷阶段：竞速 + 拾取金币 + 避陷阱]
        → [结算阶段：计分 + Too easy 判定]
    → [总分达获胜分值] → [排名结算 + 段位奖杯变动]
    → （若同分并列第一）→ [Sudden Death 加赛]
    → [返回主界面 / 再来一局]
```

**子流程**：

### 2.1 匹配

- 优先匹配同段位玩家；无合适者扩大到上下两个段位。
- 超时未匹配到，逐步放宽至「任意段位」。
- 【待确认】具体超时阈值与放宽阶梯。

### 2.2 布置阶段（每轮）

1. **道具抢夺**：地图中央刷新木箱，内含与玩家人数等量的道具；有时额外 1~2 个随机道具（概率配置）。
2. **抢夺倒计时**：木箱打开后 10 秒（常量可配）；先到先得，以客户端请求时间戳为准；超时未选者不分配道具。
3. **道具放置**：抢夺结束后开启放置倒计时 30 秒（常量可配）；摇杆吸附网格，确认键放置，不可修改；超时强制丢弃未放置道具。
4. **结束条件**：全员完成放置或放置倒计时结束。

### 2.3 跑酷阶段（每轮）

- 放置结束或全员完成后，开启游戏倒计时 30 秒（常量可配）。
- 玩家操控角色移动、跳跃、蹬墙跳、冲刺、蹲伏，避开陷阱，拾取金币，争取到达终点。
- 倒计时结束进行该回合积分结算。

### 2.4 结算与加赛

- 按生存基础分、速度分、成就分等维度计分（见积分表）。
- **Too easy**：全员存活时触发，全员不加分；部分道具出现权重百分比提升。
- 总分达到指定分值时本局结束，按总积分排名，段位表配置各排名奖励。
- **Sudden Death**：正常结算后若同分并列第一，保留当前地图与已放置道具，并列玩家纯竞速，最先到终点者获胜。

## 3. 规则

### 3.1 基本规则

| 项 | 规则 |
|----|------|
| 默认轮数 | 12 轮，可配置 |
| 角色性能 | 所有角色物理属性完全一致 |
| 玩家碰撞 | 玩家与玩家之间无物理碰撞 |
| 死亡 | 一触即死；陷阱 hitbox 接触致死部分即死亡 |
| 获胜 | 总分达到常量表配置的获胜分值 |

### 3.2 道具抢夺规则

- 木箱道具数 = 玩家人数；额外道具数量与权重在常量表配置。
- 按轮次配置不同道具权重（道具表属性）。
- 10 秒抢夺倒计时；未确认选择者不分配道具，放置阶段直接进入放置结束（无道具可放）。
- 所有玩家同时行动，先到先得，客户端请求时间戳为准。

### 3.3 道具放置规则

**物理与附着**：

| 类型 | 说明 |
|------|------|
| 需附着放置 | 须附着在其他道具上；不符合则无法放置 |
| 附着超长 | 超出被附着道具部分红色显示，放置后丢弃超出部分 |
| 受重力 | 跑酷开始时受向下重力影响 |
| 不受重力 | 跑酷开始时固定位置 |
| 附着道具 | 重力属性与附着目标相同 |
| 蜂蜜粘合 | 特殊道具可将多个道具物理链接；道具表中「无法连接」的道具可放旁边但蜂蜜不生效 |

**合法性限制**：

- 出生点与终点附近禁止放置（保护范围）。
- 不可与已放置道具重叠。
- 不可与地图原生地形重叠。
- 放置失败红色闪烁反馈。

**倒计时**：抢夺结束后立即开启 30 秒放置倒计时；超时强制丢弃未放置道具。

### 3.4 跑酷操作规则

| 操作 | 规则 |
|------|------|
| 移动 | 摇杆；基础移速 1 格/s |
| 奔跑惯性 | 有加速度与最大速度；松手保留水平动量，摩擦力衰减 |
| 基础跳跃 | 按键时长决定高度（蓄力跳跃）；不蓄力小跳；上限时长与最大高度需配置 |
| 蹬墙跳 | 紧贴垂直面按跳跃，朝墙反向跳，无次数限制 |
| 冲刺 | 消耗冲刺能量（冷却恢复）；摇杆方向冲刺一小段（仅前后）；无输入则朝角色朝向冲刺；距离与冷却需配置 |
| 蹲伏 | 缩小碰撞体高度，可穿过低矮缝隙；增加冷却时间 |

### 3.5 碰撞与陷阱

- **环境碰撞**：与地图地形碰撞。
- **陷阱碰撞**：
  - 致死部分（箭头、钉刺等）：接触即死。
  - 非致死部分（如箭杆）：不致死。
- **局内互动**：
  - **金币**：拾取后跟随玩家（头顶显示）；死亡时掉落在死亡处（悬浮、不受重力）；其他玩家可再拾取；带金币到终点才计入该玩家分数。
  - **环境陷阱**：地图原生，始终存在或周期性出现，各陷阱独立计时。

### 3.6 计分规则

| 类型 | 说明 |
|------|------|
| 生存基础分 | 到达终点即可获得 |
| 速度分 | 第一名到达终点获得 |
| 成就分 | 见 `02/…/AB2_ChickenHorseScore.md`（9 项行为+条件 ✅；**分值**待填 Q-D07） |
| Too easy | 全员到达终点 → 全员不加分；部分道具权重提升（道具表配置） |
| 总分 | 达获胜分值 P-06 → 本局结束 → 排名 → 段位奖励 |

**配置待填**：生存分 P-57、速度分 P-58（Q-D08）· 获胜分 P-06（Q-D04）· 规则边界 [04/…/09-规则边界确认.md](../../04-待策划补充/超级鸡马/09-规则边界确认.md)（Q-R01）

### 3.7 段位规则

- 奖杯积累提升段位；升段自动领取对应奖励（段位表 AB2_ChickenHorseLv）。
- 奖杯扣除会掉段；掉段后奖励不可重复领取（已领取灰置）。
- 段位每周重置。

### 3.8 Sudden Death 加赛

- 触发：正常积分结算后同分并列第一。
- 规则：保留当前地图与全部已放置道具；并列玩家纯竞速；最先到终点者直接最终胜利，其他玩家不再计分。

## 4. UI及交互

### 4.1 入口

- **主界面**：「开始游戏」入口进入玩法；首次进入前显示红点（见 §5 红点）。

### 4.2 选择角色界面

- 展示所有角色；仅可选择已解锁小鸟。
- 新解锁小鸟卡牌右上角红点；浏览该小鸟后消失。

### 4.3 匹配界面

- 搜索中状态展示；【待确认】取消匹配、预估等待 UI。

### 4.4 布置阶段 UI

- 中央木箱刷新与打开动画。
- 抢夺倒计时 10 秒展示。
- 道具选择/确认（先到先得反馈）。
- 放置阶段：摇杆控制道具吸附网格；确认键放置；非法放置红色闪烁。
- 放置倒计时 30 秒。

### 4.5 跑酷阶段 UI

- 游戏倒计时 30 秒。
- 角色头顶金币跟随显示。
- 死亡：灰色遮罩。
- 【待确认】小地图、排名实时展示。

### 4.6 结算界面

- 单轮得分明细：生存分、速度分、成就分。
- Too easy 提示。
- 对局结束：总积分排名、段位奖杯变动、段位奖励领取入口。

### 4.7 段位奖励

- 段位进度条；可领取奖励时右上角红点；领取后消失。

### 4.8 空态与异常

- 匹配超时：放宽段位继续搜索。【待确认】最终失败提示。
- 无道具可放：抢夺未选或超时 → 放置阶段跳过。

## 1. 功能概述

**玩法说明**：

联机多人派对平台跳跃游戏。玩家既是「关卡设计师」也是「挑战者」：每轮轮流从中央木箱抢夺道具并放置于地图网格，在确保自己能通过的前提下尽可能阻碍对手到达终点；随后进入跑酷阶段竞速通关，按生存、速度、成就等维度计分，累计至获胜分值后按总积分排名结算段位奖杯。

**设计目的**：

1. 提供轻量、高互动的派对竞技体验，强调「造关 + 闯关」双重身份。
2. 通过道具抢夺、放置策略与跑酷操作形成每轮差异化博弈。
3. 段位与奖杯体系驱动长期留存与匹配公平性。

**文档范围**：

- 单局流程：匹配 → 多轮（默认 12 轮）布置 + 跑酷 → 积分结算 → 可选 Sudden Death 加赛 → 对局结束。
- 外围：角色选择、段位奖杯、段位奖励、红点。
- 配置：常量表、道具表、积分表、段位表。
- 埋点：匹配、对局进程、道具、死亡、得分等（见 §6 埋点章节）。

**继承现网**：无（全新玩法模块）。  
**本次新增**：本玩法全部系统。  
**本次改动**：无。

## 2. 流程与状态

### 2.1 玩家经历的单局流程

1. **选角与匹配**：从主界面进入玩法 → 选择已解锁小鸟 → 系统匹配对手（优先同段位，过久则放宽）。
2. **多轮循环**（默认 12 轮）：每轮 = **布置** + **跑酷** + **小结算**。
3. **布置阶段**：
   - **抢夺**（约 10 秒）：木箱刷新，先到先得选一件道具；
   - **放置**（约 30 秒）：放到地图网格，须保证自己能通过，确认后不可改。
4. **跑酷阶段**（约 30 秒）：冲向终点；可被陷阱击杀、拾取金币、按到达先后影响得分。
5. **小结算**：累加生存/速度/成就分；全员都到终点则 **Too easy**（本轮回合 0 分并加重部分道具权重）。
6. **对局结算**：有人达到获胜分或 12 轮结束 → 排名与奖杯；并列第一则 **Sudden Death** 加赛。
7. **外围**：段位奖励领取、红点提示等。

### 2.2 单轮顺序

抢夺道具 → 放置道具 → 跑酷闯关 → 单轮计分 →（对局未结束）下一轮。

## R-CHH-001 段位优先匹配

**规则说明**：玩家确认角色并点击匹配后，系统优先将玩家放入**同段位**的匹配队列并开始计时。同段位内凑够人数即组局；若等待过久则进入放宽规则（见 R-CHH-002）。

**来源**：01 §2.1

## R-CHH-002 匹配放宽与成功

**规则说明**：匹配过程中，若同段位等待超过一定时间仍凑不齐人，系统逐步**放宽段位范围**（先 ±1 段，再任意段位），直到满足房间人数并成功组局。组局成功后所有玩家进入对局并加载地图。【待确认】各档放宽的等待秒数、房间人数上下限。

**来源**：01 §2.1

**规则说明**：每轮布置阶段开始时，中央木箱刷新一批道具：数量与在场玩家数相关，并按配置权重随机；另有概率额外刷新 0~2 个道具。木箱打开后进入抢夺阶段。

## R-CHH-011 道具抢夺（先到先得）

**规则说明**：抢夺阶段约 10 秒内，玩家从木箱中**先到先得**选取一件道具；已被他人选走的不可再选。超时未选则本轮回合无道具可放置。全部玩家选定或倒计时结束后进入放置阶段。

**来源**：01 §3.2

**规则说明**：放置阶段约 30 秒。玩家确认放置后不可更改；倒计时结束或全员确认后，未确认的玩家若有已选道具则**丢弃**，随后进入跑酷阶段。

**规则说明**：放置时需满足：不落在出生/终点保护区内、不与已有道具非法重叠、附着类道具需合法依附。不合法时客户端提示并拒绝，服务端为最终裁判。

**来源**：01 §3.3

## R-CHH-025 跑酷倒计时结束

## R-CHH-030 单轮积分结算

**规则说明**：每轮结算生存分、速度分（先到达者）、成就分等；若**全员**均到达终点，则本轮回合判定为 **Too easy**：全员本轮回合得 0 分，并提高部分道具在后续轮次的出现权重。

## L1 resolution_standard / tech

# 分辨率与适配 — 技术规范（L0 横切）

## 规范目标

全项目**唯一**画布与适配策略，防止多引擎/AI 实现乱拉伸、刘海遮挡、长屏错位。

## 设计稿 vs 实机

| 层 | 是否固定 9:20 |
|----|----------------|
| 设计稿 / 出图坐标 | ✅ 固定 `reference_resolution`（默认 1080×2340） |
| 实机屏幕 | ❌ 不固定 |

**核心**：固定 9:20 画布完整显示；更长屏宽度顶满、上下纯黑；更宽扁屏高度顶满、左右纯黑。

## 缩放模式（scale_mode）

| 模式 | 计算 | 适用 |
|------|------|------|
| **fit（默认）** | `scale = min(屏宽/1080, 屏高/2340)` | 固定画布，留纯黑边 |
| match_width | `scale = 屏宽/设计宽` | 备选 |
| match_height | `scale = 屏高/设计高` | 备选 |

X/Y **必须用同一 scale**，禁止 `scaleX ≠ scaleY`。

## 画布内布局（layout_anchor_policy）

默认 **stretch_center**：HUD 贴顶、Tab 贴底、中间 Fill。**不**向实机黑边区延伸。

| UI 区域 | 实机行为 |
|---------|----------|
| 顶部 HUD | 随画布 scale，不拉高 |
| 底部 Tab | 随画布 scale，不拉高 |
| 主玩法/列表 | 在 2340 内分配 |
| 居中弹窗 | 画布内居中，尺寸随 scale |
| 黑边区 | 纯黑、不可点 |

## 双层结构

- **背景层**：可铺满物理屏
- **交互层**：必须在 SafeArea 内

## 禁止

- 实机长屏中间向下延伸玩法区
- 4:3 挤扁中间不留黑边
- 黑边区放可点击按钮
- 非等比拉伸

## 验收标准

- [ ] 所有 UI 按设计坐标 1080×2340 出稿
- [ ] fit 模式下黑边不可点击
- [ ] 各系统 ux.md 不重复定义分辨率，只引用本文

# 交互反馈 — UX 规范（L0 横切）

## 规范目标

统一全项目交互反馈层级与状态机写法，支撑 AI 生成 UI 与自动化检查。

## 界面架构预设

反馈层级（全项目通用）：

| 层级 | 用途 | 示例 |
|------|------|------|
| 行内 | 即时、不打断 | 置灰、Tips、角标 |
| Toast | 轻量结果 | 操作成功/失败 |
| 叠加弹窗 | 需确认 | 高风险操作二次确认 |
| 全屏 | 强打断 | 奖励展示、断线重连 |

## 状态机 — 按钮

### Normal

**表现**：可点击，100% 缩放  
**验收**：pointer-events 启用

### Pressed

**触发**：pointer down  
**表现**：缩放至 `button_pressed_scale`（默认 95%）  
**禁止**：触发业务逻辑（等 release）

### Disabled

**触发**：业务条件不满足  
**表现**：透明度 50%  
**禁止**：
- 播放 Pressed 反馈
- 触发业务逻辑

**验收**：`opacity == 0.5 && pointer-events == none`

## 交互规则

- 防连点：`click_lock_ms` 内忽略重复点击
- Toast：默认 `toast_duration_ms`，可队列不叠加（项目可 override）
- 错误：行内优先，严重错误用 Toast

## 表现规则

- 奖励获得：全屏或大型叠加弹窗（由业务 Skill 引用，不重复定义 Pressed 规则）
- 网络错误：Toast + 可重试

## 验收标准

- [ ] Disabled 不响应点击且无 Pressed 动画
- [ ] 业务界面不重复定义按钮三态
