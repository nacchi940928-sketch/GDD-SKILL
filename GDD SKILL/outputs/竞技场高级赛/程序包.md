## 名词定义

| 名词 | 含义 |
|------|------|
| 周练组 | 竞技场周练排行榜上的一个小组，格式「XX赛区·第N组」 |
| 赛区（锦标赛） | 同一联赛+档位下的4个周练组合并为一个锦标赛赛区 |
| 小组排名 | 该玩家在本周练组内的名次（1起） |
| A/B/C/D组 | 赛区内4个周练组的代号；Ax=A组第x名 |
| 选手/观众 | 组内1–4名=选手；5名及以后=观众 |
| 轮次 | 16进8→8进4→半决赛→决赛，共4轮 |

## 七日活动日程

| 日期 | 阶段名 | 选手 | 观众 | 竞猜积分 |
|------|--------|------|------|----------|
| 第1天 | 公示 | 查看身份/对阵预览；不可战斗 | 查看身份/对阵；不可竞猜 | — |
| 第2天 | 十六进八 | 战斗日 | 开放竞猜（本轮） | UTC0发200 |
| 第3天 | 八进四 | 战斗日 | 开放竞猜（本轮） | UTC0发200 |
| 第4天 | 半决赛 | 战斗日 | 开放竞猜（本轮） | UTC0发200 |
| 第5天 | 决赛 | 战斗日 | 开放竞猜（本轮） | UTC0发200 |
| 第6–7天 | 结算 | 发放战斗/锦标赛奖励；积分1:1转竞猜币；积分清零 | 同左 | 不再发放 |

## 选手 vs 观众 全局行为矩阵

| 维度 | 选手（组内1–4名） | 观众（组内5名+） |
|------|-------------------|------------------|
| 资格来源 | 前一周周练组榜1–4；周一UTC0自动确定；无主动报名 | 前一周周练组榜5+ |
| 第1天（公示） | 可查看身份与对阵预览；不可开打 | 可查看身份与对阵；不可竞猜 |
| 【前往】 | 进入决斗界面 | 进入对阵树界面 |
| 对阵树顶栏 | 奖励统计：钻石+五档进度(P-28) | 竞猜引导文案 |
| 对阵树「你的决斗」Tab | 可切换使用 | 点击弹出Tips：无决斗信息 |
| 决斗界面 | 可进入；进行中可见双方战斗积分 | 不可进入 |
| 战斗积分可见性 | 决斗进行中：双方积分可见 | 结算前不可见；结算后通过战报查看 |

# 4.2 十六强签位表（固定，不可随机）

4.2 十六强签位表（固定，不可随机）

第一轮（16进8）8 场对阵——签位固定如下：


| 场次 | 左位 | 右位 | 说明 |
| M1 | A1 | B4 | 种子保护：1 vs 4 |
| M2 | B2 | C3 | 交叉 |
| M3 | B1 | C4 | 种子保护 |
| M4 | C2 | D3 | 交叉 |
| M5 | C1 | D4 | 种子保护 |
| M6 | D2 | A3 | 交叉 |
| M7 | D1 | A4 | 种子保护 |
| M8 | A2 | B3 | 交叉 |

同组规避：M1–M8 中无同周练组内战（A 与 A 不直接对阵，B 与 B 不直接对阵…）。

种子保护：每组第 1 名（x1）对阵其他组第 4 名（y4）。

第二轮（8进4）——胜者按固定半区衔接：


| 场次 | 对阵 |
| QF1 | Winner(M1) vs Winner(M2) |
| QF2 | Winner(M3) vs Winner(M4) |
| QF3 | Winner(M5) vs Winner(M6) |
| QF4 | Winner(M7) vs Winner(M8) |

第三轮（4进2 半决赛）：


| 场次 | 对阵 |
| SF1 | Winner(QF1) vs Winner(QF2) |
| SF2 | Winner(QF3) vs Winner(QF4) |

第四轮（决赛）：


| 场次 | 对阵 |
| F1 | Winner(SF1) vs Winner(SF2) → 冠军 |


| flowchart LR  subgraph R1[16进8]    A1 --- B4    B2 --- C3    B1 --- C4    C2 --- D3    C1 --- D4    D2 --- A3    D1 --- A4    A2 --- B3  end  R1 --> R2[8进4]  R2 --> R3[4进2]  R3 --> F[决赛] |

# 4.3 对阵树数据结构（建议）

4.3 对阵树数据结构（建议）

每个赛区一棵树，节点字段【待程序补充】至少包含：


| 字段（业务） | 说明 |
| round | 1=16进8, 2=8进4, 3=半决赛, 4=决赛 |
| matchIndex | 该轮场次序号 |
| slotLeft / slotRight | 选手 ID 或机器人 ID |
| winnerId | 胜方 |
| status | 未开始 / 进行中 / 已结束 |
| isRobot | 是否机器人 |
| displayScore | 展示用结算分 |

填充顺序：按上表 M1→M8 顺序写入叶子节点；胜者向父节点推进。

# 6.2 竞猜币

6.2 竞猜币


| 项 | 规则 |
| 用途 | 锦标赛商店兑换 |
| 来源 | 仅积分转化 |
| 保留 | 永久，不随期清零 |
| 转化 | 第 6 天（结算阶段）：持有积分 1:1 → 竞猜币（P-20 可配）；积分清零 |
| 动画 | 全部比赛结束后首次进界面播放；当期未登录则下期不补播 |

功能点

发放时点与「七日活动日程表」一致：第 2–5 天每日 UTC0 各发 200；第 1 天不发；第 6–7 天不再发

转化时点：第 6 天（结算阶段）积分 1:1 转竞猜币；转化后积分余额必为 0

竞猜积分信息栏（icon + 数量）在以下界面样式与数据一致：对阵树、决斗、战报弹窗、竞猜主/押注/记录、锦标赛商店

离线玩家轮次到点仍发放；多轮未登录后只弹一次发放动画

转化动画：全部比赛结束后首次进界面播放；当期未登录则下期不补播

数据来源


| 读写 | 业务数据 | 程序字段 | 用途 |
| 读/写 | 当期竞猜积分 | P-16 | 押注、信息栏 |
| 读 | 累计获得（展示） | P-17 | 发放动画 |
| 读/写 | 竞猜币 | P-21 | 商店 |
| 读 | 发放额 / 轮次 | P-18、P-19 | 配表 |
| 读 | 转化比例 | P-20 | 第 6 天 |

怎么实现

通用规则

每期开始（周一 UTC0 新一期）服务端清零 P-16；P-21 永久保留。

第 2–5 天每日 UTC0 服务端增加 P-18（默认 200）；客户端首次进活动弹动画并展示 P-17。

第 6 天结算：剩余 P-16 按 P-20（默认 1:1）转入 P-21，积分必清零。

在「信息栏」上

上述 7 类界面共用同一组件：读 P-16，样式一致，只读不可点（押注在竞猜弹窗改余额）。

押注成功、结算、转化后推送或下次拉取刷新数量。

在「动画」上

发放：每轮首次进活动界面触发；离线累积多轮仍只播一次。

转化：决赛结束后的结算阶段，首次进界面触发；跨期不补播。

# 周练定组规则

> 废除旧「同组最大鸟力差≤20%」算法，改用头部轮询+余席填充。
> **仅服务端计算**，客户端只读 P-03 展示结果。

---

## R-001 废除旧算法

**检测位置**: 服务端定组任务入口（每周定时触发）

**检测方式**: 切换为新算法实现，不再执行旧算法的鸟力差计算逻辑。旧代码分支标记为废弃（保留但不调用）。

**数据**: 无需读旧算法的鸟力差阈值配置。

---

## R-002 鸟力降序排序

**触发**: 服务端每周定组任务启动。

**检测方式**: 
1. 查询本周需分组的所有玩家，取每人的鸟力值（字段 `【待程序补充】`）
2. 按鸟力降序排列，编号 1..N
3. 当周小组数 G 由当前已开启的小组数决定（从 P-03 统计）

**数据**:
| 读/写 | 数据 | 说明 |
|--------|------|------|
| 读 | 玩家鸟力 | `【待程序补充】` |
| 读 | 当前已开启小组数 G | 从 P-03 已存在的组名统计 |

---

## R-003 头部轮询

**触发**: 排序完成后。

**检测方式**:
```
for i in 1..G:
    玩家[i] → 第 i 组
```
排名第 1 的玩家入第 1 组，第 2 入第 2 组…第 G 入第 G 组。每组此时各占 1 个头部席位。

**目的**: 保证头部玩家均匀分布在各组，避免强强集中。

**算例（G=3）**: 排名1→组1, 排名2→组2, 排名3→组3

---

## R-004 余席顺序填充

**触发**: 头部轮询完成（G 个玩家已分配）。

**检测方式**:
```
for i in G+1..N:
    target_group = ((i - G - 1) % G) + 1  // 循环 1,2,3,...,G,1,2,3,...
    if 组[target_group].人数 < 20:
        玩家[i] → 组[target_group]
    else:
        跳过该组 // 该组已满
```
从第 G+1 名起，按名次依次循环填入各组。组满 20 人则跳过。

**算例（G=3）**: 
| 排名 | 入组 |
|------|------|
| 4 | 组1 |
| 5 | 组2 |
| 6 | 组3 |
| 7 | 组1（循环） |

---

## R-005 组人数上限

**检测位置**: 每次填充时判断。

**检测方式**:
```
if 组[k].当前人数 >= 20:
    跳过该组，尝试下一组
```
服务端在填充循环中维护每组当前人数计数器。满 20 人的组不参与后续填充。

---

## R-006 末组可不足 20 人

**触发**: 待分配池为空（所有玩家已分配）时停止。

**检测方式**:
```
if 已分配玩家数 == N:
    停止定组
```
不强制要求每组恰好 20 人。最后一组可能不足 20，这是正常状态。

---

## R-007 组名格式固定

**触发**: 定组完成后写入。

**检测方式**:
```
P-03 = f"{联赛/赛区名} · 第 {k} 组"
```
组名写入 P-03，本周内不再变更。下周一重新定组时覆盖。

---

## R-008 客户端只读

**客户端职责**: 
- 进入周练排行榜时拉取 P-03 展示组名
- **不参与**分组计算
- **不本地缓存**分组逻辑

**服务端职责**:
- 所有分组计算
- 写入 P-03 + P-06
- 定组完成后通知客户端刷新（可选：拉取或推送）

# 签位与竞猜规则

## 16强固定签位

### R-020 组代号映射

```
A/B/C/D = 赛区内第1/2/3/4个周练组
Ax = A组排名第x的玩家（x=1..4=选手）
```

### R-021 固定签位表 — 服务端填充逻辑

```
叶子节点[8]:
  M1: left=A1, right=B4   // 种子保护: A组第1 vs B组第4
  M2: left=B2, right=C3   // 交叉
  M3: left=B1, right=C4
  M4: left=C2, right=D3
  M5: left=C1, right=D4
  M6: left=D2, right=A3
  M7: left=D1, right=A4
  M8: left=A2, right=B3
```

### R-022 同组规避验证

```
for m in [M1..M8]:
    assert getGroup(m.left) != getGroup(m.right)
    leftRank = getRank(m.left); rightRank = getRank(m.right)
    // 种子保护: 1号位对阵的是其他组的4号位
    assert (leftRank==1 implies rightRank==4) or (rightRank==1 implies leftRank==4)
```

### R-023 四轮淘汰推进

```
QF(8进4): QF1=W(M1)vsW(M2), QF2=W(M3)vsW(M4), QF3=W(M5)vsW(M6), QF4=W(M7)vsW(M8)
SF(4进2): SF1=W(QF1)vsW(QF2), SF2=W(QF3)vsW(QF4)
 F(决赛):  F1=W(SF1)vsW(SF2) → 冠军
```
服务端每场结束 → 胜者ID写入父节点 `parentMatchId` → 推进状态。

### R-024 机器人补位

```
if 赛区实际选手数 < 16:
    robotCount = 16 - 实际选手数
    生成机器人（isRobot=true, 头像统一, 展示鸟力随机, 展示分=真人最低分×20%-30%随机）
    填充空缺叶子节点
```
机器人不参与真实战斗。机器人vs真人→真人自动胜出。机器人vs机器人→随机一方高积分晋级。

### R-025 对战继承

沿用现网「纷乱的群殴」：异步对战，单局无尽模式最高分。决斗/晋级/奖励逻辑不变，只改签位来源+机器人+竞猜/商店。

## 竞猜规则

### R-030 参与资格

```
if player.tournament_id == 当前赛区ID:
    可参与竞猜  // 80人均可
```

### R-031 每轮限制 — 押注接口校验

```
押注校验:
  if phase not in [BATTLE_16, BATTLE_8, BATTLE_4, BATTLE_FINAL]: reject  // 非战斗日
  if P-27[该轮] 已存在: reject  // 每轮仅1次

  if targetPlayerId not in [match.left, match.right]: reject  // 只能选对战双方

```
if bet.target == match.winner:
    P-16 += bet.amount * 2; bet.result = WIN
else:
    bet.result = LOSE  // 不返还
```

客户端: `if phase==ANNOUNCE: 竞猜入口置灰/隐藏`。服务端: `if phase==ANNOUNCE: return ERR_BET_CLOSED`。

# 对阵树节点状态机

> 每个 BracketNode（15个节点）独立维护状态。状态驱动客户端渲染和按钮显隐。

---

## 状态转移表

| 当前状态 | 触发事件 | 目标状态 | 条件 | 副作用 |
|----------|----------|----------|------|--------|
| PENDING | 轮次到达（phase切换到该轮） | IN_PROGRESS | 当前轮次 == node.round | 节点显示「竞猜」按钮；BracketUpdatePush(status=IN_PROGRESS) |
| PENDING | 玩家对该场押注成功 | PENDING | P-27写入 | 头像显示「已下注」标签；**隐藏该轮所有竞猜按钮**（不仅是此节点） |
| IN_PROGRESS | 战斗结束（胜者产生） | COMPLETED | winnerId != 0 | 胜者写入父节点 slotLeft/slotRight；竞猜结算触发；BracketUpdatePush(status=COMPLETED, winner_id, scores) |
| COMPLETED | — | — | 终态 | 显示「战报」入口（播放icon）；不再显示竞猜按钮 |

---

## 节点数据 (P-10 BracketNode)

```
{
  matchId: int,
  round: int,        // 1=R16, 2=QF, 3=SF, 4=FINAL
  matchIndex: int,   // 该轮场次序号
  slotLeft: int,     // 左位选手/机器人ID
  slotRight: int,
  winnerId: int,     // 0=未定
  status: enum,      // PENDING | IN_PROGRESS | COMPLETED
  isRobotLeft: bool,
  isRobotRight: bool,
  scoreLeft: int,    // 展示分（结算后）
  scoreRight: int,

    switch phase:

# 数据校验规则

> **铁律**: 服务端权威校验，客户端仅做预校验提升体验。每条标注校验层、校验时机、错误码。

---

## V-001 战斗请求 — 非公示期

**校验**: `assert phase != ANNOUNCE`

**层**: 客户端（置灰）+ 服务端（拒绝）

**客户端**: `if phase == ANNOUNCE: 战斗按钮.enabled = false`

**服务端**: `if phase == ANNOUNCE: return ERR_BATTLE_LOCKED`

---

## V-002 战斗请求 — 选手身份

**校验**: `assert P-07 == PLAYER`

**层**: 客户端（路由守卫）+ 服务端（接口校验）

**客户端**: `if P-07 == AUDIENCE && route == "/duel": redirect("/bracket") + toast`

**服务端**: `if P-07 != PLAYER: return ERR_NOT_PLAYER`

---

## V-003 竞猜押注 — 在竞猜窗口内

**校验**: `assert phase in [BATTLE_16, BATTLE_8, BATTLE_4, BATTLE_FINAL]`

**层**: 服务端

**服务端**: `if phase not in BATTLE_PHASES: return ERR_BET_CLOSED`

**附加**: `assert now_utc < 该轮截止UTC0`

---

## V-004 竞猜押注 — 本轮未押注

**校验**: `assert P-27[match.round] == null`

**层**: 客户端（隐藏按钮）+ 服务端（拒绝）

**客户端**: `if P-27[match.round]: 隐藏该轮所有竞猜按钮`

**服务端**: `if P-27[match.round] exists: return ERR_ALREADY_BET`

---

## V-005 竞猜押注 — 押注额合法

**校验**: `assert 1 <= amount <= P-16`

**层**: 客户端（滑条限制）+ 服务端（拒绝）

**客户端**: 滑条 `min=1, max=P-16`；微调按钮到达边界置灰

**服务端**: `if amount < 1 or amount > P-16: return ERR_INSUFFICIENT_POINTS`

---

## V-006 商店购买 — 余额充足

**校验**: `assert P-21 >= item.price`

**层**: 客户端（按钮置灰）+ 服务端（拒绝）

**客户端**: `if P-21 < item.price: 购买按钮.enabled = false`

**服务端**: `if P-21 < item.price: return ERR_INSUFFICIENT_COINS`

**附加校验**: `assert purchase_count < item.limit`（限购检查，-1=无限）

---

## V-007 决斗进入 — 仅选手

**校验**: `assert P-07 == PLAYER`

**层**: 客户端路由守卫

**客户端**: 观众尝试通过URL直接进入决斗界面 → 路由拦截 → 重定向到对阵树

---

## 防篡改设计

所有数值校验（积分、次数、余额）以服务端存储为权威数据源。客户端缓存仅用于UI展示和预校验，不可作为业务逻辑依据。服务端在每次写操作前重新从数据库读取当前值进行校验。
