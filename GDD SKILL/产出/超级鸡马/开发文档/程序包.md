## 1. 选角与匹配

### 涉及界面 / 系统模块

| 模块 | 类型 | 说明 |
|------|------|------|
| 角色选择 UI | 新增 | 展示全部小鸟，仅可选已解锁 |
| 匹配服务 | 新增 | 段位池、放宽、组局 |
| 主界面入口 | 新增 | 开始游戏 → 选角 → 匹配 |

### 功能点

玩家从主界面进入「超级鸡马」：先在**选择角色界面**浏览所有小鸟卡牌，仅 **P-10 已解锁** 的可选中为 **P-11**；未解锁灰置不可选。确认后发起 **【待 Q-P01：发起匹配请求】**，进入匹配阶段。

**匹配规则**：
1. 优先 **P-14=0** 同段位池匹配；
2. 超时扩大到 **±1 段位**（P-14=1）；
3. 再超时扩大到 **任意段位**（P-14=2）；
4. 组局成功下发 **【待 Q-P02：组局成功通知】**，携带 **P-15** 对局 id、**P-16** 玩家列表、**P-18** 地图 id。

玩家可 **【待 Q-P01：取消匹配请求】** 取消匹配，上报 **match_cancel**（取消时匹配耗时 = now - P-13）。

【待确认】T1/T2 放宽时间、房间人数上下限、匹配最终失败 UI。

### 数据来源

| P-xx | 用途 | 读/写 |
|------|------|-------|
| P-07 | 段位 | 读 |
| P-08 | MMR | 读 |
| P-10 | 已解锁小鸟 | 读 |
| P-11 | 本局选中鸟 | 读写 |
| P-12~P-14 | 匹配池状态 | 服务端 |
| P-15~P-18 | 对局初始化 | 写 |

### 怎么实现

### 通用
- 选角页加载 P-10，新解锁鸟触发 RD-CHH-002（红点-选角-小鸟卡牌右上角）。

### 服务端
```
on 【待 Q-P01：发起匹配请求】:
  V-CHH-001（匹配：已解锁角色、无进行中局） 校验 P-11 ∈ P-10
  P-13 = now(), P-14 = 0
  enqueue(pool[P-07])
  loop R-CHH-002（匹配放宽与成功） 直到成功或取消

on 【待 Q-P01：取消匹配请求】:
  dequeue, match_cancel 埋点
```

### 客户端
- 选角 UI：卡牌列表、确认按钮；
- 匹配 UI：搜索动画、取消按钮；
- 【待 Q-P02：组局成功通知】 → 加载对局场景 P-18。

| 服务端 | 匹配池、组局、协议 | P-45（Q-P16） |

## 2. 对局状态与轮次

### 涉及界面 / 系统模块

| 模块 | 类型 | 说明 |
|------|------|------|
| 对局状态机 | 新增 | P-17 Phase 权威 |
| 轮次控制 | 新增 | P-01/P-02 |
| 阶段同步 | 新增 | 【待 Q-P19：阶段切换通知】 |

### 功能点

对局由服务端维护 **P-17 Phase** 与 **P-02**（当前轮次，1~**P-01**，默认 12 轮）。

阶段顺序：
```
MATCHING → CRATE_GRAB → PROP_PLACE → RUN → ROUND_SETTLE
  → (P-02++ 若继续) → CRATE_GRAB …
  → MATCH_SETTLE → (可选 SUDDEN_DEATH) → END
```

每次阶段切换广播 **【待 Q-P19：阶段切换通知】**，携带倒计时剩余（P-03/P-04/P-05 视阶段而定）。

**布置阶段结束**：全员 P-32 或 P-04 到 → 未放置者丢弃道具 → RUN。  
**跑酷结束**：P-05 到或逻辑结束 → ROUND_SETTLE。

| P-15~P-17 | 对局/阶段 | 读写 |
| P-03~P-05 | 各阶段倒计时 | 读 |

### 怎么实现

- 定时器驱动 P-03/P-04/P-05；

### 客户端

## 3. 木箱与道具抢夺

### 涉及界面 / 系统模块

| 模块 | 类型 | 说明 |
|------|------|------|
| 木箱刷新 | 新增 | 每轮中央刷新 |
| 抢夺 UI | 新增 | 10s 倒计时、道具列表 |
| 抢夺仲裁 | 新增 | 先到先得 |

### 功能点

每轮 **P-02** 开始时，地图中央刷新**木箱**：
- 基础道具数 = 玩家人数，从 **道具表（Q-P14）** 按 **P-30**（轮次权重）随机 **P-26**；
- 额外 **0~2** 个道具按 **P-31** 权重抽取；
- 结果写入 **P-19**，**P-20**=打开时间戳，**P-17**=CRATE_GRAB。

**抢夺阶段（P-03=10 秒）**：
- 所有玩家同时行动，点击确认道具 → **【待 Q-P04：抢夺道具请求】(P-26, P-22)**；
- 服务端按 **P-22** 时间戳先到先得；成功则 **P-21**=该道具，从 P-19 移除；
- **P-03** 结束后未确认者 **P-21** 为空，本轮回合无道具可放置。

| P-03 | 抢夺时长 | 读 |
| P-19~P-22 | 木箱与选择 | 读写 |
| P-26~P-31 | 道具配置 | 读 |

  V-CHH-002（抢夺：阶段正确、未超时、道具可抢）

### 客户端

## 4. 道具放置

### 涉及界面 / 系统模块

| 模块 | 类型 | 说明 |
|------|------|------|
| 放置预览 | 新增 | 网格吸附、附着、超长红区 |
| 放置校验 | 新增 | 服务端权威 |
| 物理配置 | 新增 | 重力/附着/蜂蜜 |

### 功能点

抢夺结束后立即开启 **P-04=30 秒** 放置倒计时，**P-17**=PROP_PLACE。

获得 **P-21** 的玩家须在限时内放置：
1. **摇杆**移动预览，道具**吸附网格**；
2. **确认键**发送 **【待 Q-P05：放置道具请求】(P-24, P-25)**；
3. **不可修改**已确认位置。

**合法性**（失败则红色闪烁，客户端可预校验）：
- 不在出生/终点保护区（**P-47、P-48**）；
- 不与 **P-23** 已有道具重叠；
- 不与地图地形重叠；
- **P-28** 需附着时，必须满足附着条件；超长部分红色显示，放置后丢弃超出段；
- **P-27** 重力模式（`gravity_mode`）：0 固定 / 1 掉落（**P-59**）/ 2 随附着体；
- 站立面摩擦：**P-64** × **P-60**（冰=0.5）；
- **蜂蜜**：邻接可 **P-29** 连接道具形成刚体组，不可连接者仅摆放不链接。

**结束**：全员 **P-32** 或 **P-04** 到 → 未放置者丢弃 P-21 → 进入跑酷。

## 6. 陷阱金币与死亡

### 涉及界面 / 系统模块

| 模块 | 类型 | 说明 |
|------|------|------|
| 陷阱碰撞 | 新增 | 致死/非致死分层 |
| 地图原生陷阱 | 新增 | 周期触发 |
| 金币实体 | 新增 | 拾取/掉落/跟随 |

### 功能点

**死亡（一触即死）**：
- 玩家 hitbox 接触陷阱**致死 collider**（箭头、钉刺等）→ **P-33=false**；
- 箭杆等非致死部分不致死；
- 地图**原生陷阱**（始终或周期出现，各独立计时）可致死；
- 坠落出界 → FALL；
- 死亡表现：**灰色遮罩**；上报 **player_death**。

**金币**：
- 拾取：碰撞金币 → **P-35++**，金币跟随头顶显示；
- 死亡：**P-35** 枚金币生成 **P-36** 悬浮在死亡点（`gravity_mode=Float`，不受 **P-59**）；
- 其他玩家可再拾取；
- **仅带币到达终点**才计入该玩家金币相关成就分（**P-44**）。

**到达终点**：
- 存活玩家首次触达终点 → **P-37**=名次；第一名获速度分候选；
- **【待 Q-P06：到达终点通知】**；**layer_finish** 埋点。

**P-05 结束**：未到达者 P-37=0 → 7-1 结算。
