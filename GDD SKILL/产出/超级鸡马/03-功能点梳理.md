## 1. 选角与匹配

### 涉及界面 / 系统模块

| 模块 | 类型 | 说明 |
|------|------|------|
| 角色选择 UI | 新增 | 展示全部小鸟，仅可选已解锁 |
| 匹配服务 | 新增 | 段位池、放宽、组局 |
| 主界面入口 | 新增 | 开始游戏 → 选角 → 匹配 |

### 功能点

玩家从主界面进入「超级鸡马」：先在**选择角色界面**浏览所有小鸟卡牌，仅 **P-10 已解锁** 的可选中为 **P-11**；未解锁灰置不可选。确认后发起 **MatchStartReq**，进入匹配阶段。

**匹配规则**：
1. 优先 **P-14=0** 同段位池匹配；
2. 超时扩大到 **±1 段位**（P-14=1）；
3. 再超时扩大到 **任意段位**（P-14=2）；
4. 组局成功下发 **MatchSuccessNtf**，携带 **P-15** 对局 id、**P-16** 玩家列表、**P-18** 地图 id。

玩家可 **MatchCancelReq** 取消匹配，上报 **match_cancel**（取消时匹配耗时 = now - P-13）。

【待确认】T1/T2 放宽时间、房间人数上下限、匹配最终失败 UI。

### 数据来源

| P-xx | 用途 | 读/写 |
|------|------|-------|
| P-07 | 段位 | 读 |
| P-08 | MMR | 读 |
| P-10 | 已解锁小鸟 | 读 |
| P-11 | 本局选中鸟 | 读写 |
| P-12~P-14 | 匹配池状态 | 服务端 |
| P-15~P-18 | 对局初始化 | 写 |

### 怎么实现

### 通用
- 选角页加载 P-10，新解锁鸟触发 RD-CHH-002（见「红点」章）。

### 服务端
```
on MatchStartReq:
  V-CHH-001 校验 P-11 ∈ P-10
  P-13 = now(), P-14 = 0
  enqueue(pool[P-07])
  loop R-CHH-002 直到成功或取消

on MatchCancelReq:
  dequeue, match_cancel 埋点
```

### 客户端
- 选角 UI：卡牌列表、确认按钮；
- 匹配 UI：搜索动画、取消按钮；
- MatchSuccessNtf → 加载对局场景 P-18。

### 程序实现分工

| 端 | 任务 | 依赖 |
|----|------|------|
| 服务端 | 匹配池、组局、协议 | P-45 段位表 |
| 客户端 | 选角/匹配 UI、埋点 match_* | 11-1 |

## 2. 对局状态与轮次

### 涉及界面 / 系统模块

| 模块 | 类型 | 说明 |
|------|------|------|
| 对局状态机 | 新增 | P-17 Phase 权威 |
| 轮次控制 | 新增 | P-01/P-02 |
| 阶段同步 | 新增 | PhaseChangeNtf |

### 功能点

对局由服务端维护 **P-17 Phase** 与 **P-02 当前轮次**（1~**P-01** 默认 12）。

阶段顺序：
```
MATCHING → CRATE_GRAB → PROP_PLACE → RUN → ROUND_SETTLE
  → (P-02++ 若继续) → CRATE_GRAB …
  → MATCH_SETTLE → (可选 SUDDEN_DEATH) → END
```

每次阶段切换广播 **PhaseChangeNtf**，携带倒计时剩余（P-03/P-04/P-05 视阶段而定）。

**布置阶段结束**：全员 P-32 或 P-04 到 → 未放置者丢弃道具 → RUN。  
**跑酷结束**：P-05 到或逻辑结束 → ROUND_SETTLE。

### 数据来源

| P-xx | 用途 | 读/写 |
|------|------|-------|
| P-01~P-02 | 轮数 | 读/写 |
| P-15~P-17 | 对局/阶段 | 读写 |
| P-03~P-05 | 各阶段倒计时 | 读 |

### 怎么实现

### 服务端
- 单一 MatchRoom 状态机，见下文状态机描述
- 定时器驱动 P-03/P-04/P-05；
- 断线 EX-CHH-004【待确认】。

### 客户端
- 订阅 PhaseChangeNtf 切换 HUD（布置/跑酷/结算）；
- 倒计时 UI 与服务器对齐。

### 程序实现分工

| 端 | 任务 | 依赖 |
|----|------|------|
| 服务端 | 状态机、定时器 | 1-1 组局 |
| 客户端 | HUD 切换 | 各阶段功能点 |

## 3. 木箱与道具抢夺

### 涉及界面 / 系统模块

| 模块 | 类型 | 说明 |
|------|------|------|
| 木箱刷新 | 新增 | 每轮中央刷新 |
| 抢夺 UI | 新增 | 10s 倒计时、道具列表 |
| 抢夺仲裁 | 新增 | 先到先得 |

### 功能点

每轮 **P-02** 开始时，地图中央刷新**木箱**：
- 基础道具数 = 玩家人数，从 **AB2_ChickenHorseItem** 按 **P-30**（轮次权重）随机 **P-26**；
- 额外 **0~2** 个道具按 **P-31** 权重抽取；
- 结果写入 **P-19**，**P-20**=打开时间戳，**P-17**=CRATE_GRAB。

**抢夺阶段（P-03=10 秒）**：
- 所有玩家同时行动，点击确认道具 → **PickItemReq(P-26, P-22)**；
- 服务端按 **P-22** 时间戳先到先得；成功则 **P-21**=该道具，从 P-19 移除；
- **P-03** 结束后未确认者 **P-21** 为空，本轮回合无道具可放置。

### 数据来源

| P-xx | 用途 | 读/写 |
|------|------|-------|
| P-02 | 轮次 | 读 |
| P-03 | 抢夺时长 | 读 |
| P-19~P-22 | 木箱与选择 | 读写 |
| P-26~P-31 | 道具配置 | 读 |

### 怎么实现

### 服务端
```
RoundStart:
  P-19 = gen_items(P-30, P-31, player_count)
  P-20 = now(), Phase=CRATE_GRAB
  schedule(P-03) → end_grab()

on PickItemReq:
  V-CHH-002
  P-21 = P-26; remove from P-19
  crate_open 埋点
```

### 客户端
- 木箱开启动画；倒计时条；
- 道具 icon 可点；已被抢灰置；
- 失败 toast【待确认】。

### 程序实现分工

| 端 | 任务 | 依赖 |
|----|------|------|
| 服务端 | 随机池、仲裁、倒计时 | 配置表 |
| 客户端 | 木箱 UI、请求 P-22 | 2-1 状态 |

## 4. 道具放置

### 涉及界面 / 系统模块

| 模块 | 类型 | 说明 |
|------|------|------|
| 放置预览 | 新增 | 网格吸附、附着、超长红区 |
| 放置校验 | 新增 | 服务端权威 |
| 物理配置 | 新增 | 重力/附着/蜂蜜 |

### 功能点

抢夺结束后立即开启 **P-04=30 秒** 放置倒计时，**P-17**=PROP_PLACE。

获得 **P-21** 的玩家须在限时内放置：
1. **摇杆**移动预览，道具**吸附网格**；
2. **确认键**发送 **PlacePropReq(P-24, P-25)**；
3. **不可修改**已确认位置。

**合法性**（失败则红色闪烁，客户端可预校验）：
- 不在出生/终点保护区（**P-47、P-48**）；
- 不与 **P-23** 已有道具重叠；
- 不与地图地形重叠；
- **P-28** 需附着时，必须满足附着条件；超长部分红色显示，放置后丢弃超出段；
- **P-27** 重力模式（`gravity_mode`）：0 固定 / 1 掉落（**P-59**）/ 2 随附着体；
- 站立面摩擦：**P-64** × **P-60**（冰=0.5）；
- **蜂蜜**：邻接可 **P-29** 连接道具形成刚体组，不可连接者仅摆放不链接。

**结束**：全员 **P-32** 或 **P-04** 到 → 未放置者丢弃 P-21 → 进入跑酷。

| P-27~P-29 | 物理属性（gravity_mode 等） | 读 |
| P-64 | 表面摩擦倍率 | 读 |
| P-59 | 掉落速度（跑酷开始） | 读【Q-D09】 |
| P-32 | 完成标志 | 写 |
| P-47~P-48 | 保护区 | 读 |

## 5. 跑酷操控

### 涉及界面 / 系统模块

| 模块 | 类型 | 说明 |
|------|------|------|
| 角色控制器 | 新增 | 移动/跳/墙跳/冲刺/蹲伏 |
| 物理参数 | 新增 | 全员一致，Const 驱动 |

### 功能点

跑酷阶段 **P-05** 倒计时内，玩家操控角色：

| 操作 | 行为 |
|------|------|
| 摇杆移动 | 基础移速 **P-49=1 格/s**；加减速 **P-61/P-62**、上限 **P-63**；地面摩擦 **P-60 × P-64**；松手水平惯性+摩擦衰减 |
| 跳跃 | 按住时长决定高度；上限 **P-50**；不蓄力=小跳 |
| 蹬墙跳 | 贴垂直面+跳→反向速度，**无次数限制** |
| 冲刺 | **P-52** 冷却，距离 **P-51**；摇杆前后方向；无输入则朝面向冲刺 |
| 蹲伏 | 降低 hitbox 过矮缝；**P-43** 冷却 |

**所有小鸟 P-11 性能完全一致**，差异仅外观。

玩家与玩家**无碰撞**。

## 6. 陷阱金币与死亡

### 涉及界面 / 系统模块

| 模块 | 类型 | 说明 |
|------|------|------|
| 陷阱碰撞 | 新增 | 致死/非致死分层 |
| 地图原生陷阱 | 新增 | 周期触发 |
| 金币实体 | 新增 | 拾取/掉落/跟随 |

### 功能点

**死亡（一触即死）**：
- 玩家 hitbox 接触陷阱**致死 collider**（箭头、钉刺等）→ **P-33=false**；
- 箭杆等非致死部分不致死；
- 地图**原生陷阱**（始终或周期出现，各独立计时）可致死；
- 坠落出界 → FALL；
- 死亡表现：**灰色遮罩**；上报 **player_death**。

**金币**：
- 拾取：碰撞金币 → **P-35++**，金币跟随头顶显示；
- 死亡：**P-35** 枚金币生成 **P-36** 悬浮在死亡点（`gravity_mode=Float`，不受 **P-59**）；
- 其他玩家可再拾取；
- **仅带币到达终点**才计入该玩家金币相关成就分（**P-44**）。

**到达终点**：
- 存活玩家首次触达终点 → **P-37**=名次；第一名获速度分候选；
- **ReachGoalNtf**；**layer_finish** 埋点。

**P-05 结束**：未到达者 P-37=0 → 7-1 结算。

### 数据来源

| P-xx | 用途 | 读/写 |
|------|------|-------|
| P-33~P-37 | 存活/名次/金币 | 读写 |
| P-36 | 掉落币（悬浮） | 读写 |
| P-59 | 世界掉落速度（对比：金币不用） | 读 |
| P-44 | 成就分配置 | 读 |

### 怎么实现

### 服务端
```
physics_tick:
  if lethal_overlap(player, trap): R-CHH-022
  if overlap(coin): R-CHH-023
  if overlap(goal) and P-33: R-CHH-024
```

### 客户端
- 陷阱动画（周期触发见道具表 trigger_period）；
- 金币跟随 UI；
- 死亡遮罩。

### 程序实现分工

| 端 | 任务 | 依赖 |
|----|------|------|
| 服务端 | 碰撞权威、计分输入 | P-18 地图、P-23 玩家陷阱 |
| 客户端 | 特效、UI | 5-1 操控 |

## 7. 单轮结算

### 涉及界面 / 系统模块

| 模块 | 类型 | 说明 |
|------|------|------|
| 计分服务 | 新增 | 生存/速度/成就 |
| Too easy | 新增 | 全员存活特殊逻辑 |
| 单轮 UI | 新增 | 得分明细 |

### 功能点

跑酷结束进入 **ROUND_SETTLE**：

**正常**：对每个玩家
- 到达终点 → **生存基础分**；
- **P-37==1** → **速度分**；

- **全员 0 分**；
- 触发 **too_easy** 埋点；
- 提升部分道具 **too_easy_weight_boost** 权重（下轮木箱 R-CHH-010 使用）。

下发 **RoundSettleNtf** → 若 **P-39 < P-06** 且 **P-02 < P-01** 则 **P-02++** 下一轮；否则 **8-1 对局结算**。
