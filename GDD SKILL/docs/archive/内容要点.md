# 内容要点

### 作业规范和培训

    - 资料仓库关系
        design： 策划仓库
            需求: 原始需求目录
                背包:
                    原始需求文档
                    需求标准文档.md
                    数据标注文档.md
            server:
                背包:
                    需求文档.md
                    需求资料目录
                    设计资料目录
                    方案资料目录
                    管线编排目录
            client:
                背包:
                    需求文档.md
                    需求资料目录
                    设计资料目录
                    方案资料目录
                    管线编排目录
            proto: 协议仓库
            config: 配置仓库
            design-skills: 策划skills集仓库
        client: 客户端仓库
            code: 客户端代码
            design: 策划仓库
            pipe: 开发管线仓库
            skills: 客户端skills集仓库
        server: 服务器仓库
            code: 服务器代码
            design: 策划仓库
            pipe: 开发管线仓库
            skills: 服务器skills集仓库
        pipe: 开发管线仓库
        proto: 协议仓库
        config: 配置仓库

    - 开发作业流程

        1. 策划: 完成原始需求编写, 入库到design仓库
            - 策划完成任意形式的原始需求文档
            - 完成从原始需求到标准策划资料的转换
            - 完成需求提交入库,交付给开发人员
        2. 后端:
            - 获取到新的需求
            - 完成文档作业: 需求整理 设计方案 开发方案 管线编排
            - ai管线自动开发 (等几个小时ai就按照要求开发完了)
            - 功能验收测试
            - 人工审计代码
            - 提交资料, 交付前端
        3. 前端:
            - 获取到新的需求 和 服务器相关资料
            - 完成文档作业: 需求整理 设计方案 开发方案 管线编排
            - ai管线自动开发 (等几个小时ai就按照要求开发完了)
            - 功能验收测试
            - 人工审计代码
            - 提交资料, 交付测试
        4. 测试:
            - 完成测试流程
            - 验收完成, 交付策划

    - bug作业流程
        - 组装 multica bug处理管线
        - 测试尝试复现bug 并 整理资料
        - 截取 服务器日志， 客户端日志, 创建 bug处理工单
        - 核对 功能文档资料 编写 异常分析文档
        - 开发人员 审计 异常分析文档 确认 问题根因
        - ai完成文档作业: 需求调整 设计方案 开发方案 管线编排
        - ai管线自动开发 (等几个小时ai就按照要求开发完了)
        - 功能验收测试
        - 人工审计代码
        - 提交资料, 交付测试 策划

### 迁移规划

    - 阶段1: 服务器完成csharp单机闭环
        - 服务器 从 框架层 和 业务层 入手抽取老项目的资料， 形成需求文档集
        - 需求文档集 按照 功能层次划分 拆分为 基础功能层 边缘系统层 核心玩法层 活动玩法层
        - 完成 基础功能层 和 边缘系统层 的 资料文档整理
        - 完成 基础功能层 和 边缘系统层 的 ai管线自动开发

    - 阶段2: 抽取前端代码知识整理为完整的需求
        - 客户端 从 框架层 和 业务层 入手抽取老项目的资料， 形成需求文档集
        - 合并 客户端 和 服务器 的需求文档集，形成完整的需求文档集
        - 策划逐个确认需求文档
        - 服务器 完成 基础功能层 和 边缘系统层 的 资料文档整理
        - 服务器 完成 基础功能层 和 边缘系统层 的 ai管线自动开发
        - 客户端 接入新的服务器框架
        - 完成前后端工程的迁移
