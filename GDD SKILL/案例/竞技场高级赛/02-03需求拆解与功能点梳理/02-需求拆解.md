| 当前状态 | 触发事件 | 目标状态 | 条件 | 副作用 |
|----------|----------|----------|------|--------|
| PENDING | 轮次到达（phase切换到该轮） | IN_PROGRESS | 当前轮次 == node.round | 节点显示「竞猜」按钮；BracketUpdatePush(status=IN_PROGRESS) |

## R-001 废除旧算法

> **L2 delta**

**检测位置**: 服务端定组任务入口（每周定时触发）

**检测方式**: 切换为新算法实现，不再执行旧算法的鸟力差计算逻辑。旧代码分支标记为废弃（保留但不调用）。

**数据**: 无需读旧算法的鸟力差阈值配置。

---

## R-002 鸟力降序排序

> **L2 delta**

**触发**: 服务端每周定组任务启动。

**检测方式**: 
1. 查询本周需分组的所有玩家，取每人的鸟力值（字段 `【待程序补充】`）
2. 按鸟力降序排列，编号 1..N
3. 当周小组数 G 由当前已开启的小组数决定（从 P-03 统计）

**数据**:
| 读/写 | 数据 | 说明 |
|--------|------|------|
| 读 | 玩家鸟力 | `【待程序补充】` |
| 读 | 当前已开启小组数 G | 从 P-03 已存在的组名统计 |

---

## R-003 头部轮询

> **L2 delta**

**触发**: 排序完成后。

**检测方式**:
```
for i in 1..G:
    玩家[i] → 第 i 组
```
排名第 1 的玩家入第 1 组，第 2 入第 2 组…第 G 入第 G 组。每组此时各占 1 个头部席位。

**目的**: 保证头部玩家均匀分布在各组，避免强强集中。

**算例（G=3）**: 排名1→组1, 排名2→组2, 排名3→组3

---

## R-004 余席顺序填充

> **L2 delta**

**触发**: 头部轮询完成（G 个玩家已分配）。

**检测方式**:
```
for i in G+1..N:
    target_group = ((i - G - 1) % G) + 1  // 循环 1,2,3,...,G,1,2,3,...
    if 组[target_group].人数 < 20:
        玩家[i] → 组[target_group]
    else:
        跳过该组 // 该组已满
```
从第 G+1 名起，按名次依次循环填入各组。组满 20 人则跳过。

**算例（G=3）**: 
| 排名 | 入组 |
|------|------|
| 4 | 组1 |
| 5 | 组2 |
| 6 | 组3 |
| 7 | 组1（循环） |

---

## R-005 组人数上限

> **L2 delta**

**检测位置**: 每次填充时判断。

**检测方式**:
```
if 组[k].当前人数 >= 20:
    跳过该组，尝试下一组
```
服务端在填充循环中维护每组当前人数计数器。满 20 人的组不参与后续填充。

---

## R-006 末组可不足 20 人

> **L2 delta**

**触发**: 待分配池为空（所有玩家已分配）时停止。

**检测方式**:
```
if 已分配玩家数 == N:
    停止定组
```
不强制要求每组恰好 20 人。最后一组可能不足 20，这是正常状态。

### R-023 四轮淘汰推进

> **继承 R-TB-004** + **继承 R-TB-005**（单败晋级写入父节点）

```
QF(8进4): QF1=W(M1)vsW(M2), QF2=W(M3)vsW(M4), QF3=W(M5)vsW(M6), QF4=W(M7)vsW(M8)
SF(4进2): SF1=W(QF1)vsW(QF2), SF2=W(QF3)vsW(QF4)
 F(决赛):  F1=W(SF1)vsW(SF2) → 冠军
```
服务端每场结束 → 胜者ID写入父节点 `parentMatchId` → 推进状态。

### R-024 机器人补位

> **继承 R-TB-004**（`robot_fill=true`）

```
if 赛区实际选手数 < 16:
    robotCount = 16 - 实际选手数
    生成机器人（isRobot=true, 头像统一, 展示鸟力随机, 展示分=真人最低分×20%-30%随机）
    填充空缺叶子节点
```
机器人不参与真实战斗。机器人vs真人→真人自动胜出。机器人vs机器人→随机一方高积分晋级。

### R-025 对战继承

> **继承 R-TB-005**（继承现网「纷乱的群殴」战斗模块，只改签位来源）

沿用现网「纷乱的群殴」：异步对战，单局无尽模式最高分。决斗/晋级/奖励逻辑不变，只改签位来源+机器人+竞猜/商店。

### R-031 每轮限制 — 押注接口校验

```
押注校验:
  if phase not in [BATTLE_16, BATTLE_8, BATTLE_4, BATTLE_FINAL]: reject  // 非战斗日
  if P-27[该轮] 已存在: reject  // 每轮仅1次

  if amount < 1 or amount > P-16: reject
  if targetPlayerId not in [match.left, match.right]: reject  // 只能选对战双方
```

### R-032 结算

```
if bet.target == match.winner:
    P-16 += bet.amount * 2; bet.result = WIN
else:
    bet.result = LOSE  // 不返还
```

**检测**: 定组算法填充时（R-004/R-005），每组维护当前人数计数器

**超限**: 满20人的组跳过后续填充。末组允许不足20人。

---

## LIM-002 赛区人数

> **继承 R-TB-003**（`groups_per_bracket=4`，80 人/赛区）

**固定值**: 80人 = 16选手（4组×4名）+ 64观众（4组×16名）

**检测**: 报名完成时统计各赛区人数

**不足**: 选手<16→机器人补位（EX-001）

---

## LIM-003 每轮押注次数

> **L2 delta**（`enable_betting=true`）

**限制值**: 1次/轮

**检测**: 服务端押注接口检查 P-27[该轮] 是否已存在

**超限**: 首次押注成功后写P-27 → 客户端隐藏竞猜按钮 → 阻止再次押注

---

## LIM-004 竞猜积分发放次数

> **L2 delta**

**限制值**: 4次（第2-5天各1次），总计800（P-18×4，可配）

**检测**: 服务端根据当天 `day_index` 判断是否发放

**第1天/第6-7天**: 不发

---

## LIM-005 竞猜积分有效期

> **L2 delta**

**生命周期**: 当期（7天），期初强制清零

**转化**: 第6天按 P-20（默认1:1）转为 P-21

**检测**: 周一UTC0 → P-16=0；第6天结算 → 转化后 P-16=0

---

## LIM-006 竞猜币有效期

> **L2 delta**

**生命周期**: 永久，不随活动期清零

**检测**: 新一期开始时 P-21 保持不变

## LIM-007 对阵树轮次

> **继承 R-TB-004**（`bracket_size=16`，4 轮单败）

**固定值**: 4轮（16进8 → 8进4 → 半决赛 → 决赛）

**检测**: Round枚举值（1/2/3/4），共15个节点（8+4+2+1）

**超限**: 决赛结束后无后续轮次，进入结算阶段

## V-001 战斗请求 — 非公示期

## V-002 战斗请求 — 选手身份

**层**: 客户端（路由守卫）+ 服务端（接口校验）

**客户端**: `if P-07 == AUDIENCE && route == "/duel": redirect("/bracket") + toast`

**服务端**: `if P-07 != PLAYER: return ERR_NOT_PLAYER`

## V-003 竞猜押注 — 在竞猜窗口内

> **L2 delta**（`enable_betting=true`；BATTLE_16/8/4/FINAL）

**层**: 服务端

**附加**: `assert now_utc < 该轮截止UTC0`

## V-004 竞猜押注 — 本轮未押注

> **L2 delta**（P-27 每轮仅 1 次）

**校验**: `assert P-27[match.round] == null`

**层**: 客户端（隐藏按钮）+ 服务端（拒绝）

**客户端**: `if P-27[match.round]: 隐藏该轮所有竞猜按钮`

**服务端**: `if P-27[match.round] exists: return ERR_ALREADY_BET`

---

## V-005 竞猜押注 — 押注额合法

> **L2 delta**

**校验**: `assert 1 <= amount <= P-16`

**层**: 客户端（滑条限制）+ 服务端（拒绝）

**客户端**: 滑条 `min=1, max=P-16`；微调按钮到达边界置灰

**服务端**: `if amount < 1 or amount > P-16: return ERR_INSUFFICIENT_POINTS`

---

## V-006 商店购买 — 余额充足

> **L2 delta**

**校验**: `assert P-21 >= item.price`

**层**: 客户端（按钮置灰）+ 服务端（拒绝）

**客户端**: `if P-21 < item.price: 购买按钮.enabled = false`

**服务端**: `if P-21 < item.price: return ERR_INSUFFICIENT_COINS`

**附加校验**: `assert purchase_count < item.limit`（限购检查，-1=无限）

## 防篡改设计

## RD-001 锦标赛入口红点（父级）

**位置**: 竞技场主界面 → 锦标赛活动入口 icon

**触发条件**: 新一期开始（周一UTC0，phase切换到ANNOUNCE）

**检测方式**: 客户端比对 `tournament_id`（本地缓存 vs 服务端下发）。ID变化 → 亮红点。

**消除条件**: 玩家进入活动展示弹窗（点击入口 → 弹窗展示 → 标记 `entry_viewed = true`）

**类型**: 纯红点 | **优先级**: 高

**聚合**: 此红点为父级。`RD-001 = RD-002 OR RD-003 OR RD-005`（任一子红点亮则父亮）

---

## RD-002 竞猜开放红点（子级）

**位置**: 对阵树界面 → 当前轮次进行中的节点 →「竞猜」按钮

**触发条件**: 阶段切换到 BATTLE_16/8/4/FINAL（第2-5天），且该轮 P-27 不存在（未押注）

**检测方式**: 
```
if phase in [BATTLE_16, BATTLE_8, BATTLE_4, BATTLE_FINAL]:
    for match in getCurrentRoundMatches():
        if P-27[match.id] == null:
            match.showRedDot = true
```

**消除条件**: 完成押注（P-27写入后该场次红点消除）或该轮 UTC0 截止

**类型**: 纯红点 | **优先级**: 高

---

## RD-003 积分发放红点（子级）

**位置**: 对阵树/决斗/竞猜 顶栏 → 竞猜积分信息栏

**触发条件**: 每日 UTC0 发放积分后，玩家首次进入活动界面

**检测方式**: 服务端维护 `grant_anim_flag` 标记。`if grant_anim_flag == UNPLAYED: 亮红点`

**消除条件**: 播放发放动画后 → `grant_anim_flag = PLAYED` → 红点消除

**类型**: 数字红点（展示 P-17 累计获得积分） | **优先级**: 中

**离线处理**: 多轮未登录，只弹一次动画并展示累计值

---

## RD-004 锦标赛商店红点

**位置**: 对阵树/决斗右下 → 商店圆形按钮

**触发条件**: 
1. 结算转化后 P-21 增加（竞猜币余额变化）
2. （可选）商店有新商品上架

**检测方式**: 客户端缓存上次 P-21 值，与最新拉取值比对。`if P-21 > cached_P21: 亮红点`

**消除条件**: 进入商店界面后消除

**类型**: 纯红点 | **优先级**: 低

**独立红点**: 不聚合到 RD-001

---

## RD-005 战斗结果红点（子级）

**位置**: 对阵树 → 已支持选手所在场次的已结束节点 → 战报入口

**触发条件**: 玩家押注支持的选手所在场次状态变为 COMPLETED

**检测方式**: 
```
if match.status == COMPLETED and P-27[match.id] != null:
    match.showRedDot = true  // 亮在战报入口
```

**消除条件**: 点击战报入口查看战斗记录弹窗后消除

**类型**: 纯红点 | **优先级**: 中

### T5 机器人补位（详述）

**前置**: 某赛区仅10名真实选手

**验证**:
- 对阵树共16个叶节点（10真人 + 6机器人）
- 机器人有头像和名称，标记 isRobot=true
- 机器人不产生真实战斗记录

---

### T6-T11 积分/押注/结算（详述）

**T6 积分发放**: 第2天UTC0后首次进活动 → P-16+=200，播放发放动画展示 P-17。

**T7 押注**: 竞猜开放轮次选一方押100 → 生成1条记录，P-16扣100，P-27写入，该轮所有竞猜按钮隐藏。

**T8 猜中**: 押100且目标胜出 → 结算后 P-16+=200（净+100）。

**T9 猜错**: 押100且目标失败 → 结算后无返还。

**T10 积分转币**: 第6天进入结算 → P-21+=P-16×P-20，P-16清零，播放转化动画。

**T11 已结束节点**: COMPLETED 节点仅显示战报入口，不显示竞猜按钮。
