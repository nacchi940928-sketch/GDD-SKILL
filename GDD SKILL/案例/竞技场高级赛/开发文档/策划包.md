竞技场高级赛（纷乱的群殴锦标赛）活动优化

1. 设计目的

1.1 竞技场锦标赛优化

设计目的： 在原有「纷乱的群殴」上，与 竞技场小组排名 衔接，自动划分 选手 / 观众；用 16 人淘汰赛 强化炫耀与竞争，用 竞猜 + 商店 让本期 持续可参与、有收益。

调整报名门槛，取消主动报名，按 联赛档位小组排名 自动入选。

优化参与条件，小组 前 4 为 参赛选手，其余为 观众。

新增竞猜系统，所有玩家通过竞猜玩法支持喜欢/熟悉的选手，强化归属感

新增商店系统，玩家持续参与该活动，可以兑换稀有道具

1.2 竞技场分组优化

设计目的：竞技场锦标赛需要依托竞技场分组，保证锦标赛 为 联赛前列玩家竞争 各个赛区的冠军；同时需要增加档位数量，激励更多玩家参与

不再使用同组最大鸟力差在20%的分组模式

使用定组插入的方式，按鸟力排序后将 各联赛档位 前列玩家，轮询分散到各周练小组，优先保护头部玩家在组内榜上的竞争体验与争第一空间，再填充其余席位。

增加档位数量

细分更多档位，让更多玩家体验到有“拿第一”的机会

2. 竞技场功能优化

2.1 竞技场分组优化

联赛档位优化

在当前基础上，增加更多的细分档位

※该优化为策划调整配置，需要美术资源补充

周练分组规则调整

按 鸟力 降序排序全体待分配玩家。

设当周已开启 / 将要填充的小组数为 G。

头部轮询入槽：排名第 1 的玩家进入 第 1 组，第 2 名进入 第 2 组 … 第 G 名进入 第 G 组（各组先占 1 个头部席位）。

余席填充：剩余玩家继续按排序 依次填充 各组，直至每组满 20 人 或待分配池耗尽（尾组可不足 20 人）。

定组插入：玩家在步骤完成后 固定 所属「XX 赛区 · 第 N 组」。

## R-003 头部轮询

> **L2 delta**

**触发**: 排序完成后。

**检测方式**:
```
for i in 1..G:
    玩家[i] → 第 i 组
```
排名第 1 的玩家入第 1 组，第 2 入第 2 组…第 G 入第 G 组。每组此时各占 1 个头部席位。

**目的**: 保证头部玩家均匀分布在各组，避免强强集中。

**算例（G=3）**: 排名1→组1, 排名2→组2, 排名3→组3

---

## R-004 余席顺序填充

> **L2 delta**

**触发**: 头部轮询完成（G 个玩家已分配）。

**检测方式**:
```
for i in G+1..N:
    target_group = ((i - G - 1) % G) + 1  // 循环 1,2,3,...,G,1,2,3,...
    if 组[target_group].人数 < 20:
        玩家[i] → 组[target_group]
    else:
        跳过该组 // 该组已满
```
从第 G+1 名起，按名次依次循环填入各组。组满 20 人则跳过。

**算例（G=3）**: 
| 排名 | 入组 |
|------|------|
| 4 | 组1 |
| 5 | 组2 |
| 6 | 组3 |
| 7 | 组1（循环） |

## 竞猜积分 (P-16)

### R-040 发放

```
第2-5天每日UTC0:
    for player in 赛区80人:
        P-16 += P-18  // 默认200，可配
        P-17 += P-18  // 累计获得
        grant_flag[player] = 本轮未播放
```
第1天不发，第6-7天不发（执行转化）。

### R-041 期初清零

```
新一期开始(周一UTC0):
    P-16 = 0  // 强制清零
```

### R-042 发放动画

客户端首次进活动界面时:
```
if grant_flag[player] == 本轮未播放:
    播放发放动画（展示 P-17 累计获得）
    grant_flag[player] = 已播放
```
离线多轮累积 → 只弹一次动画（flag为"未播放"→弹一次→标记已播放所有轮次）。

## 16强固定签位

### R-020 组代号映射

> **继承 R-TB-004**（固定签位表前置：组代号约定）

```
A/B/C/D = 赛区内第1/2/3/4个周练组

```

### R-021 固定签位表 — 服务端填充逻辑

> **继承 R-TB-004**（`bracket_size=16` 固定签位表）

```
叶子节点[8]:
  M1: left=A1, right=B4   // 种子保护: A组第1 vs B组第4
  M2: left=B2, right=C3   // 交叉
  M3: left=B1, right=C4
  M4: left=C2, right=D3
  M5: left=C1, right=D4
  M6: left=D2, right=A3
  M7: left=D1, right=A4
  M8: left=A2, right=B3
```

### R-022 同组规避验证

> **继承 R-TB-004**（签位生成校验）

```
for m in [M1..M8]:
    assert getGroup(m.left) != getGroup(m.right)
    leftRank = getRank(m.left); rightRank = getRank(m.right)
    // 种子保护: 1号位对阵的是其他组的4号位
    assert (leftRank==1 implies rightRank==4) or (rightRank==1 implies leftRank==4)
```

### R-023 四轮淘汰推进

> **继承 R-TB-004** + **继承 R-TB-005**（单败晋级写入父节点）

```
QF(8进4): QF1=W(M1)vsW(M2), QF2=W(M3)vsW(M4), QF3=W(M5)vsW(M6), QF4=W(M7)vsW(M8)
SF(4进2): SF1=W(QF1)vsW(QF2), SF2=W(QF3)vsW(QF4)
 F(决赛):  F1=W(SF1)vsW(SF2) → 冠军
```
服务端每场结束 → 胜者ID写入父节点 `parentMatchId` → 推进状态。

### R-024 机器人补位

> **继承 R-TB-004**（`robot_fill=true`）

```
if 赛区实际选手数 < 16:
    robotCount = 16 - 实际选手数
    生成机器人（isRobot=true, 头像统一, 展示鸟力随机, 展示分=真人最低分×20%-30%随机）
    填充空缺叶子节点
```
机器人不参与真实战斗。机器人vs真人→真人自动胜出。机器人vs机器人→随机一方高积分晋级。

### R-025 对战继承

> **继承 R-TB-005**（继承现网「纷乱的群殴」战斗模块，只改签位来源）

沿用现网「纷乱的群殴」：异步对战，单局无尽模式最高分。决斗/晋级/奖励逻辑不变，只改签位来源+机器人+竞猜/商店。

### R-031 每轮限制 — 押注接口校验

```
押注校验:
  if phase not in [BATTLE_16, BATTLE_8, BATTLE_4, BATTLE_FINAL]: reject  // 非战斗日
  if P-27[该轮] 已存在: reject  // 每轮仅1次
  if now > 该轮UTC0截止: reject
  if amount < 1 or amount > P-16: reject
  if targetPlayerId not in [match.left, match.right]: reject  // 只能选对战双方
```

### R-032 结算

```
if bet.target == match.winner:
    P-16 += bet.amount * 2; bet.result = WIN
else:
    bet.result = LOSE  // 不返还
```

服务端押注成功后写 P-27 = `{matchId → targetPlayerId}`。客户端读P-27渲染"已下注"标签，同时隐藏该轮所有竞猜按钮。

### R-034 第1天门控

客户端: `if phase==ANNOUNCE: 竞猜入口置灰/隐藏`。服务端: `if phase==ANNOUNCE: return ERR_BET_CLOSED`。

**检测**: `count(identity==PLAYER in 赛区) < 16`

**处理**:
- 计算差值 `robotCount = 16 - 实际选手数`
- 生成机器人实体（isRobot=true, 头像统一, 展示鸟力按真人数据范围随机）
- 填充空缺叶子节点
- 机器人不参与真实战斗

**用户感知**: 对阵树显示机器人头像和名称，与真人选手视觉一致。

## EX-002 观众尝试进入决斗

> **继承 B-TB-001** / **V-TB-002**

**客户端**: `if P-07 == AUDIENCE and route == "/duel": redirect("/bracket") + toast("无决斗信息")`

**服务端**: `if P-07 != PLAYER: return ERR_NOT_PLAYER`

## V-001 战斗请求 — 非公示期

> **继承 V-TB-001 概念**（阶段门控）；**L2 delta** phase=ANNOUNCE 不可战斗

**校验**: `assert phase != ANNOUNCE`

**层**: 客户端（置灰）+ 服务端（拒绝）

**客户端**: `if phase == ANNOUNCE: 战斗按钮.enabled = false`

**服务端**: `if phase == ANNOUNCE: return ERR_BATTLE_LOCKED`

## V-002 战斗请求 — 选手身份

> **继承 V-TB-002**（CONTESTANT 才能进入战斗接口）

**校验**: `assert P-07 == PLAYER`

**层**: 客户端（路由守卫）+ 服务端（接口校验）

**客户端**: `if P-07 == AUDIENCE && route == "/duel": redirect("/bracket") + toast`

**服务端**: `if P-07 != PLAYER: return ERR_NOT_PLAYER`

## V-003 竞猜押注 — 在竞猜窗口内

> **L2 delta**（`enable_betting=true`；BATTLE_16/8/4/FINAL）

**校验**: `assert phase in [BATTLE_16, BATTLE_8, BATTLE_4, BATTLE_FINAL]`

**层**: 服务端

**服务端**: `if phase not in BATTLE_PHASES: return ERR_BET_CLOSED`

**附加**: `assert now_utc < 该轮截止UTC0`

## V-004 竞猜押注 — 本轮未押注

> **L2 delta**（P-27 每轮仅 1 次）

**校验**: `assert P-27[match.round] == null`

**层**: 客户端（隐藏按钮）+ 服务端（拒绝）

**客户端**: `if P-27[match.round]: 隐藏该轮所有竞猜按钮`

**服务端**: `if P-27[match.round] exists: return ERR_ALREADY_BET`

---

## V-005 竞猜押注 — 押注额合法

> **L2 delta**

**校验**: `assert 1 <= amount <= P-16`

**层**: 客户端（滑条限制）+ 服务端（拒绝）

**客户端**: 滑条 `min=1, max=P-16`；微调按钮到达边界置灰

**服务端**: `if amount < 1 or amount > P-16: return ERR_INSUFFICIENT_POINTS`

---

## V-006 商店购买 — 余额充足

> **L2 delta**

**校验**: `assert P-21 >= item.price`

**层**: 客户端（按钮置灰）+ 服务端（拒绝）

**客户端**: `if P-21 < item.price: 购买按钮.enabled = false`

**服务端**: `if P-21 < item.price: return ERR_INSUFFICIENT_COINS`

**附加校验**: `assert purchase_count < item.limit`（限购检查，-1=无限）

## V-007 决斗进入 — 仅选手

> **继承 V-TB-002** / **B-TB-001**

**校验**: `assert P-07 == PLAYER`

**层**: 客户端路由守卫

**客户端**: 观众尝试通过URL直接进入决斗界面 → 路由拦截 → 重定向到对阵树

## 防篡改设计

所有数值校验（积分、次数、余额）以服务端存储为权威数据源。客户端缓存仅用于UI展示和预校验，不可作为业务逻辑依据。服务端在每次写操作前重新从数据库读取当前值进行校验。

## RD-001 锦标赛入口红点（父级）

**位置**: 竞技场主界面 → 锦标赛活动入口 icon

**触发条件**: 新一期开始（周一UTC0，phase切换到ANNOUNCE）

**检测方式**: 客户端比对 `tournament_id`（本地缓存 vs 服务端下发）。ID变化 → 亮红点。

**消除条件**: 玩家进入活动展示弹窗（点击入口 → 弹窗展示 → 标记 `entry_viewed = true`）

**类型**: 纯红点 | **优先级**: 高

**聚合**: 此红点为父级。`RD-001 = RD-002 OR RD-003 OR RD-005`（任一子红点亮则父亮）

---

## RD-002 竞猜开放红点（子级）

**位置**: 对阵树界面 → 当前轮次进行中的节点 →「竞猜」按钮

**触发条件**: 阶段切换到 BATTLE_16/8/4/FINAL（第2-5天），且该轮 P-27 不存在（未押注）

**检测方式**: 
```
if phase in [BATTLE_16, BATTLE_8, BATTLE_4, BATTLE_FINAL]:
    for match in getCurrentRoundMatches():
        if P-27[match.id] == null:
            match.showRedDot = true
```

**消除条件**: 完成押注（P-27写入后该场次红点消除）或该轮 UTC0 截止

**类型**: 纯红点 | **优先级**: 高

---

## RD-003 积分发放红点（子级）

**位置**: 对阵树/决斗/竞猜 顶栏 → 竞猜积分信息栏

**触发条件**: 每日 UTC0 发放积分后，玩家首次进入活动界面

**检测方式**: 服务端维护 `grant_anim_flag` 标记。`if grant_anim_flag == UNPLAYED: 亮红点`

**消除条件**: 播放发放动画后 → `grant_anim_flag = PLAYED` → 红点消除

**类型**: 数字红点（展示 P-17 累计获得积分） | **优先级**: 中

**离线处理**: 多轮未登录，只弹一次动画并展示累计值

---

## RD-004 锦标赛商店红点

**位置**: 对阵树/决斗右下 → 商店圆形按钮

**触发条件**: 
1. 结算转化后 P-21 增加（竞猜币余额变化）
2. （可选）商店有新商品上架

**检测方式**: 客户端缓存上次 P-21 值，与最新拉取值比对。`if P-21 > cached_P21: 亮红点`

**消除条件**: 进入商店界面后消除

**类型**: 纯红点 | **优先级**: 低

**独立红点**: 不聚合到 RD-001

---

## RD-005 战斗结果红点（子级）

**位置**: 对阵树 → 已支持选手所在场次的已结束节点 → 战报入口

**触发条件**: 玩家押注支持的选手所在场次状态变为 COMPLETED

**检测方式**: 
```
if match.status == COMPLETED and P-27[match.id] != null:
    match.showRedDot = true  // 亮在战报入口
```

**消除条件**: 点击战报入口查看战斗记录弹窗后消除

**类型**: 纯红点 | **优先级**: 中

## L1 resolution_standard / tech

# 分辨率与适配 — 技术规范（L0 横切）

## 规范目标

全项目**唯一**画布与适配策略，防止多引擎/AI 实现乱拉伸、刘海遮挡、长屏错位。

## 设计稿 vs 实机

| 层 | 是否固定 9:20 |
|----|----------------|
| 设计稿 / 出图坐标 | ✅ 固定 `reference_resolution`（默认 1080×2340） |
| 实机屏幕 | ❌ 不固定 |

**核心**：固定 9:20 画布完整显示；更长屏宽度顶满、上下纯黑；更宽扁屏高度顶满、左右纯黑。

## 缩放模式（scale_mode）

| 模式 | 计算 | 适用 |
|------|------|------|
| **fit（默认）** | `scale = min(屏宽/1080, 屏高/2340)` | 固定画布，留纯黑边 |
| match_width | `scale = 屏宽/设计宽` | 备选 |
| match_height | `scale = 屏高/设计高` | 备选 |

X/Y **必须用同一 scale**，禁止 `scaleX ≠ scaleY`。

## 画布内布局（layout_anchor_policy）

默认 **stretch_center**：HUD 贴顶、Tab 贴底、中间 Fill。**不**向实机黑边区延伸。

| UI 区域 | 实机行为 |
|---------|----------|
| 顶部 HUD | 随画布 scale，不拉高 |
| 底部 Tab | 随画布 scale，不拉高 |
| 主玩法/列表 | 在 2340 内分配 |
| 居中弹窗 | 画布内居中，尺寸随 scale |
| 黑边区 | 纯黑、不可点 |

## 双层结构

- **背景层**：可铺满物理屏
- **交互层**：必须在 SafeArea 内

## 禁止

- 实机长屏中间向下延伸玩法区
- 4:3 挤扁中间不留黑边
- 黑边区放可点击按钮
- 非等比拉伸

## 验收标准

- [ ] 所有 UI 按设计坐标 1080×2340 出稿
- [ ] fit 模式下黑边不可点击
- [ ] 各系统 ux.md 不重复定义分辨率，只引用本文

## L1 interaction_feedback / ux

# 交互反馈 — UX 规范（L0 横切）

## 规范目标

统一全项目交互反馈层级与状态机写法，支撑 AI 生成 UI 与自动化检查。

## 界面架构预设

反馈层级（全项目通用）：

| 层级 | 用途 | 示例 |
|------|------|------|
| 行内 | 即时、不打断 | 置灰、Tips、角标 |
| Toast | 轻量结果 | 操作成功/失败 |
| 叠加弹窗 | 需确认 | 高风险操作二次确认 |
| 全屏 | 强打断 | 奖励展示、断线重连 |

## 状态机 — 按钮

### Normal

**表现**：可点击，100% 缩放  
**验收**：pointer-events 启用

### Pressed

**触发**：pointer down  
**表现**：缩放至 `button_pressed_scale`（默认 95%）  
**禁止**：触发业务逻辑（等 release）

### Disabled

**触发**：业务条件不满足  
**表现**：透明度 50%  
**禁止**：
- 播放 Pressed 反馈
- 触发业务逻辑

**验收**：`opacity == 0.5 && pointer-events == none`

## 交互规则

- 防连点：`click_lock_ms` 内忽略重复点击
- Toast：默认 `toast_duration_ms`，可队列不叠加（项目可 override）
- 错误：行内优先，严重错误用 Toast

## 表现规则

- 奖励获得：全屏或大型叠加弹窗（由业务 Skill 引用，不重复定义 Pressed 规则）
- 网络错误：Toast + 可重试

## 验收标准

- [ ] Disabled 不响应点击且无 Pressed 动画
- [ ] 业务界面不重复定义按钮三态

# 单败淘汰赛对阵树 — 设计规范（框架 Skill）

## 规范目标

提供**可复用的锦标赛 Bracket 策划框架**：任意「来源分组 → 报名 → 签位 → 多轮单败 → 结算」类玩法，均可继承本 Skill，在 L2 只写业务 delta。

**本文件不包含**：具体项目名称、来源组/分区名词、固定签位表数值、extension 槽内业务规则、P-xx 字段。

## 适用范围

- 单败 Bracket，`bracket_size` 可配置（8/16/32…）
- 可选**双身份**（参赛者 / 观赛者）或 L2 定义为单一身份
- 服务端权威**阶段机** + 客户端门控
- `extension_slots` 声明扩展能力挂点，**不定义**扩展业务规则

## 玩家流程（框架）

```text
[活动入口] → [公示/活动展示]
  ├── 参赛者 → [战斗主界面]
  └── 观赛者 → [对阵树主界面] →（可选扩展槽）
```

## 核心规则

### R-TB-001 报名模式

| registration_mode | 行为 |
|-------------------|------|
| `auto` | 按 `registration_schedule` 触发；无主动报名 UI/接口 |
| `manual` | 玩家主动报名；截止时间与资格由 L2 定义 |

**自动报名框架行为**：
- 触发：`registration_schedule`
- 读：来源组归属 + 组内排名（字段名 L2 定义）
- 写：身份、Bracket 快照
- 签位与报名**同一事务**；失败回滚

### R-TB-002 身份判定（双身份模式）

```
if rank in [1 .. contestant_rank_top_n]:
    role = CONTESTANT
else:
    role = SPECTATOR
```

- 身份在 `identity_lock_duration` 内不变（GM 修改需 L2 定义审计）
- 下一周期重新报名时覆盖

> 若项目无观赛者，L2 标注「R-TB-002 N/A，全员 CONTESTANT」。

### R-TB-003 Bracket 组成

- 每 `source_groups_per_bracket` 个**来源组**合并为一个独立 Bracket
- 各 Bracket 独立淘汰赛、独立冠军
- 规模：叶节点 `bracket_size` 名参赛者 + L2 定义的观赛者池（若有）

**来源组**：L2 定义（按排名/公会/服务器等分组），框架不绑定具体算法。

### R-TB-004 签位生成

- 签位表由**配置/常量表**驱动，**不可运行时随机**
- 报名成功 → 写叶节点 → `robot_fill=true` 时不足补机器人
- 签位失败 → 回滚报名

签位算法（同组规避、种子保护等）：**L2 在 02/规则 展开**。

### R-TB-005 对战与晋级

- 单败：胜者写入父节点
- 轮次数量由 `bracket_size` 决定（log2 规模）
- **战斗判定**：框架不定义；L2 标注「继承现网 {模块}」或「新建 MatchService」

### R-TB-006 阶段日程

由 `period_structure` 实例化，框架阶段枚举：

| 阶段 | 框架含义 |
|------|----------|
| ANNOUNCE | 公示；不可战斗 |
| BATTLE_* | 各战斗轮（数量 = f(bracket_size)） |
| SETTLE | 结算、发奖、扩展槽收尾（L2 定义） |

阶段切换：服务端权威；切换 tick 由 L2 定义（如 UTC0）。

## 扩展槽（框架挂点）

`extension_slots` 非空时，L2 在独立章节/SKill 定义规则，例如：

| 槽位 id | 框架约定 | 规则定义方 |
|---------|----------|------------|
| `betting` | 观赛者可选参与；与 BATTLE 轮次对齐 | L2 / 独立 Skill |
| `shop` | 结算后或期内兑换 | L2 |
| `custom_currency` | 期内代币与结算转化 | L2 |

框架**不包含**扩展槽的业务数值与 UI 文案。

## 数据模型（概念层）

| 概念 | 说明 |
|------|------|
| BracketSnapshot | 完整对阵树 |
| BracketNode | 单场比赛节点 |
| PlayerRole | CONTESTANT / SPECTATOR（可扩展） |
| Phase | ANNOUNCE / BATTLE_n / SETTLE |

字段编号、proto 名：**L2 在 02/数据源 登记**。

## 边界与异常（框架）

| 编号 | 场景 | 框架处理 |
|------|------|----------|
| EX-TB-001 | 定时任务失败 | L2 定义重试 |
| EX-TB-002 | 签位失败 | 回滚报名 |
| EX-TB-003 | 战斗超时未结算 | L2 定义判负/延期 |
| PRE-TB-001 | 无来源组资格 | 不参与本期 |
| LIM-TB-001 | 身份锁定期 | 不因局内事件改身份 |

## 验收标准（框架）

- [ ] registration_mode 行为与配置一致
- [ ] 身份判定符合 contestant_rank_top_n（若启用双身份）
- [ ] 签位非随机、robot_fill 行为正确
- [ ] 阶段切换服务端权威，客户端门控一致
- [ ] 节点三态无歧义（见 ux.md）
- [ ] L2 workflow skill_configs 与 02 规则数值一致

# 单败淘汰赛对阵树 — UX 规范（框架 Skill）

## 规范目标

对阵树类活动的**界面架构模式**与节点交互行为规范。引用 `resolution_standard`、`interaction_feedback`，不定义具体界面名称与文案。

## 界面架构预设（模式）

| 模式 | 说明 |
|------|------|
| 入口 | L2 定：HUD / 活动中心 / 弹窗触发 |
| 参赛者主界面 | 全屏战斗流 |
| 观赛者主界面 | 全屏对阵树 |
| 公示 | 弹窗或全屏预览 |
| 扩展槽 UI | 由 extension_slots 驱动，L2 定义 |

**身份分流（双身份模式）**：
- CONTESTANT → 战斗主界面
- SPECTATOR → 对阵树主界面

## 与全局画布

> 布局在 `resolution_standard` 画布内；本 Skill 不定义分辨率。

## 状态机 — Bracket 节点（框架）

### PENDING

**触发**：节点未到达或轮次未到  
**表现**：占位/待定  
**禁止**：终态入口（战报等）

### IN_PROGRESS

**触发**：当前 Phase 轮次 == node.round  
**表现**：可进行轮次内操作（战斗入口 / 扩展槽入口，L2 定义）  
**禁止**：与 COMPLETED 态入口共存

### COMPLETED

**触发**：winnerId 已确定  
**表现**：胜者标识；终态入口（如战报）  
**禁止**：轮次内进行中入口

**框架验收**：同一节点不同时展示互斥入口。

## 交互规则（模式）

| 操作类型 | 参赛者 | 观赛者 |
|----------|--------|--------|
| 进入战斗主界面 | 允许 | L2 门控（通常禁止） |
| 对阵树内参赛者专属 Tab | 允许 | L2 门控 |
| 扩展槽（如 betting） | L2 定义 | L2 定义 |
| 进行中战斗数据可见性 | L2 定义 | L2 定义 |

## 表现规则

- Bracket 树形排布方向：L2 定稿
- 阶段倒计时：入口或顶栏展示剩余时间（字段 L2 定义）

## 异常规则

- 网络失败：继承 `interaction_feedback` Toast
- 阶段不允许的操作：行内 Tips

## 验收标准

- [ ] 身份分流符合架构模式
- [ ] 节点三态无互斥冲突
- [ ] 未重复定义分辨率与按钮反馈

## L1 tournament_bracket / tech

# 单败淘汰赛对阵树 — 技术规范（框架 Skill）

## 规范目标

模块边界、数据结构骨架、接口**族**。不含具体 proto 名、P-xx、项目服务类名。

## 服务 / 模块（框架）

| 模块 | 职责 |
|------|------|
| TournamentScheduler | 阶段切换 |
| RegistrationService | 报名 |
| BracketService | 签位、晋级写入 |
| MatchService | 对战（可继承现网或 L2 新建） |
| ExtensionAdapter | 扩展槽适配（betting/shop…，可选） |
| PushGateway | 阶段/节点推送 |

## BracketNode（骨架）

```json
{
  "matchId": 0,
  "round": 0,
  "matchIndex": 0,
  "slotLeft": 0,
  "slotRight": 0,
  "winnerId": 0,
  "status": "PENDING",
  "isRobotLeft": false,
  "isRobotRight": false,
  "parentMatchId": 0
}
```

**status**：`PENDING` | `IN_PROGRESS` | `COMPLETED`

**round**：从 1 递增；语义（十六强/八强…）由 `bracket_size` 推导，L2 可命名别名。

## 接口族（框架）

| 接口族 | 方向 | 用途 |
|--------|------|------|
| GetBracketSnapshot | C→S | 拉取对阵树 |
| GetPhaseInfo | C→S | 阶段 + 倒计时 |
| PhaseChangePush | S→C | 阶段变更 |
| BracketUpdatePush | S→C | 节点更新 |
| Extension* | C↔S | 扩展槽，L2 定义 |

## 实现约束

- 签位与报名同事务
- 阶段切换前：L2 定义上一轮结算完成条件
- Push：L2 选全量/增量

## 校验规则（框架）

| 编号 | 校验 |
|------|------|
| V-TB-001 | 扩展槽写操作：phase 允许 + 业务规则（L2） |
| V-TB-002 | 身份门控：参赛者才能进战斗接口 |
| V-TB-003 | 叶节点数 == bracket_size（含机器人） |

## 验收标准

- [ ] L2 协议与骨架字段一一映射
- [ ] 服务端权威，客户端不 sole source of truth

- 节点状态与晋级
- 身份门控
- 扩展槽（若 extension_slots 非空）

## 测试用例

### T-TB-001 自动报名

**前置**：registration_mode=auto，到达 registration_schedule  
**验证**：身份写入正确；Bracket 快照生成  

### T-TB-002 身份锁定

**前置**：identity_lock_duration 生效期内已报名  
**步骤**：触发排名变化类事件  
**验证**：身份字段不变  

### T-TB-003 签位固定

**前置**：bracket_size 配置值，部分空缺  
**步骤**：robot_fill=true  
**验证**：叶节点数正确；与配置签位表一致  

### B-TB-001 观赛者进战斗

**前置**：role=SPECTATOR（若项目启用双身份）  
**验证**：门控拦截 + 提示  

### E-TB-001 签位失败回滚

**前置**：模拟签位异常  
**验证**：报名回滚；无脏快照  

## 自动化检查点

- Phase 枚举与 Scheduler 日志一致
- BracketNode.status 合法枚举
